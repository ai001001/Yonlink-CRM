# ADR-006 数据库迁移策略

- 状态：提议中
- 日期：2026-11-08
- 关联：ADR-005、ADR-008

## 1. 背景
- 任务书 T3 要求“migration up/down 策略清楚”；Prisma Migrate 不提供 down 迁移。
- RLS 策略、触发器、部分唯一索引、CHECK 约束、函数索引（`lower(email)`）、`SECURITY DEFINER` 函数无法用 Prisma schema 表达。
- 单服务器无独立预发布环境，迁移失败的恢复手段必须在本机可执行。

## 2. 决策
1. **只前进迁移**：生产路径只执行 `prisma migrate deploy`；不在运行环境执行 `migrate dev`/`db push`/`migrate reset`。
2. **SQL 为准**：用 `prisma migrate dev --create-only` 生成迁移后人工补写 SQL（RLS、触发器、索引、角色授权）；`schema.prisma` 与 SQL 不一致时以审查过的 SQL 为准，并由 migration check 发现漂移。
3. **配套回滚脚本**：每个迁移目录附 `rollback.sql`（手写，可审查）；CI 在一次性数据库上验证 “up → rollback → up” 可执行。
4. **expand/contract 两段式**：破坏性变更（删列、改类型、改约束）拆为“扩展 → 回填 → 切换代码 → 收缩”多次发布，保证新旧代码可共存。
5. **迁移前强制备份**：执行 `migrate deploy` 前自动触发一次数据库备份（ADR-008 的 `pre-migrate` 快照），备份失败则中止迁移。
6. **角色分离**：迁移使用 `yonlink_migrator` 凭据，仅迁移脚本持有；运行时使用 `yonlink_app`（ADR-005）。
7. **数据保护**：任何删除表/列的迁移需负责人书面批准；禁止手工修改数据库。
8. **Seed**：开发 seed 位于 `packages/database/seed/dev/`，所有数据带明显“开发演示”标记；部署环境拒绝执行开发 seed；不存在默认弱密码（开发管理员密码由脚本随机生成并写入本地未提交文件）。

## 3. Migration check（本机 CI 步骤）
- 在 `yonlink-crm-test`（ADR-009）的独立检查库中执行全部迁移（由 `yonlink_test_admin` 创建、`yonlink_migrator` 执行迁移，结束即删除）；测试模板库构建复用同一流程。
- `prisma migrate diff` 确认 schema 与数据库无漂移。
- 断言所有租户表启用并强制 RLS；断言 `audit_logs` 对 `yonlink_app` 无 UPDATE/DELETE 权限。
- 断言授权版本对象存在（ADR-004 §2.3、ER §3.9）：`users.authz_version`/`tenants.authz_version` 的非负 CHECK、只增触发器、权限变更触发器、`system_settings` 预置行；修改 `permissions`/`role_permissions` 的迁移必须同时递增 `authz.global_version`。
- 断言用户部门与部门状态约束对象存在（ER §3.10，决策 6-1 及决定 A/B/C）：
  - D1 部分唯一索引 `user_departments_one_primary`（`WHERE is_primary`）；
  - D2 保护触发器覆盖 `INSERT`、`UPDATE`、`DELETE`；D3 约束触发器为 `DEFERRABLE INITIALLY DEFERRED`；D4 `departments` 状态触发器覆盖 `status`、`deleted_at`；
  - D2/D3/D4 函数 `prosecdef = false`（`SECURITY INVOKER`）、`provolatile = 'v'`（`VOLATILE`）、设置了固定 `search_path`；
  - `departments.status` 为 `NOT NULL`，存在取值 CHECK 与组合 CHECK `(status = 'deleted') = (deleted_at IS NOT NULL)`；
  - 两条复合外键存在且为 `NO ACTION`；`user_departments`、`departments` 已 `ENABLE` + `FORCE ROW LEVEL SECURITY`；
  - 租户策略使用 `app.current_tenant_id()`，不直接使用 `current_setting(...)::uuid`；
  - `yonlink_app` 的列级授权与 ER §3.10.10 / ADR-005 §8 一致：`users.authz_version`、`users.tenant_id`、`user_departments` 键列、`tenants` 均无 UPDATE 权限；
  - D4 包含终态规则：迁移检查运行“`deleted` → `active`/`inactive` 被拒绝”的冒烟断言。
- 断言 `departments` 的授权版本触发器覆盖 `parent_id`、`status`、`deleted_at` 变化。
- 断言密码重置与邮件 Outbox 对象存在且正确（ER §3.11，决策 6-2）：
  - `password_reset_tokens`：`token_hash` 唯一且 `CHECK (octet_length = 32)`；`reset_type` 取值 CHECK；`reset_type` 与 `requested_by_user_id` 一致性 CHECK；按类型固定有效期的 CHECK（30 分钟 / 24 小时）；消费与撤销互斥 CHECK；`revoked_reason` 取值 CHECK；单一有效令牌部分唯一索引；目标用户与发起管理员两条复合外键；`ENABLE` + `FORCE ROW LEVEL SECURITY`；
  - `email_outbox`：`idempotency_key` 唯一；`event_type`、`status` 取值 CHECK；状态与租约/终态时间/密文字段的一致性 CHECK；`attempt_count`、`max_attempts` 范围 CHECK；领取与租约过期部分索引；`ENABLE` + `FORCE ROW LEVEL SECURITY`；仅存在 `TO yonlink_migrator` 的定向策略；
  - `yonlink_app` 对 `password_reset_tokens`、`email_outbox` **无任何表权限**，只对 `auth.*`、`outbox.*` 受控函数有 `EXECUTE`；
  - 受控函数为 `SECURITY DEFINER`、固定 `search_path`；`outbox.*` 属主为 `yonlink_migrator`；`auth.*` 属主按决策 6-10 结论校验；
  - `auth_sessions.revoked_reason` 取值包含 `password_reset`；
  - 冒烟断言：以 `yonlink_app` 直接 `SELECT` 两张表均报权限不足；`outbox.mark_sent` 在围栏条件不符时影响 0 行。
- 执行 rollback 循环测试。

## 4. 影响
- 迁移编写成本略高（需手写 SQL 与回滚）；换来可审查、可回退、可验证。
- 检查库位于 `yonlink-crm-test`（PG 内存上限 768 MB），仅在 CI 期间存在，计入 ADR-007 测试环境与临时空间预算。

## 5. 验收
- 空库执行迁移可重复成功；seed 可重复执行（幂等）。
- rollback 循环测试通过。
- 迁移前备份缺失时迁移脚本拒绝执行。
