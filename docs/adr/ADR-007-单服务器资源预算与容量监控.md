# ADR-007 单服务器资源预算与容量监控

- 状态：提议中
- 日期：2026-11-08
- 关联：ADR-001、ADR-002、ADR-008

## 1. 背景
唯一服务器：2 OCPU（2 核 Neoverse-N1）、12 GB RAM（实测 11.6 GiB）、100 GB 引导卷（文件系统 96 GB），当前**无 Swap**。
2026-11-08 实测：已用内存约 5.0 GB（Claude Desktop、Chromium、Xvnc 桌面、Claude Code），磁盘已用 12 GB。
因此应用栈可用内存约 6.5 GB，且必须为构建与测试峰值留出空间。

## 2. 内存与 CPU 预算

### 2.1 部署栈（`yonlink-crm-prod`，后续阶段；每个容器均设置 `mem_limit` 与 `cpus`）
| 组件 | 内存上限 | 内存预留 | CPU 上限 | 关键参数 |
|---|---|---|---|---|
| postgres | 2.0 GB | 1.0 GB | 1.0 | `shared_buffers=512MB`、`effective_cache_size=1536MB`、`work_mem=8MB`、`maintenance_work_mem=128MB`、`max_connections=50`、`max_wal_size=1GB` |
| valkey | 384 MB | 128 MB | 0.25 | `maxmemory 256mb`、`maxmemory-policy noeviction`（BullMQ 要求）、AOF `everysec` |
| api | 768 MB | 384 MB | 1.0 | `NODE_OPTIONS=--max-old-space-size=512`，连接池 10 |
| worker | 512 MB | 256 MB | 0.5 | `--max-old-space-size=384`，并发 2，连接池 5 |
| web | 512 MB | 256 MB | 0.5 | Next.js standalone，`--max-old-space-size=384` |
| nginx | 64 MB | 32 MB | 0.25 | `worker_processes 2` |
| **合计** | **≈ 4.2 GB** | **≈ 2.0 GB** | 超配可接受（上限非独占） | |

### 2.2 开发栈（`yonlink-crm-dev`，第一阶段）
| 组件 | 预计内存 |
|---|---|
| postgres + valkey 容器（同上限制，postgres 可降至 1.5 GB 上限） | ≤ 1.9 GB |
| `nest start --watch`（api）+ worker | ≈ 0.8 GB |
| `next dev` | ≈ 1.0–1.5 GB |
| **合计** | **≈ 3.7–4.2 GB** |

### 2.2A 测试环境（`yonlink-crm-test`，ADR-009，按需启动）
| 组件 | 内存上限 | 说明 |
|---|---|---|
| 测试 postgres | **768 MB** | `max_connections=30`；模板库 + 每进程测试库 |
| 测试 valkey | 128 MB | `maxmemory 64mb`；权限缓存与故障注入测试 |
| Vitest 单元测试（≤ 2 进程） | ≈ 0.6 GB | 不连接数据库 |
| Vitest 集成测试（1–2 进程） | ≈ 0.6 GB | 每进程独立测试库 |
| Playwright E2E（1 进程） | ≈ 0.8–1.0 GB | 与集成测试串行 |

运行集成测试/E2E 时的核算（**必须停止 `next dev` 与 API/Worker 开发进程**，开发 postgres/valkey 容器可保留）：
桌面与工具 5.0 + 开发容器 1.9 + 测试容器 0.9 + 测试进程峰值 1.0 ≈ **8.8 GB**，低于 11.6 GiB 物理内存。

### 2.3 峰值活动（串行执行，不并发）
| 活动 | 峰值 | 控制措施 |
|---|---|---|
| `next build` | 1.5–2.5 GB | `turbo --concurrency=1`；构建时停止 `next dev` |
| Playwright E2E | ≈ 0.8–1.0 GB | `workers=1`，仅 Chromium |
| `pnpm install` | ≈ 1.0 GB | 仅首次/依赖变更 |
| 测试/迁移检查数据库（ADR-006、ADR-009，`yonlink-crm-test`） | ≤ 0.9 GB（PG 768 MB + Valkey 128 MB 上限） | 按需启动，测试结束后停止 |
| restic 备份 | ≈ 0.3–0.5 GB | 夜间执行，`nice`/`ionice` 低优先级 |

### 2.4 总量核算
- 常驻桌面与工具：≈ 5.0 GB
- 开发栈：≈ 4.2 GB
- 单项峰值：≈ 2.5 GB
- 合计 ≈ 11.7 GB，**接近 11.6 GiB 物理上限**。

缓解措施（需负责人执行或批准）：
1. 建立 **4 GB Swap 文件**，`vm.swappiness=10`，仅作 OOM 缓冲（需 sudo，由负责人执行）。
2. 运行构建/E2E 时关闭不必要的浏览器标签与桌面应用。
3. 部署栈运行时停止开发栈；两者不得同时满负荷运行。
4. 所有容器 `restart: unless-stopped`，并配置健康检查；OOM 事件计入容量日志。

## 4. 日志轮转
- 应用（pino JSON）、Nginx 访问/错误日志全部输出到 stdout/stderr，由 Docker 收集。
- Docker 日志驱动：`local`（压缩），`max-size=10m`、`max-file=3`；每容器 ≤ 30 MB，6 个容器 ≤ 180 MB。
- 主机 journald：`SystemMaxUse=500M`（需 sudo，由负责人执行；当前占用 20.6 MB）。
- PostgreSQL：`log_min_duration_statement=500ms`、`log_rotation_size=10MB`，输出到 stderr 由 Docker 轮转。
- 审计日志存数据库（业务数据），不计入日志预算，按月分区，保留期由租户策略决定（默认 365 天，需负责人确认合规要求）。
- 日志禁止包含密码、令牌、密钥与敏感明文（脱敏器 + 测试断言）。

## 5. 容量监控与告警（不引入 Prometheus/Grafana，避免约 0.5 GB 常驻内存）
- `scripts/capacity-check.sh` 由 `ai` 用户 crontab 每 15 分钟执行（无需 sudo），采集：
  - 文件系统使用率与 inode；各预算目录占用（`du`）；
  - 内存/Swap 使用、容器 `docker stats` 快照、近期 OOM 事件；
  - restic 仓库大小与最近一次成功备份时间（ADR-008）；
  - 邮件 Outbox（ER §3.11）：`pending/retry_wait` 积压数、最老待发送任务年龄、`failed` 数量、未清理密文数量、`key_unavailable` 任务数。
- 输出 `/home/ai/yonlink-data/status/capacity.json`；API `/api/v1/system/status`（仅平台运维/租户管理员可见）读取并展示于仪表盘“真实系统状态”。
- 告警级别：

| 指标 | 警告 | 严重 | 紧急动作 |
|---|---|---|---|
| 文件系统使用率 | ≥ 70% | ≥ 80% | ≥ 90%：API 拒绝新上传（507），提示管理员清理；备份收紧保留 |
| 单类目录超预算 | 达告警阈值 | 超预算 | 写入审计/系统事件 |
| 可用内存（含 Swap） | < 1.5 GB | < 0.8 GB | 记录事件，提示停止开发进程 |
| 最近成功备份 | > 26 小时 | > 48 小时 | 仪表盘红色横幅 |
| 邮件 Outbox | 最老待发送任务 > 10 分钟，或存在 `key_unavailable` 任务 | 出现 `failed` 任务，或积压 > 100 | 仪表盘横幅；不删除失败任务（ER §3.11.7） |
| 离线副本最近同步 | > 8 天 | > 15 天 | 仪表盘提示负责人执行离线拉取 |

- 告警渠道：仪表盘横幅 + 结构化日志；如负责人提供**已有**邮箱 SMTP，可选邮件通知（非运行前提）。

## 6. 验收
- `docker compose config` 显示所有服务都有内存与 CPU 限制及日志轮转配置。
- 模拟磁盘阈值（测试用阈值参数）触发对应告警与上传拒绝。
- 在开发栈运行状态下执行一次完整 `pnpm ci:local`，记录峰值内存，不发生 OOM。
