# ADR-009 测试框架与数据库集成测试

- 状态：**负责人已决策**（决策 5/9，2026-11-08）；正式文本待 T0-A 最终决策清单统一批准
- 日期：2026-11-08
- 关联：ADR-001、ADR-004、ADR-005、ADR-006、ADR-007、`docs/04-第一阶段开发任务书.md` T1/T2/T3/T10

## 1. 背景
- 全仓包含 NestJS（依赖装饰器元数据）、Next.js 16 + React 19 + Ant Design v6、Prisma 7（新生成器输出 ESM/TS）。
- 多租户隔离的核心防线是 PostgreSQL RLS，必须以**真实数据库 + 正式运行时角色**验证，不得以 mock 代替。
- 单服务器 2 OCPU / 12 GB RAM（ADR-007），测试必须控制并发与内存。
- 2026-11-08 核查版本：Vitest 5.1.0（Vite 8 / rolldown，`@rolldown/binding-linux-arm64-gnu` 可用）、`@vitest/coverage-v8` 5.1.0、`unplugin-swc` 2.0.0、`@swc/core` 1.16.22（`linux-arm64-gnu` 可用）、`@nestjs/testing` 12.4.0、supertest 7.3.2、Playwright 1.65.0。

## 2. 决策一：测试框架 —— Vitest 5（全仓统一）

### 2.1 适用范围
`apps/api`、`apps/worker`、`apps/web`、`packages/*` 统一使用 Vitest 5。E2E 使用 Playwright，**不纳入 Vitest 替代范围**。

### 2.2 技术约定
1. 后端使用 Vitest + `unplugin-swc`，输出 NestJS 所需的装饰器元数据（`emitDecoratorMetadata`），并在 T1 验证。
2. 后端测试配合 `@nestjs/testing` 与 `supertest`。
3. 前端使用 Vitest + jsdom + Testing Library。
4. Ant Design 测试环境所需的浏览器接口（如 `window.matchMedia`、`ResizeObserver`、`getComputedStyle` 相关补丁）在测试初始化文件中统一补齐，位于 `packages/ui` 提供的共享测试 setup。
5. 覆盖率使用 `@vitest/coverage-v8`（无原生二进制依赖）。
6. 统一由根配置（Vitest projects）管理各 workspace 的测试项目。

### 2.3 T1 概念验证（PoC）必须证明
| # | 验证项 | 通过标准 |
|---|---|---|
| P1 | NestJS 依赖注入 | 构造函数注入、自定义 provider、`@Inject()` 令牌在 Vitest 中正常解析 |
| P2 | 守卫（Guard） | 全局与路由级 Guard 生效，拒绝路径返回预期状态码 |
| P3 | 管道（Pipe） | 全局 `ValidationPipe`（`whitelist` + `forbidNonWhitelisted`）基于 class-validator 装饰器正常校验 |
| P4 | Prisma 7 ESM 客户端 | 生成的客户端可在 Vitest 中直接导入并连接测试数据库 |
| P5 | 峰值内存 | 单元测试（2 进程）与集成测试（1–2 进程）峰值内存分别记录，合计 ≤ ADR-007 测试活动预算 |
PoC 结果写入 T1 里程碑报告（真实命令与输出）。

### 2.4 回退规则
- 仅当 NestJS 装饰器元数据存在**无法合理解决**的问题时，才允许评估后端（`apps/api`、`apps/worker`）单独采用 Jest 30 + `@swc/jest`。
- 必须提交独立 ADR，**未经负责人批准不得切换**。
- 前端与 packages 不受影响，继续使用 Vitest。

### 2.5 质量底线
不允许因为选择 Vitest 而放松覆盖率、安全测试或 RLS 测试要求：
- 安全关键路径（认证、会话、授权、租户上下文、审计）分支覆盖率 ≥ 90%；
- ADR-004 S1–S25、ADR-005 §5 全部必过项、§3 RLS 测试矩阵均不得跳过（禁止 `.skip`/`.only` 进入主干，lint 规则拦截）。

## 3. 决策二：RLS 集成测试方案（负责人已批准）

### 3.1 测试环境
| 项 | 约定 |
|---|---|
| Compose 项目 | `yonlink-crm-test`（与 `yonlink-crm-dev`、`yonlink-crm-prod` 完全独立：独立容器、数据目录、凭据） |
| PostgreSQL | 与生产同版本镜像（`postgres:18-alpine`，固定 digest）；**内存上限 768 MB**；`max_connections=30`；仅绑定 `127.0.0.1` 或仅容器内部网络 |
| Valkey | 测试专用实例（`valkey/valkey:8-alpine`）；`maxmemory 64mb`，**内存上限 128 MB**；用于权限缓存与故障注入测试（ADR-004 S8/S9） |
| 数据存储 | 测试数据目录 `/home/ai/yonlink-data/test/`，可随时销毁重建；计入 ADR-007 “临时空间”预算 |
| 生命周期 | 由测试脚本按需启动；测试结束后默认停止容器（保留模板库以加速下次运行） |

### 3.2 数据库角色（测试集群）
角色为集群级对象，测试集群创建与生产**完全相同**的运行时角色及权限，另加一个测试专用管理角色：

| 角色 | 测试中的用途 | 约束 |
|---|---|---|
| `postgres`（容器超级用户） | **仅**用于容器首次初始化脚本创建下列角色 | 测试代码与测试连接中禁止使用 |
| `yonlink_test_admin` | 创建/删除模板库与测试库、重建模板 | `CREATEDB`；非超级用户；无 `BYPASSRLS`；不持有业务表；仅测试脚本持有凭据；**不得用于执行任何业务断言** |
| `yonlink_migrator` | 在模板库执行全部迁移（业务表属主） | 与生产一致 |
| `yonlink_app` | **所有 RLS 集成测试与 API 集成测试的数据库连接** | 与生产完全一致：非超级用户、`NOBYPASSRLS`、非业务表属主 |
| `yonlink_auth` | `SECURITY DEFINER` 登录/会话解析函数属主 | 与生产一致 |
| `yonlink_backup` | 备份脚本测试（ADR-008） | 与生产一致 |

测试角色权限必须与正式运行时角色一致；**不得通过提高权限让测试通过**。角色授权脚本与生产共用同一份迁移 SQL。

### 3.3 模板库与测试库流程
1. **构建模板**：`yonlink_test_admin` 创建 `yonlink_test_template` → `yonlink_migrator` 在其中执行全部迁移与测试基线 seed → 记录迁移校验和（数据库 `COMMENT` 保存所有迁移文件的 SHA-256 汇总）。
2. **封存模板**：迁移完成后断开所有连接；`ALTER DATABASE yonlink_test_template WITH IS_TEMPLATE true ALLOW_CONNECTIONS false`，防止任何会话连入（`CREATE DATABASE ... TEMPLATE` 要求模板无活动连接）。
3. **复用判断**：运行前比较迁移校验和；不一致则删除并重建模板。
4. **创建测试库**：每个测试进程由 `yonlink_test_admin` 执行
   `CREATE DATABASE yonlink_test_{run_id}_w{worker} TEMPLATE yonlink_test_template`。
   - `CREATE DATABASE` **不得在事务块内执行**，使用独立的自动提交连接。
   - 复制后表属主仍为 `yonlink_migrator`，`yonlink_app` 保持非属主。
5. **执行测试**：测试进程以 `yonlink_app` 连接自己的测试库。
6. **清理**：测试结束后 `yonlink_test_admin` 执行 `DROP DATABASE ... WITH (FORCE)`。
7. **失败恢复**：
   - 每次运行开始前，清理名称匹配 `yonlink_test_*_w*` 且不属于当前 `run_id` 的残留库；
   - 模板构建失败 → 删除不完整模板并以非零退出码终止，不得使用半成品模板；
   - 容器异常 → `docker compose -p yonlink-crm-test down` 后可安全重建（测试数据无保留价值）；
   - 测试中断（Ctrl+C、OOM）后的残留由下次运行开始前的清理步骤处理。

### 3.4 守卫测试（每次集成测试运行的第一个测试，失败则中止全部集成测试）
- `current_user = 'yonlink_app'`；
- `SELECT rolsuper, rolbypassrls FROM pg_roles WHERE rolname = current_user` 均为 `false`；
- 对所有含 `tenant_id` 的业务表，`pg_tables.tableowner <> current_user`；
- 所有含 `tenant_id` 的表 `relrowsecurity` 与 `relforcerowsecurity` 均为 `true`；
- 当前数据库名匹配 `yonlink_test_%`（防止误连开发或生产库）。

### 3.5B 密码重置与邮件 Outbox 测试矩阵（决策 6-2，ER §3.11）
数据库相关用例以真实 `yonlink_app` 角色执行；SMTP 使用测试替身（可注入成功、4xx、5xx、超时、“接受后崩溃”）；Valkey 故障使用测试 Valkey 容器启停与客户端故障注入。原始令牌、密码、收件人在任何测试输出中都必须被断言为不存在于日志。

| PR4 | 过期令牌 | 确认重置被拒绝，统一提示 |
| PR5 | 已消费令牌再次使用 | 拒绝 |
| PR6 | **并发消费**：同一令牌并发确认（≥ 200 次循环） | 每轮恰好一个成功，其余失败；密码只更新一次 |
| PR7 | 已撤销令牌（`superseded` 等） | 拒绝 |
| PR8 | 用户已禁用/软删除，或租户停用 | 确认被拒绝且整体回滚（令牌不被消费）；申请不产生令牌与邮件 |
| PR9 | 新申请取代旧令牌（⏳ 待确认行为，见 ER §3.11.2） | 旧令牌 `superseded`，旧链接失效 |
| PR10 | 重置令牌用作 Session Cookie 或访问受保护 API | 401；重置成功后未自动登录 |

**账号枚举**
| # | 场景 | 期望 |
|---|---|---|
| PE1 | 不存在的邮箱 / 存在的邮箱 / 存在但禁用 / 不存在的租户 slug | 均 HTTP 202，响应体与响应头逐字节一致（除通用请求 ID）；不存在时不产生邮件 |
| PE2 | 响应时间分布 | 存在与不存在两组的中位数差异在测试阈值内（应用对两类请求执行相同的令牌生成与加密工作） |
| PE3 | 异常路径（数据库错误、Valkey 故障、触发限速） | 不泄露账号信息；限速命中仍返回 202 |
| PE4 | 管理员路径：目标用户属于其他租户 | 与目标不存在相同的 404，不泄露其他租户信息 |

**限速**
| # | 场景 | 期望 |
|---|---|---|
| PL1 | 同一账号 1 小时内第 4 次申请 | 202，不产生令牌与邮件 |
| PL2 | 同一 IP 1 小时内第 11 次申请 | 202，不产生令牌与邮件 |
| PL3 | 邮箱规范化绕过：大小写、前后空白、Unicode 兼容字符 | 计入同一账号计数 |
| PL4 | 伪造 `X-Forwarded-For` | 不改变限速使用的 IP（只信任 Nginx 设置的来源地址） |
| PL5 | Valkey 停止/超时 | 账号限速由数据库计数兜底；IP 限速由 API 进程内限速器执行（更严格阈值）；无无限制放行 |
| PL6 | API 进程重启后 Valkey 仍不可用 | 进程内计数清零，但数据库账号计数仍生效；文档化的边界被验证 |
| PL7 | 多 API 进程（仅作为边界验证） | 记录进程内限速按进程数放大的行为，与 ER §3.11 文档描述一致 |

**会话撤销**（与 ADR-004 S6a–S6d 联动）
| # | 场景 | 期望 |
|---|---|---|
| PS1 | 重置成功 | 该用户全部 `auth_sessions` 撤销（`password_reset`），其他未使用令牌撤销（`reset_completed`），其 Outbox 任务 `cancelled` |
| PS2 | 重置事务中途失败（故障注入） | 全部回滚：密码不变、会话有效、令牌未消费 |
| PS3 | 提交后开始的新请求 | 使用旧会话的请求被拒绝 |
| PS4 | 登录用户主动修改密码 | 其他会话撤销，当前会话轮换后可用 |
| PS5 | 平台运维账号 | 无法经租户自助或租户管理员接口重置；`password_reset_tokens`、`email_outbox` 中不出现平台账号数据 |

**Outbox 与 Worker**
| # | 场景 | 期望 |
|---|---|---|
| PO1 | 申请成功 | 令牌与 Outbox 任务在同一事务提交 |
| PO2 | 事务回滚（故障注入） | 两者都不留下 |
| PO3 | 正常发送 | `sent`，密文已清理，`sent_at` 非空 |
| PO4 | Worker 发送中被杀死 | 租约过期后被重新领取并完成 |
| PO5 | SMTP 4xx / 超时 | `retry_wait`，按退避重试 |
| PO6 | SMTP 5xx（永久错误） | 直接 `failed`，关联令牌 `delivery_failed`，产生告警 |
| PO7 | 超过 `max_attempts` 或 `deliver_before` | `failed`，不删除任务 |
| PO8 | BullMQ 唤醒任务丢失 | 轮询仍完成投递 |
| PO9 | 申请时 Valkey 不可用 | Outbox 任务已持久化，Valkey 恢复前由轮询投递 |
| PO10 | 多 Worker 并发（2 个实例，≥ 200 个任务） | 无同一任务被两个 Worker 同时持有；每个任务最终进入终态 |
| PO11 | 重复唤醒 / 重复领取 | 围栏条件拒绝旧 Worker 的状态变更；状态转换不重复 |
| PO12 | SMTP 接受后、`mark_sent` 前 Worker 崩溃 | 可能重复发送同一封邮件；令牌仍只能消费一次 |
| PO13 | 令牌在发送前已消费/撤销/过期 | `cancelled`，不发送 |
| PO14 | 数据库与日志检查 | Outbox 只有密文；日志、异常、BullMQ 任务数据中无收件人完整地址、原始令牌或明文载荷 |
| PO15 | 密钥缺失或解密失败 | 任务暂停（不计重试）并告警；截止后 `failed`；无明文降级 |
| PO16 | 终态清理 | `sent/failed/cancelled` 的密文字段均为 `NULL`，`payload_purged_at` 非空 |
| PO17 | 密文挪用（把 A 行密文复制到 B 行） | AAD 校验失败，拒绝发送 |
| PO18 | 保留期清理 | 超过保留期的令牌与 Outbox 行被删除；未到期的不受影响 |

### 3.6 并发与资源控制
| 测试类型 | 进程数 | 数据库 |
|---|---|---|
| 单元测试 | 最多 2 | 不连接数据库 |
| 集成测试 | 1–2 | 每进程一个独立测试库 |
| E2E 测试（Playwright） | 1 | 使用由模板复制的 E2E 专用库 |

- 单元、集成、E2E **串行执行，不得同时运行**（`pnpm ci:local` 顺序编排）。
- 运行集成测试与 E2E 时，应停止 `next dev` 与 API/Worker 开发进程（ADR-007 内存核算前提）。
- 测试 PostgreSQL 768 MB + 测试 Valkey 128 MB 纳入 ADR-007 预算。

## 4. 备选方案
| 方案 | 结论 | 原因 |
|---|---|---|
| Jest 30（全仓） | 否决 | Prisma 7 ESM 下 Jest ESM 仍为实验性；`ts-jest` 不支持 TS 7；内存占用较高 |
| Testcontainers 每次动态起容器 | 不采用 | 单机资源下反复启停容器开销大；固定 Compose 项目更可控（`@testcontainers/postgresql` 可用，保留为备选） |
| 事务回滚隔离（每测试包一个事务） | 不作为主方案 | 无法测试事务边界、`SET LOCAL` 生命周期与连接池复用；仅可用于部分单表测试 |
| 以超级用户或属主运行 RLS 测试 | 禁止 | RLS 被绕过，测试结果无效 |
