## 0. 负责人正式决策：Node.js 版本与容器基础镜像（2026-11-08，决策 2/9）
以下条款为正式决策，优先于本文其他位置的旧表述。

### 0.1 Node.js 版本
- 选择 **Node.js 26 LTS**（"Lithium"；Active LTS 2026-10-28，维护期 2027-10-20，EOL 2029-04-30，依据 nodejs/Release `schedule.json`）。
- `.nvmrc` 内容为 `26`。
- 根及各 workspace `package.json` 的 `engines.node` 设置为 `>=26.13 <27`。
- 开发环境与容器环境统一使用 Node 26；**不使用 Node 24 作为默认版本**。

### 0.2 容器基础镜像
- 使用 `node:26-trixie-slim`（Debian 13 Trixie，glibc）。
- 必须验证 `linux/arm64` 兼容性（2026-11-08 已核对官方 manifest 含 arm64；T0-B 安装 Docker 后以 `docker manifest inspect` 复核并记录）。
- 采用**多阶段 Docker 构建**：依赖安装/构建阶段与运行阶段分离；运行镜像仅包含生产依赖与构建产物，以非 root 用户运行，尽量减小镜像体积。

### 0.3 镜像维护
- 生产部署镜像（含基础镜像及 postgres/valkey/nginx）**固定 digest**。
- **每月**检查一次安全补丁（Node 补丁版本、Debian 安全更新、依赖镜像新 digest）。
- 更新 digest 前必须完成构建与全部自动化测试（`pnpm ci:local`）。
- 保留**上一个已验证版本**的镜像与 digest 记录，确保可回退（计入 ADR-007 Docker 磁盘预算）。
- 不允许长期固定旧 digest 而不进行安全更新；超过 45 天未执行月度检查视为待办逾期，纳入容量/系统状态提示。

### 0.4 升级规划
- Node 26 预计 2029-04-30 结束支持，**届时必须已完成升级**。
- Node 28 预计 2028-10 进入 LTS，届时评估升级并提交 ADR。
- 若 Node 26 遇到无法解决的依赖阻塞，可评估 Node 24，但必须**单独提交 ADR**，并重新进行兼容性与安全测试。

## 0A. 负责人正式决策：前端组件库（2026-11-08，决策 4/9）
以下条款为正式决策。

### 0A.1 技术选择
1. 采用 **Ant Design v6.x**（2026-11-08 核查：6.7.0，MIT，peer React ≥ 18；锁定次版本，升级经测试后进行）。
2. 使用 `@ant-design/nextjs-registry` 适配 Next.js App Router 样式提取。
3. 使用 `@ant-design/icons`。
4. **暂不引入 Ant Design ProComponents**（稳定版 2.8.10 的 peer 依赖仅为 `antd ^4.24 || ^5.11`，不兼容 v6；v3 尚为 beta）。待 v3 正式稳定且兼容 v6 后另立 ADR 评估。
5. **暂不引入 Tailwind CSS**，避免两套样式体系并存。
6. 样式使用 **Ant Design Theme Token + CSS Modules**。
7. 业务文案统一使用 **next-intl**（i18n key），组件中不得硬编码中文或英文文案。
8. 组件内置文字（分页、日期、空状态等）使用 Ant Design `ConfigProvider` 语言包（`zh_CN`、`en_US`）及 dayjs locale，随用户 locale 切换。

### 0A.2 自有封装层 `@yonlink-crm/ui`（`packages/ui`）
- 业务模块只能从 `@yonlink-crm/ui` 引入 UI 组件。
- ESLint `no-restricted-imports` 禁止 `apps/web` 业务代码直接 import `antd`、`antd/*`、`@ant-design/*`；仅 `packages/ui` 允许。
- 封装层统一管理：品牌主题 token、`ConfigProvider`（主题 + locale）、组件国际化、使用规范与默认密度。
- 权限相关组件（如按权限隐藏按钮/菜单）**仅用于体验**，不构成安全控制；NestJS 后端必须对每个请求独立执行授权（CLAUDE.md 规则 4）。
- 将来升级或更换 Ant Design 时，变更应尽可能限定在 `packages/ui` 内。

### 0A.3 永联CRM 自有视觉规范
T8 交付 `docs/design/visual-guidelines.md`（经负责人审核），至少定义：
- 品牌主色及语义色（成功/警告/错误/信息），满足 WCAG AA 对比度；
- 字体栈（中文优先、系统字体自托管/本地回退，不依赖外部字体 CDN）；
- 圆角、间距刻度；
- 紧凑型企业级界面密度（默认 compact 算法或自定义 token）；
- 表格、表单、菜单、仪表盘的统一风格与使用示例。
- **不使用 Zoho 的配色、图标或专有界面表达**。

### 0A.4 ARM64 与资源
- antd、icons、nextjs-registry、next-intl、dayjs 均为纯 JS，无原生二进制依赖。
- 构建内存在 ADR-007 预留的 `next build` 峰值（≤ 2.5 GB）内，T8 实测后记录。

## 1. 背景

永联CRM 必须运行在唯一一台现有服务器上：

| 项 | 值 |
|---|---|
| 云平台 | Oracle Cloud（现有实例，不新增任何云资源） |
| 操作系统 | Ubuntu 26.04.1 LTS，内核 7.0.0-oracle |
| 架构 | aarch64（Ampere / Neoverse-N1） |
| CPU | 2 OCPU（`nproc` = 2，每核 1 线程） |
| 内存 | 12 GB（实测 MemTotal ≈ 11.6 GiB） |
| 磁盘 | 100 GB 引导卷（文件系统 96 GB） |
| 用户 / 目录 | `ai` / `/home/ai/Desktop/CRM/Yonlink-CRM/` |

该服务器同时承担开发环境（含桌面 VNC、Chromium、Claude Code，实测常驻约 5 GB 内存）与后续私有部署环境。

## 2. 决策

### 2.1 架构形态
- 模块化单体：一个 NestJS API 进程 + 一个 Worker 进程 + 一个 Next.js Web 进程。
- 编排：Docker Compose（Compose v2）。**不使用 Kubernetes、Docker Swarm 或微服务集群。**
- 所有运行组件部署在本服务器：`nginx`、`web`、`api`、`worker`、`postgres`、`valkey`。
- 不包含独立对象存储容器（见 ADR-002）。

### 2.2 技术栈与版本（均已确认 linux/arm64 可用）

| 组件 | 选型 | 版本策略 | ARM64 依据 |
|---|---|---|---|
| 运行时 | Node.js | **Node 26 LTS**（已决策，见 §0）；开发与容器统一；`engines >=26.13 <27` | 官方 arm64 镜像 `node:26-trixie-slim` 已核对 |
| 包管理 | pnpm workspaces | 锁定主版本，`packageManager` 字段固定；Node 26 无 corepack，经 npm 安装至用户目录 | 纯 JS |
| 构建编排 | Turborepo | 2.x，`--concurrency=1`（资源约束） | 提供 linux-arm64 二进制 |
| 后端 | NestJS | 12.x | 纯 JS |
| 前端 | Next.js（App Router，`output: standalone`） | 16.x | SWC 提供 linux-arm64-gnu |
| ORM | Prisma | **锁定 7.x 稳定版**（npm `latest` 当前指向 8.0.0-rc，禁止使用）+ `@prisma/adapter-pg` | 7.x 使用 TS 查询编译器，无 Rust 引擎二进制依赖 |
| 数据库 | PostgreSQL | **18**（原生 `uuidv7()`）镜像 `postgres:18-alpine` | manifest 已核对 arm64 |
| 缓存/队列 | **Valkey**（负责人指定）+ BullMQ | Valkey 8.x 镜像 `valkey/valkey:8-alpine` | manifest 已核对 arm64；BSD 许可适合私有化交付 |
| 反向代理 | Nginx | `nginx:1-alpine` | manifest 已核对 arm64 |
| 密码哈希 | `@node-rs/argon2`（Argon2id） | 2.x | 提供 `linux-arm64-gnu` 预编译包 |
| 前端 UI | Ant Design v6 + `@ant-design/nextjs-registry` + `@ant-design/icons`，经 `@yonlink-crm/ui` 封装（已决策，见 §0A） | 6.x 锁定次版本；不引入 ProComponents、Tailwind | 纯 JS |
| 前端国际化 | next-intl + antd ConfigProvider 语言包 + dayjs | 4.x | 纯 JS |
| 测试 | **Vitest 5**（全仓统一，已决策，见 ADR-009）+ `unplugin-swc` + `@vitest/coverage-v8`；E2E 使用 Playwright | — | Playwright 在 Ubuntu 26.04 的系统依赖需安装后复核；必要时用官方 Playwright 容器 |
| 备份 | restic | Ubuntu 仓库 0.18.1 | apt arm64 包已确认（安装需负责人批准） |

### 2.3 环境划分（同一服务器）
| 环境 | Compose 项目名 | 内容 | 端口绑定 |
|---|---|---|---|
| 开发 | `yonlink-crm-dev` | 仅 `postgres`、`valkey` 容器；api/web/worker 用 `pnpm dev` 在主机运行 | 仅 `127.0.0.1` |
| 私有部署（后续阶段） | `yonlink-crm-prod` | 全部 6 个容器 | 仅 Nginx 对外，且需负责人单独批准 |
| 恢复演练 | `yonlink-crm-restore` | 临时 postgres + 恢复校验 | 仅 `127.0.0.1`，演练后销毁 |

- 各环境使用**独立数据目录、独立数据库凭据、独立 Valkey 实例**，互不共享。
- 受资源限制，**不得同时满负荷运行开发栈与部署栈**；运行部署栈时应停止开发进程（见 ADR-007）。

### 2.4 数据目录（项目目录之外，避免误入 Git 或误删）
```text
/home/ai/yonlink-data/
  dev/{postgres,valkey,files}/
  prod/{postgres,valkey,files}/        # 后续阶段
  status/                              # 容量与备份状态 JSON
/home/ai/yonlink-backups/              # restic 本地仓库与离线导出暂存（见 ADR-008）
```
> 以上目录将在 T2 实施阶段经批准后创建，本 ADR 不创建。

### 2.5 网络暴露
- 第一阶段**不部署到公网**：所有端口仅绑定 `127.0.0.1`，通过 SSH 隧道访问。
- PostgreSQL、Valkey 永不对外暴露端口；Nginx 对外开放需负责人单独批准并记录 ADR。
- 已发现现有服务 Xvnc 监听 `0.0.0.0:8484`、rpcbind 监听 `0.0.0.0:111`，建议负责人核对 OCI 安全列表（本项目不修改防火墙）。
- 前端所有字体、图标、脚本随构建产物自托管，**不依赖任何外部 CDN**（同时规避境内访问问题）。

### 2.6 CI/CD
- 不依赖付费 CI/CD。主 CI 为本机脚本 `pnpm ci:local`：install（frozen lockfile）→ lint → typecheck → unit → integration → e2e → build → migration check → 依赖审计 → 密钥扫描。
- 通过 git `pre-push` 钩子强制运行快速检查；完整 CI 在提交里程碑前手动运行并记录结果。
- 代码异地保存通过 `git bundle` 纳入离线备份（ADR-008）；是否另行使用免费代码托管由负责人决定，**不作为前提**。
- 部署方式：本机 `docker compose build` + `up`，不使用外部镜像仓库推送。

## 3. 备选方案

| 方案 | 结论 | 原因 |
|---|---|---|
| Kubernetes / k3s | 否决 | 违反约束；控制平面占用 0.5–1 GB 内存 |
| 微服务拆分 | 否决 | 违反约束；单机无收益 |
| Redis 8 | 否决 | 负责人指定 Valkey；Redis 8 许可（AGPL/RSAL/SSPL）不利于私有化交付 |
| MinIO 容器 | 否决 | 社区镜像已无法获取；第一阶段改用本地磁盘（ADR-002） |
| 托管 CI（GitHub Actions 等） | 不作为前提 | 约束禁止依赖付费 CI；ARM 私有仓库 runner 收费 |

## 4. 影响
- 正面：无外部付费依赖；运维面最小；完全可在单机复现。
- 负面：单点故障（服务器宕机即服务中断）；横向扩展能力有限。RTO 依赖本服务器修复或在同一实例上重建，见 ADR-008。
- 需同步：`docs/03-系统架构.md`、`docs/04-第一阶段开发任务书.md` 中 MinIO/Redis 表述（批准后修订）。

## 5. 验收
- 所有镜像 `docker manifest inspect` 包含 `linux/arm64`（安装 Docker 后复核并记录）。
- `docker compose config` 中无对外绑定的数据库/缓存端口。
- 仓库中无任何云厂商 SDK 作为运行必需依赖。
