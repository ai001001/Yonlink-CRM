# ADR-008 备份、恢复与离线灾备

- 状态：提议中
- 日期：2026-11-08
- 关联：ADR-002、ADR-005、ADR-006、ADR-007

## 1. 背景
- 唯一服务器、唯一 100 GB 磁盘；本地备份最多 20 GB（ADR-007）。
- 负责人约束：必须有容量告警、保留周期、离线备份；**同盘备份不得视为唯一灾备**；不得依赖付费云存储。

## 2. 决策

### 2.1 备份对象
| 对象 | 方式 | 频率（UTC） |
|---|---|---|
| PostgreSQL 业务库 | `pg_dump -Fc`（以 `yonlink_backup` 角色）+ `pg_dumpall --globals-only`（角色定义） | 每日 18:30（北京时间 02:30）；可配置为每 6 小时 |
| 迁移前快照 | 同上，标签 `pre-migrate` | 每次 `migrate deploy` 前（ADR-006） |
| 上传文件目录 | restic 增量 | 每日 19:00 |
| 配置 | `.env`（含密钥，包括邮件 Outbox 加密密钥环 `EMAIL_OUTBOX_KEYS`，ER §3.11.4）、Compose override、Nginx 配置、TLS 证书（如有）、crontab 导出 | 每日，随文件备份 |
| 代码仓库 | `git bundle --all` | 每日 |

- 工具：**restic**（BSD-2，Ubuntu 仓库 arm64 包），提供 AES-256 加密、去重、保留策略与完整性校验。
- 本地仓库：`/home/ai/yonlink-backups/restic`（与数据目录、项目目录分离）。
- 备份脚本以 `nice -n 19 ionice -c3` 运行，避免影响在线服务。
- 一致性：数据库使用逻辑导出（自洽）；文件先备份后校验 sha256 样本。

### 2.2 本地保留策略（20 GB 硬上限）
- 常规：`--keep-daily 7 --keep-weekly 4 --keep-monthly 3`；`pre-migrate` 快照保留最近 5 个。
- 仓库 ≥ 16 GB：告警；≥ 18 GB：自动收紧为 `--keep-daily 3 --keep-weekly 2 --keep-monthly 1` 并告警。
- 任何情况下**保留最近 3 个成功快照**，不会因容量清理导致无可用备份。
- 每次备份后 `restic forget --prune`；每周 `restic check --read-data-subset=10%`。

### 2.3 离线副本（脱离本服务器，不依赖云存储）
采用 3-2-1 原则的单服务器变体：
| 副本 | 位置 | 频率 | 方式 |
|---|---|---|---|
| 1 | 本服务器 restic 仓库 | 每日 | 自动 |
| 2 | 负责人自有电脑（Windows） | **每周** | 由电脑端**主动拉取**（MobaXterm SFTP / WinSCP 同步 / `rsync`/`scp`）整个 restic 仓库目录 |
| 3 | 负责人自有移动硬盘（拉取后断开） | **每月** | 从副本 2 复制，存放后物理断开 |

- **拉取模式**：服务器不保存任何访问负责人电脑或移动介质的凭据，服务器被入侵也无法删除离线副本。
- restic 仓库已加密，离线介质丢失不会泄露明文。
- **restic 仓库密码与 `.env` 主密钥由负责人离线保管**（密码管理器 + 纸质备份），不能只存于本服务器；否则服务器损毁将导致备份无法解密。
- 离线拉取完成后，负责人运行一条校验命令（`restic check`，可在电脑端执行）或在服务器端记录“离线同步时间戳”，供 ADR-007 监控“离线副本时效”。

### 2.4 恢复流程（Runbook：`docs/runbooks/backup-restore.md`，T2 阶段编写）
1. 确认故障范围与恢复点（RPO：数据库 ≤ 24 小时，可配置为 ≤ 6 小时）。
2. 停止 `api`、`worker`、`web`，保留 Nginx 维护页。
3. 从本地 restic（或离线副本复制回服务器）还原指定快照到临时目录。
4. 先恢复全局角色，再 `pg_restore` 到新库，执行迁移状态校验。
5. **轮换权限缓存纪元并清空权限缓存**（ADR-004 §2.3.3）：将 `system_settings` 中 `authz.cache_epoch` 更新为新 UUID，并清空 Valkey `perm:` 命名空间，防止恢复导致的版本号回退复用旧缓存。
6. 还原文件目录与配置；抽样校验 sha256。
   - **邮件 Outbox 一致性**（决策 6-2）：恢复后检查所有未终态 `email_outbox` 任务引用的 `payload_key_id` 均存在于恢复后的密钥环中；缺失的任务保持暂停并告警，到达 `deliver_before` 后按 ER §3.11.4 进入 `failed` 并撤销关联令牌，**不得**明文降级。Worker 启动后从 Outbox 重新扫描未完成任务，BullMQ 中的唤醒任务无需恢复。
   - 恢复后是否统一撤销会话与未使用的重置令牌属于决策 6-11，本步骤不作规定。
7. 运行冒烟测试与租户隔离快速测试后恢复服务。
8. 写入恢复记录（时间、快照 ID、耗时、校验结果）。
- RTO 目标：服务器可用前提下 ≤ 4 小时；若服务器整体损毁，需在同一实例重装系统后按 Runbook 从离线副本恢复（不新增任何云资源）。

### 2.5 恢复演练
- **每月一次**在本服务器隔离环境执行：Compose 项目 `yonlink-crm-restore`，独立端口（仅 127.0.0.1）与临时目录，使用 ≤ 5 GB 磁盘、≤ 1 GB 内存，演练期间暂停开发构建。
- 校验项：表行数对比、关键约束与 RLS 存在性、审计哈希链连续性、文件 sha256 抽样。
- 演练结束立即销毁临时容器与数据，并记录结果。
- 第一阶段 DoD 要求至少完成一次演练。

### 2.6 监控与告警
- 备份失败、最近成功备份超时、仓库超阈值、离线副本超期均进入 ADR-007 容量监控。

## 3. 备选方案
| 方案 | 结论 | 原因 |
|---|---|---|
| 同盘目录复制 | 否决作为唯一灾备 | 违反约束；磁盘损坏/实例删除即全部丢失 |
| 云对象存储（S3/OSS/COS） | 否决 | 违反约束 |
| 挂载第二块云盘 | 否决 | 属于新增云资源 |
| pgBackRest + WAL 归档（PITR） | 推迟 | 增加磁盘与运维复杂度；当业务要求 RPO < 6 小时再评估 |
| 服务器推送到负责人电脑 | 否决 | 需在服务器保存远端凭据，入侵后可破坏离线副本 |

## 4. 已知风险
- 离线副本依赖负责人定期执行拉取；超期将由仪表盘提示，但无法自动保证。
- 负责人家用/办公网络带宽影响首次全量拉取耗时（预计几百 MB 至数 GB）。
- 单服务器架构下服务中断期间无法自动切换，RTO 依赖人工恢复。

## 5. 验收
- 备份脚本、保留策略、超限收紧有自动化测试（使用小阈值参数）。
- 完成一次完整恢复演练并记录。
- 完成一次离线拉取并在电脑端 `restic check` 通过。
- 确认负责人已离线保存 restic 密码。
