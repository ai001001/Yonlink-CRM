# Yonlink-CRM Enterprise — 正式产品需求文档（PRD）

- 文档版本：1.0
- 产品代号：Yonlink-CRM
- 产品类型：Enterprise
- 部署模式：Private / Self-hosted
- 目标市场：中国及国际市场
- 默认语言：简体中文；支持英文，后续扩展其他语言
- 状态：待产品负责人评审
- 重要声明：以 Zoho CRM 企业版公开功能作为能力对标基准，不复制其源代码、商标、专有素材或受保护的界面表达。

## 1. 产品愿景与目标

建设一套可私有化部署、面向中大型企业、模块化可扩展的 CRM 平台。产品应覆盖从线索获取、客户管理、销售机会、报价合同、订单回款、营销、客户服务，到流程自动化、权限治理、报表分析和开放集成的完整客户生命周期。

“功能对标”按能力域和验收用例衡量，不以页面数量衡量。Zoho 的企业版能力基线包括销售自动化、预测、多币种、评分、团队销售、活动、报表、字段级安全、自定义模块、布局、Blueprint、审批、Cadences、API、Sandbox、门户等。具体版本能力和限制可能调整，正式验收时应以需求冻结时的官方功能清单复核。

## 2. 产品目标与非目标

### 2.1 目标
1. 单套私有部署支持一个或多个逻辑组织/租户，租户间强隔离。
2. 提供完整的 CRM 核心对象及关系、时间线和客户 360° 视图。
3. 支持企业级组织、角色、记录共享、字段权限和审计。
4. 支持元数据驱动的自定义模块、字段、布局、视图和关联关系。
5. 支持可视化工作流、审批、Blueprint 状态转换和 Cadences 跟进序列。
6. 支持多语言、多时区、多币种、税率和汇率快照。
7. 提供开放 REST API、Webhook、导入导出和集成连接器。
8. 支持容器化部署、备份恢复、升级和可观测性。

### 2.2 非目标（首期不承诺）
- 不在第一阶段实现 Zoho 全部功能。
- 不复制 Zoho 产品 UI、文案、图标、品牌资产或内部实现。
- 不自研完整邮件服务、电子签名、支付网关；通过标准连接器集成。
- 不以微服务作为初始架构；先采用模块化单体。
- 不在没有法律/合规评估前宣称满足特定国家的全部监管认证。

## 4. 信息架构与模块清单

### 4.1 平台与组织基础
- 登录、退出、密码重置、会话管理、MFA（分阶段）
- 租户、组织、法人实体、部门、团队、用户、角色、权限
- 时区、语言、日期/数字格式、工作时间、财年和假期
- 登录策略、IP 策略、会话策略、审计日志

### 4.2 销售自动化
- Leads：线索、来源、评分、分配、去重、转化
- Accounts：企业/机构客户、层级客户关系、客户等级
- Contacts：联系人、职务、决策角色、联系方式
- Deals：商机、销售阶段、概率、预计关闭日、竞争对手、输单原因
- Products、Price Books、Quotes：产品、价目表、报价和折扣
- Sales Orders、Invoices、Payments：订单、发票、收款/回款
- Forecasts、Territories、Team Selling、Deal Splits：预测、区域、团队销售和业绩分摊

### 4.3 活动与协作
- Tasks、Calls、Meetings、Events、Reminders
- 与记录关联的统一时间线
- 团队日历、重复任务、逾期提醒
- 邮件记录、邮件模板、邮件线程关联；外部邮箱连接器
- 文件、附件、备注、标签、关注和订阅

### 4.4 营销
- Campaigns、Campaign Members、营销渠道
- 客户分群、受众、营销触点和转化归因
- Web-to-Lead 表单、自动回复、退订和同意记录
- 邮件发送由可插拔邮件提供商负责，记录发送状态和退信

### 4.5 客户服务
- Tickets、队列、分类、优先级、状态
- SLA 计时、升级、分派、内部备注
- 知识库、客户满意度和服务分析
- 客户门户（后续阶段）

### 4.6 配置与平台能力
- 自定义模块、字段、布局、子表单、关联字段
- 自定义视图、列表视图、详情页布局、表单布局
- 验证规则、字段依赖、布局规则、重复规则
- Workflow Rules、Scheduled Actions、Blueprint、Approval、Cadences
- 自定义函数/扩展点（受沙箱与权限约束）
- 报表、仪表盘、计划报告、导出
- REST API、Webhook、OAuth 2.0、API Key 管理、连接器
- Sandbox/配置发布与回滚（后续阶段）

## 5. 核心业务流程与规则

### 5.1 线索到客户
1. 线索可由人工创建、CSV 导入、Web 表单或 API 创建。
2. 线索按规则分配给用户/队列；所有分配记录留痕。
3. 去重规则可配置，默认以标准化邮箱、电话和企业名称组合判断。
4. 转化时在一个事务中创建或匹配 Account、Contact，并可创建 Deal。
5. 转化前后保留来源、原始字段、负责人和审计轨迹；不允许静默丢失字段。

### 5.2 商机生命周期
- 阶段由租户配置，默认：资格确认、需求分析、方案/报价、谈判、赢单、输单。
- 每阶段有概率、进入/退出条件和必填字段。
- 预计金额、币种、预计关闭日期必须可审计。
- 赢单/输单需记录结果；输单原因可配置。
- 商机变更记录进入时间线，支持阶段停留时长分析。

### 5.3 报价与订单
- 报价行项目记录产品、数量、单价、折扣、税率、币种和金额。
- 报价审批按折扣、金额、毛利阈值触发。
- 报价被接受后可转订单；转换必须防止重复执行。
- 已确认单据采用版本/状态管理，不能因产品价格变化而重算历史单据。

### 5.4 自动化
- 事件触发、定时触发、条件触发三类。
- 动作包括字段更新、创建记录、创建任务、分配、通知、Webhook、审批。
- 每次执行记录触发源、输入快照、结果、错误、重试次数和关联记录。
- 执行需幂等、可重试、有死信/失败队列和管理员重放机制。
- 禁止任意执行未审查的用户脚本；自定义函数需受限运行环境。

### 5.5 多币种与国际化
- 每个租户设置基础币种；记录可使用交易币种。
- 金额使用 Decimal/Numeric，不使用浮点数。
- 保存交易币种金额、基础币种金额、汇率、汇率日期和汇率来源快照。
- 支持汇率有效期、人工汇率和外部汇率导入；不自动篡改历史单据。
- 每个用户有语言、时区和区域格式偏好；业务记录保存 UTC 时间并按用户时区展示。
- UI 文案使用 i18n key；用户可见的自定义字段/选项支持翻译值。
- 默认中文，英文作为第二语言；数据库字符集和排序规则需支持 Unicode。

## 7. 非功能需求（NFR）

- 安全：OWASP ASVS 风格的安全控制；密码使用 Argon2id；敏感字段加密；TLS；CSRF/XSS/SQL 注入防护。
- 授权：服务端每次请求执行租户和对象级授权；前端隐藏按钮不构成安全控制。
- 隔离：租户 ID 必须来自已验证会话上下文，不信任客户端提交值；数据库约束和 PostgreSQL RLS 作为纵深防御。
- 可用性：目标由部署环境决定；首版提供健康检查、备份和恢复手册，不承诺未经验证的 SLA。
- 性能基线（首轮压测目标）：常见列表查询 P95 < 500ms（测试数据规模、硬件和过滤条件需记录）；后台任务不阻塞 API。
- 可扩展性：模块化边界、事件接口、连接器接口和版本化 API。
- 可维护性：严格 TypeScript、Lint、格式化、迁移脚本、自动化测试和 ADR。
- 可观测性：结构化日志、请求 ID、指标、错误追踪、队列深度、审计日志。
- 备份：PostgreSQL 定期备份 + 对象存储备份；必须定期执行恢复演练。
- 隐私：数据导出、删除/匿名化、保留策略、同意/退订记录按适用法律配置。

## 8. 核心验收标准

1. 用户无法通过修改 URL、请求体或 IDOR 访问未授权租户的数据。
2. 所有核心模块 CRUD 均在服务端执行数据权限检查。
3. 线索转化事务可重复请求而不会重复创建客户/联系人/商机。
4. 货币金额精确计算，汇率快照可追溯。
5. 用户语言和时区切换不改变数据库原始值。
6. 工作流失败可查看、重试，重复事件不会重复产生业务动作。
7. 导入提供预览、字段映射、错误报告和失败行下载。
8. 审计日志不可由普通用户修改或删除。
9. 备份能在干净环境恢复，并通过校验。
10. 每个 P0 功能具备单元、集成和端到端测试。

## 9. 版本路线

- Foundation 0.1：项目骨架、认证、租户、组织、RBAC、审计、容器部署。
- CRM MVP 0.2：线索、客户、联系人、商机、活动、基础搜索和导入导出。
- Sales 0.3：产品、报价、合同、订单、回款。
- Enterprise 0.4：工作流、审批、Blueprint、评分和自定义模块。
- Platform 0.5：报表、仪表盘、API/Webhook、集成。
- Advanced 1.0：营销、客服、Cadences、门户、AI、Sandbox。

## 10. 风险与决策

- “完全实现 Zoho”是长期能力目标，不是一次性交付承诺；必须建立逐功能对标矩阵。
- 自定义模块、权限、工作流是平台级复杂能力，必须先设计元数据和安全模型。
- 邮件、WhatsApp、短信、电子签名等服务涉及第三方账户、地区限制和费用。
- 国际市场涉及隐私、数据驻留、税务和电子通信法规，需按目标国家单独评估。
- 私有化部署仍需明确支持矩阵：Linux 发行版、CPU 架构、Docker 版本、外部 SMTP、对象存储和反向代理。
