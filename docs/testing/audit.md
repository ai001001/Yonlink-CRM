## 功能说明
| 项 | 实现 |
|---|---|
| 记录范围 | 线索/客户/联系人/商机/跟进的新建、修改、删除；线索转化（含转化时创建的客户/联系人/商机，标注 `via: lead.convert`）；登录成功、登录失败（仅已存在账号，原因 bad_password / inactive）、退出登录 |
| 内容 | 操作人、对象类型与 ID、操作、时间、IP（X-Forwarded-For 首个地址）、User-Agent；新建记 `after` 快照，删除记 `before` 快照，修改只记变化字段 `fields: {字段: [旧, 新]}`；无变化的修改不记录 |
| 一致性 | 与业务写入在同一事务：业务失败则无日志，日志写入失败则业务回滚 |
| 只追加 | 触发器 `audit_logs_append_only` 拒绝一切 UPDATE/DELETE；API 只有 GET |
| 脱敏 | 邮箱/电话打码（`z***@example.com`、`138******34`）；备注、跟进内容、地址只记 `[redacted]`；密码、密码哈希、会话令牌从不记录（字段白名单） |
| 时间 | `clock_timestamp()`，同一事务内多条记录按真实写入顺序排序 |
| 查询 | `GET /api/audit-logs`：按对象类型、对象 ID、操作、操作人、时间范围筛选，分页；严格校验，未知参数 400 |
| 界面 | 左侧导航“审计日志”页；线索/客户/商机详情中的“操作记录” |

覆盖：校验失败/409/404 不产生日志；并发转化只记录胜出方；审计写入失败时业务回滚；ORM 与原生 SQL 的 UPDATE/DELETE 均被拒绝且数据不变；API 无写方法；删除业务记录后日志仍可查；打码规则；11 类敏感原文（邮箱、电话、备注、地址、密码、哈希、令牌）在全部日志中均不出现；不存在邮箱的失败登录不记录；组织隔离（列表、按他组织对象 ID/操作人查询均为空）；未登录 401；10 种非法查询 400；复合外键阻止跨组织操作人。

### 失败与修复
| 现象 | 原因 | 修复 |
|---|---|---|
| 查询带未知参数 `q=x` 返回 200 | 查询参数校验默认忽略未知字段；拼错的筛选条件（如把 `actorId` 写成 `actor`）会被静默忽略，返回全部日志，审计场景下有误导性 | 审计查询改为严格模式，未知参数返回 400；新增 `actor=` 用例 |

### 开发中主动修正（非测试失败）
| 问题 | 处理 |
|---|---|
| 同一事务内的多条审计记录 `created_at` 相同（`now()` 取事务开始时间），排序依赖插入顺序，不可靠 | 新迁移改为 `clock_timestamp()`，并在 R1 中断言转化产生的 4 条记录时间各不相同且递增 |

## 剩余风险
- 尚无角色体系，同组织所有用户都能查看本组织审计日志；引入角色后应限制为管理员。
- 不存在的邮箱登录失败无法归属组织，因此不记录（暴力尝试仍受登录限流约束）。
- 设置主要联系人时被自动取消“主要”的其他联系人不单独记录日志。
- 未实现日志保留期限与归档；数据库所有者账号理论上可禁用触发器（生产环境应使用非属主运行角色，见 ADR-005）。
