## 功能
- **仓库**（产品页“仓库”按钮；维护需 `product.manage`：管理员、经理，所有用户可查看）：
  - 代码（自动转大写，同组织唯一）、名称、地址、启停；显示有库存的产品数与库存件数。
  - 每组织一个默认仓库；把其他仓库设为默认时自动取消原默认；组织的第一个仓库自动为默认；组织还没有仓库时，第一次产生库存流水会自动建立默认仓库（代码 MAIN）。
  - 默认仓库不能停用、取消默认或删除；有库存流水的仓库不能删除（可以停用）；停用的仓库不能再收货、发货、调整或调入调出。写审计。
- **库存按仓库**：
  - 产品总库存为各仓库之和；低库存提醒、库存筛选、缺货提示仍按总库存。
  - 手工调整可选仓库（不选为默认仓库）；盘点按所选仓库的数量计算差额。
  - 仓库间调拨：调出、调入两条成对流水（共用调拨 ID），总库存不变；调出与调入须为不同的启用仓库；允许调出后为负（与原有库存规则一致）。
  - 采购收货可选收货仓库，销售订单发货可选发货仓库（多个启用仓库时显示，不选为默认仓库）；已发货订单取消时退回原发货仓库（即使该仓库已停用）。
- **库存详情**：各仓库库存表（默认仓库在前；停用且为 0 的仓库不显示）、调拨表单、流水的仓库与仓库余额列、按仓库筛选流水。
- **审计**：仓库的新建、修改、删除；调整记录仓库与该仓库前后库存；调拨记录两端仓库与数量；收货、发货、退回的库存变动带仓库代码。
- **演示数据**：【演示】上海总仓（默认）、华南仓、华北仓；期初库存与历史流水在总仓；5 个产品在 20 天前调拨到区域仓（按时间顺序写入，余额连续）。
- **不做**：按仓库设置再订货水平、库位/货架、批次与序列号、调拨单审批与在途库存、按仓库的库存报表。

### 失败与修复
| 现象 | 原因 | 修复 |
|---|---|---|
| R1 首次：收货与发货用例准备数据时数据库约束报错（采购单状态约束、明细序号必填） | 测试问题：直接写入“已下单”的采购单时没有下单时间，明细缺少序号 | 准备数据时补上下单时间与序号，断言不变 |
| 原有演示数据测试：按时间的余额不连续 | 产品问题（演示数据）：演示调拨发生在 20 天前，但写在全部历史流水之后，按时间排序时余额不连续 | 调拨并入事件列表，与其他流水一起按时间顺序写入 |
| E2E 首次：多仓库用例超时 | 测试问题：调拨备注输入框的名称是“调拨 调整原因”，测试写成了“调拨 备注” | 改正名称 |
| E2E 首次：原有库存用例取到的第一行不是流水 | 界面变化：库存详情上方新增了各仓库库存表 | 流水表加测试标识，用例改为在流水表内定位，断言不变 |
| E2E 首次：原有“产品目录与商机明细”用例超时（33 秒） | 长流程用例耗时接近并超过 30 秒默认时限（上次约 29.5 秒） | 与其他长流程用例一样单独设置 60 秒时限，断言不变 |

### 测试调整说明（行为变化）
- 库存流水必须指定仓库：原有库存第二轮测试中直接写入流水的地方补上仓库（A 用首次调整自动建立的默认仓库，B 新建一个仓库），断言不变。
- 手工调整的返回值增加“该仓库余额”，审计增加仓库代码与该仓库前后库存；销售订单取消的审计中库存变动增加仓库代码。相应用例的预期加上这些字段。
