# 按区域扩大记录可见范围（#60 延伸之四）— 三轮测试记录

日期：2026-11-24　环境：同 [leads.md](leads.md)　参考：Zoho CRM Territory Management（区域成员可访问区域内的记录）

迁移：无（使用 #55 已有的区域、区域成员与客户区域字段）。

## 功能
- **谁受影响**：没有“查看全部记录”权限的用户（销售代表）。管理员、经理、只读用户本来就能看全部，不变。
- **可读范围**：自己负责的记录，加上自己担任区域经理或成员的区域（含全部下级区域）中的：
  - 客户（列表、详情、得分明细、客户的联系人列表）；
  - 这些客户下的联系人（联系人列表、详情、得分明细）；
  - 这些客户下的商机（列表、看板、详情、产品明细、价格预览、联系人角色、竞争对手、阶段历史、得分明细）；
  - 上述客户、商机的备注与附件（列表与下载）。
- **只读**：编辑、删除、批量操作、加标签、新增联系人/产品明细/联系人角色/竞争对手/备注、上传附件，仍只限负责人（或有“编辑全部”权限的角色）。被拒绝时返回 403（与读取共用查找的路径）或 404（写入专用查找只按负责人的路径），不会写入数据或审计。不能把新商机挂到只读客户上。
- **即时生效**：每个请求从数据库读取区域与成员，不缓存。移出成员、区域改挂上级、客户地址变化后被规则移出区域，下一次请求即生效。
- **商机数**：客户列表与详情中的“商机数”按可读范围计数（与客户详情的商机页签一致）。
- **界面**：沿用已有的“负责人才显示编辑按钮”规则，区域内他人负责的记录只显示查看。
- **不做（保持按负责人）**：线索（不属于客户）；跟进记录（跟进有自己的负责人）；报价单、销售订单、发票、回款等财务单据；报表、仪表盘、预测的统计；导出（只有管理员和经理有导出权限，已能看全部）；标签使用次数统计。
- **演示数据**：沿用已有区域——王芳是“【演示】海外”成员（可只读查看陈静负责的海外客户与商机），陈静是“【演示】国内”成员（可只读查看郑经理负责的国内客户与商机）。

## 第一轮：功能测试
命令：`npx vitest run tests/territory-visibility/territory-visibility.r1-functional.test.ts`
结果：**5/5 通过**（首次运行有测试问题，见下方“失败与修复”）。原始输出：[results/territory-visibility-r1-functional.txt](results/territory-visibility-r1-functional.txt)

覆盖：
- **列表**：区域成员看到下级区域的客户、联系人、商机与看板；区域经理同样适用；区域筛选、负责人筛选与可见范围取交集；商机数按可读范围计数；负责人与管理员不变。
- **详情与明细**：客户、联系人、商机详情；产品明细、联系人角色、竞争对手、阶段历史、得分；负责人写的备注可见；负责人上传的附件可列出、可下载；其他区域的客户与附件 404。
- **只读**：改客户、删客户、新增联系人、改/删联系人、改商机、加竞争对手、加联系人角色、加备注、上传附件均被拒绝；不能给只读客户新建商机；数据库中记录未变。
- **即时生效**：区域改挂到另一上级后原成员立即看不到、新上级的经理立即可见；改回后恢复；移出成员后详情 404。
- **保持按负责人**：不在任何区域的新用户看不到；自己新建的客户正常；区域内商机的报价单、跟进对代表不可见。

覆盖：
- **规则分配**：按地址规则自动进入区域后可见；负责人改地址被规则移出后立即不可见；改规则并重新分配后恢复。
- **组织隔离**：B 组织不能引用 A 的区域；B 的区域成员看不到 A 的客户（详情 404），A 的成员也看不到 B 的。

- **回收站、密钥、角色**：删除的商机不可见；以代表身份的 API 密钥同样只读可见；经理、只读角色不变；停用代表后会话立即失效。

### 失败与修复
| 现象 | 原因 | 修复 |
|---|---|---|
| R1 首次：看板用例报错 | 测试问题：看板每列的卡片字段是 `items`，测试写成了 `cards` | 改为 `items` |
| R1 首次：改联系人返回 404 而非 403 | 测试预期不准确：改联系人、改商机、设置标签的写入路径只按负责人查找记录，所以是 404；两者都是拒绝，数据未变 | 这几项断言改为“403 或 404”，并补充检查数据库记录未变 |
| R2 首次：API 密钥用例 400 | 测试问题：创建密钥需要指定 `userId`，原测试缺少该字段；且原测试对成功、失败两种结果都放行，可能静默跳过 | 改为管理员为代表创建密钥，断言必须成功，并验证密钥也不能编辑 |
| R2 首次：设置标签返回 404 | 同上（写入路径按负责人查找） | 断言改为“403 或 404” |
| 自查：客户列表“商机数”仍只数自己负责的商机，与商机页签不一致 | 产品问题：计数条件仍按负责人 | 计数改为按可读范围（R1 增加断言） |

- `e2e/contacts.spec.ts`：销售代表的联系人用例改为“自己负责客户及所在区域客户的联系人”（见第三轮）。
