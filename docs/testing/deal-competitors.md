# 商机竞争对手与联系人角色 — 三轮测试记录

日期：2026-11-15　环境：同 [leads.md](leads.md)　参考：Zoho CRM Contact Roles、Competitors
迁移：`20261115150000_deal_competitors_contact_roles`（新表 `deal_contact_roles`、`deal_competitors`，枚举 `deal_contact_role_type`、`competitor_threat`；`contacts` 新增组织内复合唯一键供外键引用；角色表对商机、联系人为组织内复合外键并随之级联删除；手工约束：每个商机最多一个主要联系人（部分唯一索引）、竞争对手名称在同一商机内不区分大小写唯一、名称不能为空白）

## 功能
- 商机详情新增“联系人角色”页签：从商机所属客户的联系人中选择，角色为决策人、评估人、影响者、技术采购、采购、最终用户、其他；可勾选“主要联系人”（每个商机一个，新设的会取消旧的）；可直接在表格中改角色、设为主要、移除（只移除角色，联系人保留）。客户还没有联系人时提示并给出打开客户的链接。
- 商机详情新增“竞争对手”页签：名称、威胁程度（高、中、低）、优势、劣势；按威胁程度从高到低排列；同一商机内名称不区分大小写不能重复（表单内提示）。
- 规则：
  - 只能选择商机所属客户的联系人；添加时在事务中锁定商机行，与“修改商机客户”串行。
  - 商机换客户时，不属于新客户的联系人角色在同一事务中移除，并逐条记审计（经由“商机 · 修改”）。
  - 删除联系人时其角色随之删除。
- 权限：查看需能看到该商机；新增、修改、删除需能编辑该商机（销售只能改自己的商机，只读用户只能查看）。
- 审计（记在商机上）：添加、修改、移除联系人角色；新增、修改、删除竞争对手；优势、劣势只记“已修改”，不记原文。审计日志页可按这些操作筛选，操作记录中显示联系人或竞争对手名称、角色、威胁程度。
- 回收站：删除商机时快照联系人角色与竞争对手（摘要显示数量）；恢复时竞争对手全部恢复，联系人角色只恢复联系人仍存在且仍属于该客户的，其余提示“部分未恢复：部分联系人角色（联系人已删除）”。
- 报表：销售报表新增“竞争对手胜负”表（名称不区分大小写合并，显示最早录入的写法；在手商机不限时间，赢单、输单按预计成交日期落在所选时间段内；含期间输单金额与赢单率；按所选币种、负责人与可见范围统计；最多 20 行）；销售报表 CSV 导出同步增加该段。
- 演示数据：4 家虚构竞争对手（名称带“【演示】”），每 3 个商机中有 2 个带竞争对手（48 条）；每个演示商机为客户的前 1–3 位联系人设置决策人（主要联系人）、评估人、技术采购（101 条）。
- 不做：竞争对手独立模块与竞品库、输单时指定“输给谁”、联系人角色的自定义角色值、跨客户的联系人（如渠道伙伴）。

| 现象 | 原因 | 修复 |
|---|---|---|
| R1 首次 1 项失败（[首次输出](results/deal-competitors-r1-functional-first-run-failed.txt)）：合并后显示 `acme`，测试期望 `ACME` | 报表原用 `min(name)` 取显示名称，结果取决于数据库排序规则，不同环境可能不同；测试的期望值也是基于这一不确定行为写的 | 改为显示最早录入的写法（`array_agg(name ORDER BY created_at, id)[1]`），结果确定；测试期望改为最早录入的 `Acme` |
