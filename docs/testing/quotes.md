# 报价单（产品与报价 第 2 步）— 三轮测试记录

日期：2026-11-12　环境：同 [leads.md](leads.md)　参考：Zoho CRM Quotes
迁移：`20261112115853_quotes`（quotes、quote_line_items 表与 quote_status 枚举；组织内报价单号唯一；复合外键保证报价单与商机、明细与报价单、创建人同组织；税率 0–100、金额非负、总计 = 小计 + 税额、明细序号/数量/单价/折扣/小计的 CHECK；随商机级联删除）

## 功能
- 商机详情新增“报价单”页签：列出该商机的报价单，“生成报价单”复制商机当前产品明细为快照（主题默认商机名称，可填有效期、税率、条款）；商机没有明细时不能生成。
- 报价单号按组织、按年连续编号（`QT-2026-0001`），事务级咨询锁保证并发不重号。
- 小计 = 明细合计；税额 = 小计 × 税率%（十进制四舍五入到分）；总计 = 小计 + 税额（数据库 CHECK 兜底）。
- 明细为纯快照（不引用产品）：之后修改商机明细、产品名称/单位/价格都不影响已生成的报价单；草稿可“从商机同步明细”。
- 状态：草稿 → 已发送 → 已接受 / 已拒绝；已发送可退回草稿；已接受、已拒绝为终态。只有草稿可修改、同步、删除。已发送且过了有效期显示“已过有效期”。
- 新增“报价单”列表页（状态筛选，按报价单号、主题、商机、客户搜索）与报价单详情抽屉（状态操作、编辑、同步、删除、打印）。
- 打印页 `/print/quote?id=…`：无导航外壳，显示组织名称、客户、电话、地址、明细、合计与条款，不显示内部备注；打印时隐藏工具栏（浏览器可另存为 PDF）。
- 权限与可见范围跟随所属商机：销售代表只能看到和操作自己负责商机的报价单，只读用户只看，经理/管理员全部。
- 审计：quote.create / update / sync_items / status / delete；条款与内部备注脱敏。审计日志页筛选新增“产品”“报价单”及商机明细动作（第 1 步遗漏，本次补上），审计详情按对象显示报价单状态与字段名称。
- 演示数据：21 张报价单（4 草稿、7 已发送其中 2 张已过有效期、7 已接受、3 已拒绝），人民币报价含 13% 增值税，美元出口报价不含税；报价单号按创建时间递增。

### 失败与修复
| 现象 | 原因 | 修复 |
|---|---|---|
| R1：同一组织第二次生成报价单返回 409（重复值） | **真实缺陷**：取最大编号的 SQL 中 `substring(quote_number FROM $n)` 的参数未定型，被 PostgreSQL 解析为 text，`substring(text FROM text)` 是正则版本，返回 NULL，导致每次都生成 0001 | 参数显式转为 `::int` 并加注释；R1 编号测试与 R2 并发编号测试覆盖 |
| 开发阶段单独运行 E2E：取报价单号失败 | 测试脚本问题：抽屉标题不是 heading 角色 | 改为读取抽屉标题元素 |
| R3 首次：审计日志 E2E 在对象类型下拉中找不到“线索”（[首次失败输出](results/quotes-r3-regression-first-run-failed.txt)） | 本次把下拉选项从 8 个增加到 10 个，超出虚拟列表一屏；选中最后一项“登录”后再展开，列表滚动到底部，顶部“线索”不在页面中 | 选项少且固定，关闭该下拉的虚拟滚动并加大列表高度，所有选项始终可见；单独重跑审计 E2E 通过后完整重跑 R3 |
