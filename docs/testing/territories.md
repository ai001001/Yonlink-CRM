## 功能
- **区域**（设置 › 区域管理，`territory.manage`：管理员、经理）：
  - 树形，最多 3 级，每组织最多 100 个（加锁判断）。
  - 可设负责人与成员（组织内的启用用户），修改时成员整体替换。
  - 上级不能是自己或自己的下级。
  - 删除：有下级时拒绝；其中的客户变为无区域并恢复自动分配。
  - 所有用户可读取区域列表，用于筛选与显示。写审计。
- **分配规则**：
  - 按客户的名称、行业、地址、电话、网站、负责人设置最多 10 个条件，全部满足或任一满足。
  - 优先级数字小的先匹配，同优先级按名称；没有条件的区域不自动分配。
  - 客户新建、编辑时按规则自动分配；导入客户、线索转化新建的客户同样按规则分配。
  - “重新分配”按规则重算全部非手工指定的客户，分批处理，只更新有变化的客户，结果写审计。
- **手工指定**：
  - 有 `territory.manage` 的用户可在客户表单中选择“自动（按规则）”“无区域”或某个区域。
  - 手工指定（包括“无区域”）后，编辑与重新分配都不覆盖；选“自动”恢复按规则分配。
  - 销售不能指定区域（403），新建的客户照常自动分配。
- **列表与详情**：
  - 客户列表新增“区域”列与区域筛选：某区域（含下级）、我的区域（我负责或参与的区域及其下级）、无区域。
  - 商机列表可按客户所在区域筛选。
  - 客户详情显示区域，手工指定时有“手工指定”标记。
  - 客户导出（CSV、Excel）末尾追加“区域”列（在自定义字段列之前），并支持区域筛选。
- **统计**（区域管理页）：
  - 每个区域显示客户数、进行中商机与赢单的数量和金额，含下级区域；另有“无区域”汇总。
  - 金额按今天的汇率折合本币，缺少汇率的币种会提示。
  - 只统计当前用户能看到的客户与商机（销售只统计自己负责的）。
- **审计**：
  - 区域的新建、修改（列出变化的项）、删除（清除的客户数）、重新分配（检查与变更的客户数）。
  - 客户审计记录区域与手工指定的变化。
- **回收站**：恢复客户时保留区域；区域已删除时置空并恢复自动分配。
- **演示数据**：
  - 区域：【演示】国内（下级“华东”）、【演示】海外（下级“北美”“欧洲”），规则按地址前缀或城市匹配，设有负责人与成员。
  - 分配结果：华东 4、国内 5、北美 5、欧洲 5、海外 11、无区域 2。
- **不做**：
  - 按区域扩大记录可见范围：销售仍只能看到自己负责的记录。若要做，需要改动全部按负责人判断可见性的查询，列入 #60 延伸。
  - 一个客户属于多个区域、联系人与商机单独指定区域、区域配额与目标、区域变化通知。

### 失败与修复
| 现象 | 原因 | 修复 |
|---|---|---|
| R1 首次：商机按区域筛选返回 500（`Invalid element at key "territoryId"`） | 产品缺陷：商机模块引用区域模块，区域模块经工作流又引用商机模块，形成循环引用，商机列表的查询校验在区域筛选定义完成前就已构建 | 区域输入校验移到只依赖 zod 的 `territory-input.ts` |
| R1 首次：导入的两个客户区域顺序与预期相反 | 测试问题：按名称排序依赖数据库排序规则，“导入甲/导入乙”的顺序不确定 | 改为按名称对应检查，断言内容不变 |
| R2 首次连同相关测试运行：视图、预测、报表、回收站等 5 个测试文件加载失败（`exchange-rates.ts` 读取 `dateOnly` 时为 undefined） | 产品缺陷：另一条循环引用，商机 → 区域 → 汇率 → 商机 | 规则匹配与筛选拆到 `territory-rules.ts`（不依赖客户、商机、汇率模块），区域维护与统计留在 `territories.ts`；拆分后重跑第一轮与第二轮 |
| R2 首次：多语言守卫测试失败 | 产品缺陷：区域下拉的缩进使用了全角空格，属于界面源码中的全角字符 | 改为 ` ` 转义 |
| R3 首次：商机端到端用例超时（30 秒） | 产品问题：客户、商机列表为显示区域筛选而请求完整区域列表，每次都计算统计，拖慢页面；该用例原本已接近时限 | 新增 `view=options` 只返回选项，筛选与下拉改用选项，统计只在区域管理页计算 |
| R3 首次：商机评分 2000 条规模用例未返回重算数 | 产品缺陷（原有功能）：保存评分规则在同一事务内重算全部记录，使用默认 5 秒事务时限；全量回归并行负载下用时 5.3 秒，事务过期 | 该事务时限放宽到 60 秒；单独运行与全量回归均通过 |
| E2E 首次：区域管理页看不到下级区域“【演示】华东” | 产品缺陷：表格的“默认全部展开”只在首次渲染生效，数据异步加载后下级区域保持折叠 | 改为受控展开：有下级的区域默认展开，记住用户手动收起的行 |

说明：R3 首次失败的原始输出见 [results/territories-r3-first-run-failed.txt](results/territories-r3-first-run-failed.txt)；其余首次失败的运行输出没有单独保存为文件，上表按当时终端输出记录。修复后的结果文件为最终运行结果。
