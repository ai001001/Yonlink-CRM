## 功能
- **蓝图**（设置 › 流程蓝图，`blueprint.manage`：管理员、经理）：为线索状态或商机阶段定义可走的转换。
  - 转换：名称、出发状态（1–10 个）、目标状态、可执行的角色（管理员、经理、销售）、执行时必须填写的字段（线索：公司、职位、电话、邮箱、备注；商机：金额、预计成交日期、备注）、是否必须填写说明。
  - 同一蓝图内转换名称不重复；出发状态不能包含目标状态；同一出发→目标只能有一个转换。线索不能转换到“已转化”（由线索转化完成）。
  - 每个对象同时只能启用一个蓝图（加锁检查，并有数据库唯一索引）；每组织最多 20 个；对象创建后不可改；修改时已有转换的 ID 保留。写审计。
- **强制**（蓝图启用时）：
  - 编辑表单、批量改状态/阶段、看板拖动、宏、工作流、查重合并都不能直接修改受控字段（`BLUEPRINT_CONTROLLED`）；工作流的修改动作记为跳过。
  - 新建记录可以是任意状态；线索转化照常把状态改为已转化；停用或删除蓝图后恢复自由修改。
  - 编辑表单中受控字段变为只读，并提示由哪个蓝图控制。
- **执行转换**（线索、商机详情顶部的“流程”面板）：
  - 显示当前状态和当前用户此刻可执行的转换（当前状态是出发状态、角色允许、记录可编辑；已转化线索没有转换）。
  - 弹窗按转换要求填写字段（预填记录已有的值）与说明；必填字段取提交值或已有值，都为空时拒绝，金额须大于 0；只能提交转换要求的字段，按普通修改的规则校验。
  - 修改沿用线索、商机的修改服务：验证规则、工作流、阶段历史、通知照常；同一事务内锁定记录并确认状态未被并发修改（否则 409，提示刷新）。
  - 说明写入记录的备注；审计记录蓝图、转换、从哪个状态到哪个状态。
- **演示数据**：“【演示】商机推进流程”（默认停用，管理员可一键启用）：开始需求分析（须填预计成交日期）→ 提交方案（须填金额）→ 进入谈判（须填说明）→ 确认赢单（经理或管理员，须填说明）；任一进行中阶段可标记输单（须填说明）；输单可由经理或管理员重新打开。
  - 默认停用的原因：现有的批量、宏、商机流程等用例与演示操作需要自由修改阶段；启用后这些操作会按设计被拦截。
- **不做**：蓝图的适用条件（只对部分记录生效）、转换后的自动动作（可用“字段变化”工作流实现）、转换的时限与超时提醒、客户等其他对象的蓝图、流程图形编辑器。

## 第一轮：功能测试
命令：`npx vitest run tests/blueprints/blueprints.r1-functional.test.ts`
结果：**5/5 通过**（首次运行 3/5，见下方“失败与修复”）。原始输出：[results/blueprints-r1-functional.txt](results/blueprints-r1-functional.txt)

覆盖：
- **维护**：
  - 新建（转换 ID 自动生成）；16 类非法输入：空名称、无转换、21 个转换、未知目标、商机用线索状态、出发包含目标、空出发、转换重名、重复路径、商机用线索字段、只读角色、空角色、重复角色、客户对象、线索用金额字段、线索转到已转化；同名 409。
  - 每个对象只能启用一个（新建与修改都 409），线索可另启用；销售不能维护、不能看列表但可读取状态。
  - 修改：对象不可改；改转换须提交对象；已有转换 ID 保留、新转换生成新 ID；停用后另一个可启用；删除后状态为空；其他组织 404；审计序列；上限 20。
- **强制**：
  - 新建可任意阶段；编辑改阶段 409 `BLUEPRINT_CONTROLLED`，提交相同阶段并改名可以；批量改阶段、宏改阶段逐条失败；工作流改阶段被跳过并记录原因；停用后编辑可改阶段。
  - 线索蓝图：编辑改状态被拒；查重合并选重复记录的状态被拒，不选则正常合并；线索转化照常；已转化后没有可执行转换。
- **执行转换**：
  - 可用转换按当前状态与角色过滤；只读用户没有；他人记录 404。
  - 必填字段为空、提交非转换字段、非法日期均 400；成功后阶段、预计成交日期与阶段历史正确；再次执行同一转换 409。
  - 金额为空或 0 视为未填；字段变化工作流照常通知；角色不允许 403；说明必填；验证规则照常拦截；说明去空格后写入备注；审计三条转换记录。
  - 未知转换 400；没有启用的蓝图 409；可用转换返回空。
  - 线索转换：已有公司时可不提交，缺邮箱 400，非法邮箱 400，成功后状态与字段正确。

覆盖：

### 失败与修复
| 现象 | 原因 | 修复 |
|---|---|---|
| R1 首次：带“预计成交日期”的转换返回 400（`expected string, received Date`） | 产品缺陷：转换字段已按修改规则解析（日期转为 Date），之后又交给修改的校验再次解析，日期被拒 | 解析后的值直接传给修改服务，不再重复解析 |
| R1 首次：蓝图审计条数与预期不符 | 测试问题：预期写了 4 条修改审计，实际成功的修改只有 3 次（被拒的修改不写审计） | 改为 3 条，与实际操作一致 |
