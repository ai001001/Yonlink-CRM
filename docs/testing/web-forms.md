# 网页表单收集线索 — 三轮测试记录

日期：2026-11-18　环境：同 [leads.md](leads.md)　参考：Zoho CRM Webforms（Web-to-Lead）
迁移：`20261118090000_web_forms`
- 新表：`web_forms`。
- 新列：`leads.web_form_id`（来源网页表单，表单删除时置空）。
- 新通知类型：`WEB_FORM_LEAD`。
- 手工约束：
  - 表单名称在组织内唯一，不区分大小写，且不能为空白；标题不能为空白。
  - 公开标识至少 32 个字符。
  - 字段只能取固定集合，必填字段必须在已启用字段中；提交次数非负。
  - 触发器：线索的来源表单必须属于同一组织（外键只引用 id）。

## 功能
- **权限**：
  - 所有用户可以查看表单。
  - 新建、修改、删除、重新生成地址需要 `campaign.manage`（管理员、经理），属于营销设置。
- **导航**：“营销”组：市场活动、**网页表单**。
- **表单设置**：
  - 名称（内部用）、标题、说明、启用状态。
  - 收集字段：姓名始终显示且必填；公司、职位、邮箱、电话、手机、留言可以启用，并可设为必填。
  - 生成线索的来源、负责人（可不分配）、市场活动、提交成功提示。
- **公开表单页** `/web-form?key=…`：
  - 无需登录，支持中英文切换。
  - 在详情中复制链接分享，或复制 iframe 代码嵌入官网。地址沿用当前站点的路径前缀和末尾斜杠（GitHub Pages 为 `/Yonlink-CRM/web-form/?key=…`），不依赖跳转。
  - 提交走本站同源前端调用后端，不需要放宽跨域设置。
  - 公开配置接口只返回标题、说明、字段、成功提示，不含组织、负责人等内部信息。
  - 停用、地址错误、格式错误一律返回 404，不区分原因。
- **提交生成线索**：
  - 线索使用表单的来源、负责人、市场活动，状态为新线索，并记录来源表单；只保存已启用的字段。
  - 负责人已停用时不分配。
  - 有负责人时发送“网页表单收到新线索”通知。
  - 审计：操作人为空，注明来源表单和来源 IP；邮箱、电话打码，留言只记“已修改”。
  - 更新表单的提交次数和最近提交时间。
- **防滥用**：
  - 隐藏的诱饵字段被填写时返回成功，但不保存。
  - 同一 IP 对同一表单 10 分钟内最多 5 次；每个表单每小时最多 200 次（进程内计数，多实例部署时每个实例分别计数）。
  - 请求体不超过 16 KB；未启用的字段、多余字段（如负责人、状态）一律拒绝；公开接口不读取登录令牌。
- **重新生成地址**：旧地址立即失效，用于地址泄露或收到垃圾提交时。
- **删除表单**：已生成的线索保留，来源表单置空。
- **线索详情**显示“来源网页表单”并可点击进入；回收站恢复线索时，如果来源表单已删除则置空并提示。
- **演示数据**：
  - 官网产品咨询：关联 3 条来源为网站的演示线索，提交次数与之一致。
  - 技术研讨会报名：关联研讨会活动。
  - 已停用的展会现场登记表。
- **不做**：验证码（CAPTCHA）、自定义字段、文件上传、自动回复邮件（第一阶段不做邮件集成）、按规则轮流分配、提交记录单独存档。

## 第一轮：功能测试
命令：`npx vitest run tests/web-forms/web-forms.r1-functional.test.ts`
结果：**7/7 通过（首次即通过）**。原始输出：[results/web-forms-r1-functional.txt](results/web-forms-r1-functional.txt)

覆盖：
- **维护**：
  - 新建的默认值，公开标识为 43 个字符。
  - 同名（含首尾空格、大小写不同）返回 409。
  - 字段按固定顺序保存并去重；必填字段未启用返回 400；6 类非法参数返回 400。
  - 其他组织的负责人、不存在的市场活动返回 400。
  - 修改的审计（说明只记“已修改”，字段数组前后对比）；去掉必填字段时校验；改名重复返回 409；列表筛选。
- **重新生成与删除**：旧地址的查看和提交都返回 404，新地址可以使用；审计；详情列出最近线索；删除后线索保留、来源置空，审计记录提交次数。
- **公开配置**：返回内容精确等于 4 项显示信息；未知、格式错误、过短的地址返回 404；停用后查看和提交都返回 404。
- **提交**：
  - 生成的线索的各字段、来源、负责人、市场活动、来源表单正确；邮箱转为小写；姓名去除首尾空格。
  - 提交次数和最近提交时间更新。
  - 通知（类型、线索、无操作人、标题）。
  - 审计无操作人，记录来源 IP 和表单名，邮箱打码，留言只记“已修改”。
  - 线索详情显示来源表单。
- **校验与防滥用**：
  - 必填缺失、字段未启用、邮箱格式、空白姓名，以及客户端提交负责人、状态时返回 400，不生成线索。
  - 诱饵字段返回成功但不保存，也不计数。
  - 负责人停用后线索不分配、不通知。
  - 同一 IP 第 6 次返回 429，换 IP 可以继续提交。
  - 请求体超过 16 KB 返回 413；非法 JSON 返回 400。
- **回收站**：恢复线索时，来源表单已删除则置空并提示。
- **演示数据**：名称、启用状态正确；提交次数等于关联线索数；必填字段都已启用；演示表单可以公开访问；可以重复重置。

## 第二轮：集成测试
命令：`npx vitest run tests/web-forms/web-forms.r2-integration.test.ts`
结果：**5/5 通过（首次即通过）**。原始输出：[results/web-forms-r2-integration.txt](results/web-forms-r2-integration.txt)

覆盖：
- 销售代表、只读用户可以查看，4 类维护操作都返回 403，数据不变；经理可以维护；未登录访问管理接口返回 401。
- 表单详情的最近线索按可见范围过滤（销售只看到分配给自己的）；销售的线索列表能看到表单线索；通知中心收到 `WEB_FORM_LEAD`。
- 跨组织隔离：
  - 查看、修改、重新生成、删除都返回 404；不能引用其他组织的负责人；名称只在组织内唯一。
  - 带着其他组织的令牌提交，线索仍属于表单所在组织。
  - 数据库触发器拒绝跨组织的来源表单；线索接口不接受客户端指定来源表单。
- 10 个并发提交：线索、提交次数、通知都是 10。
- 每个表单每小时上限：不同 IP 累计到 200 次后返回 429。
- 跨域预检、审计日志筛选。

另外，线索、通知、回收站、市场活动、权限、多语言、审计、查重合并相关测试共 254/254 通过（含本功能 12 项）。

## 第三轮：回归测试
命令：`scripts/regression.sh web-forms`（后台运行）
结果：**通过**（第二次运行）：lint、类型检查、101 个文件 1021 项单元/集成测试、Pages 构建、生产构建、89 项 E2E 全部通过；首次有 1 项 E2E 失败，见下表。原始输出：[results/web-forms-r3-regression.txt](results/web-forms-r3-regression.txt)

新增 E2E `e2e/web-forms.spec.ts`（2 项）：
- 经理的完整流程：
  1. 查看演示表单，停用的不显示。
  2. 新建表单：加手机字段，邮箱必填，分配给王芳。
  3. 访客在未登录的独立浏览器中打开公开地址，看到 6 个字段；必填校验提示后补全并提交成功。
  4. 表单详情显示提交次数 1 和这条线索；线索详情显示来源表单。
  5. 重新生成地址后，旧地址显示“表单不存在或已停用”。
  6. 王芳的通知中心收到“网页表单收到新线索”。
- 只读用户只能查看：能看到地址和 3 条演示线索，没有编辑、重新生成按钮。

导航 E2E 的四种角色菜单都加入了“网页表单”。

### 失败与修复
| 现象 | 原因 | 修复 |
|---|---|---|
| 开发中：类型检查发现 `Lead` 上没有 `webForm` | 开发失误：新增字段写进了公共类型中的 `Deal`，线索页使用的是页面内的 `Lead` 类型 | 移到线索页的 `Lead` 类型，公共类型恢复原样 |
| 开发中：演示数据中 `owner('admin')` 类型错误 | 开发失误：`owner()` 只接受负责人账号（经理、销售），管理员 ID 应使用 `ids.admin` | 改为 `ids.admin` |
| 开发中自查：GitHub Pages 使用末尾斜杠 | 预防：生成的 `/web-form?key=` 地址依赖 Pages 的目录跳转保留查询参数 | 地址沿用当前页面的末尾斜杠风格 |
| R3 首次 E2E 1 项失败：切换到王芳登录时超时（[首次输出](results/web-forms-r3-regression-first-run-failed.txt)） | 测试代码错误：仍以经理身份登录时再次打开登录页，登录页会把已登录用户跳回首页，点击“登录 王芳”时按钮已被移除（单独运行时偶尔赶在跳转前点中，所以首次单独运行通过）。其余 88 项 E2E、1021 项单元/集成测试、lint、类型检查、两种构建均通过 | 王芳改在新的浏览器上下文中登录；单独运行 2/2 通过后完整重跑第三轮 |
