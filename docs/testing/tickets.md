# 服务工单 — 三轮测试记录

日期：2026-11-16　环境：同 [leads.md](leads.md)　参考：Zoho CRM Cases
迁移：
- `20261116090000_tickets`：新表 `tickets`，枚举 `ticket_status`、`ticket_priority`、`ticket_type`、`ticket_channel`。客户为组织内复合外键 RESTRICT；联系人、负责人为组织内复合外键（不级联）；工单号在组织内唯一。`notifications` 新增 `ticket_id`。CHECK：已解决或已关闭必须有解决方案与解决时间，其他状态没有解决时间；主题非空白；通知恰好指向一个对象（加入工单）。
- `20261116090100_ticket_counters`：工单号计数器表 `ticket_counters`，每个组织每年一行。CHECK：序号为正、年份合理。

## 功能
- 左侧导航新增“服务工单”（位于“跟进”之后）。
  - 列表：顶部按“未解决 / 各状态 / 全部”切换，并显示各状态数量；可搜索工单号、主题、客户、联系人；可按优先级、负责人、“只看逾期”筛选。
  - 详情：显示全部字段与操作记录。
  - 新建、编辑、删除。
- 字段：
  - 工单号 `CS-年份-序号`：由计数器原子分配，并发不重号，删除后不复用，各组织独立编号。
  - 主题、描述、客户（必填，必须可见）、联系人（选填，必须属于所选客户；选客户后加载其联系人）。
  - 类型（咨询、故障、需求建议）、来源渠道（电话、邮件、网站、现场、其他）、优先级（紧急、高、中、低）、负责人、处理期限。
- 状态流转：
  - 新建 → 处理中 ⇄ 等待客户 → 已解决 → 已关闭；已解决、已关闭可重新打开。
  - 解决或关闭必须填写解决方案（服务端与数据库约束双重保证），并记录解决时间；关闭时保留原解决时间。
  - 重新打开时清空解决时间，解决方案保留供参考。
  - 处理期限已过、且仍未解决的工单标为“已逾期”。
- 并发：同时修改同一工单时只有一个成功，其余返回 409（“工单刚被他人修改”），不会出现后写覆盖前写。
- 权限：
  - 与其他业务记录一致：销售只看、只改自己负责的工单，不能指派给他人，也不能删除。
  - 只读用户只能查看；删除需要删除权限（管理员、经理）。
  - 客户端不能提交工单号、组织、解决时间。
- 审计（新对象“服务工单”）：记录新建、修改、删除；描述与解决方案只记“已修改”，不记原文。审计日志页可以按工单筛选。
- 通知：新建或改派给他人时，通知新的负责人；点通知跳转到工单详情。
- 关联数据：
  - 有工单的客户不能删除（提示“该客户下存在服务工单”），数据库 RESTRICT 外键兜底。
  - 删除联系人时，清空工单上的联系人，并在该联系人的删除审计中记录清空了几张工单。
  - 合并重复客户时，工单转到主客户。
- 演示数据：10 张虚构工单（主题带“【演示】”），覆盖全部状态，并包含逾期工单；重建演示数据时同步重置工单号计数器。
- 不做：邮件自动建单、SLA 升级规则、客户门户、知识库、工单评论往来、CSV 导出、工单进入回收站（删除后不可恢复，仅保留审计）。

## 第一轮：功能测试
命令：`npx vitest run tests/tickets/tickets.r1-functional.test.ts`
结果：**8/8 通过（首次即通过）**。原始输出：[results/tickets-r1-functional.txt](results/tickets-r1-functional.txt)

覆盖：
- 新建与默认值；工单号连续，删除后不复用；审计中描述已脱敏。
- 他客户联系人、不存在客户、新建即解决但无解决方案，均返回 400；带解决方案时记录解决时间；5 类非法参数返回 400。
- 状态流转全过程：解决需解决方案、关闭保留解决时间、已关闭不能清空解决方案、重新打开清空解决时间并保留方案，以及相应审计。
- 逾期判定（已解决的过期工单不算逾期）；按逾期、未解决、状态、优先级、联系人名、工单号、客户名搜索筛选；各状态数量不受状态筛选影响。
- 改派与新建指派他人时发出通知（含工单 ID 与标题）；换客户时联系人必须匹配。
- 有工单的客户删除返回 409；删除联系人清空工单联系人并记审计；删除工单后客户可删除。
- 合并客户转移工单。
- 演示工单 10 张，覆盖全部状态，联系人属于客户，计数器一致，重复重建结果相同。

## 第二轮：集成测试
命令：`npx vitest run tests/tickets/tickets.r2-integration.test.ts`
结果：**8/8 通过（首次即通过）**。原始输出：[results/tickets-r2-integration.txt](results/tickets-r2-integration.txt)

覆盖：
- 销售只看自己的（列表、数量、详情、修改，他人工单均返回 404）；不可见客户不能建单；不能指派他人（403）；不能删除（403）；能解决自己的工单。
- 只读用户只能查看，写操作均返回 403；经理可以改派，改派后原负责人看不到；经理可以删除。
- 跨组织隔离：列表、详情、修改、删除；不能引用其他组织的客户、联系人或负责人；各组织独立编号。
- 客户端提交工单号、组织、解决时间、逾期标记均返回 400；4 类非法查询；未登录 401。
- 并发：10 个并发新建得到连续且不重复的编号；3 个并发修改中失败的返回 409，审计条数等于成功次数；删除客户与新建工单并发 3 轮，不会留下指向已删除客户的工单。
- 跨域预检。
