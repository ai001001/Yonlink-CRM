# 报表导出 Excel — 三轮测试记录

日期：2026-11-19　环境：同 [leads.md](leads.md)　参考：Zoho CRM 报表导出（XLSX）
无数据库迁移。

## 功能
- **Excel 写入器** `src/server/xlsx.ts`：
  - 不新增第三方依赖，用 Node 自带的 zlib 压缩和 CRC32，按 Office Open XML 生成 `.xlsx`。
  - 文本以内联字符串写入，不会被当作公式执行（CSV 用单引号前缀防公式注入，Excel 则不存在这个问题）；XML 特殊字符转义，非法控制字符删除。
  - 数字格式：金额为千分位两位小数；整数带千分位；比率显示为“45.5%”，单元格值与页面上的百分数一致。
  - 表头和合计行加粗、冻结表头，列宽按内容估算（中日韩字符按 2 个宽度计）。
  - 工作表名会替换非法字符、截断到 31 个字符并去重；时间戳固定，同样的输入生成完全相同的文件。
- **三个报表可以导出 Excel**：
  - **销售报表**：7 个工作表——概览（含币种、期间、负责人）、销售漏斗、按月赢单、负责人排行、线索来源转化、报价单状态、竞争对手胜负。
  - **销售预测**：一个工作表，按负责人一行，团队合计行加粗。
  - **应收账款**：3 个工作表——概览（未收、逾期、近 30 天收款，以及账龄分布）、按客户汇总、未收发票明细。
  - 与 CSV 使用同一份报表计算，数字与页面一致。
- **接口**：原导出接口增加 `format=xlsx`；不传或 `format=csv` 时仍为 CSV，内容不变；其他取值返回 400。
- **权限与审计**：与 CSV 相同，需要导出权限（管理员、经理）。审计中记录 `format: 'xlsx'`；CSV 的审计内容不变。
- **界面**：销售报表、销售预测、应收账款页面的“导出”按钮旁新增“下载 Excel”按钮。没有导出权限的用户看不到这两个按钮。
- **不做**：图表、单元格公式、列表页（线索、客户等）的 Excel 导出、Excel 导入。

## 第一轮：功能测试
命令：`npx vitest run tests/report-excel/report-excel.r1-functional.test.ts`
结果：**4/4 通过（首次即通过）**。原始输出：[results/report-excel-r1-functional.txt](results/report-excel-r1-functional.txt)

测试使用独立实现的读取器 `tests/report-excel/xlsx-reader.ts`：按 ZIP 中央目录解包、校验 CRC32，再解析单元格。

覆盖：
- **写入器**：
  - ZIP 文件头、文件清单与顺序、输出稳定。
  - 工作表名：非法字符替换、去重、截断到 31。
  - `<b>&"x"` 原样保留；控制字符被删除；`=SUM(...)` 仍是内联文本，没有公式。
  - 表头加粗、金额、比率、整数样式；冻结窗格；超过 Z 列为 AA、AB；空单元格省略；百分比格式代码；没有工作表时报错。
- **销售报表**：
  - 响应类型、文件名、导出条数；7 个工作表的名称；概览中的标题、币种。
  - 赢单金额 1000.5 与接口一致，并且是金额格式的数字单元格；赢单率与接口一致；漏斗各阶段的数量和金额与接口一致；冻结表头。
  - 英文工作表名。
  - CSV 默认导出与 `format=csv` 完全相同；`format=pdf` 返回 400。
  - 审计：两次 Excel 导出记录了格式，两次 CSV 导出没有。
- **销售预测**：标题与说明行、表头位置、冻结行；负责人的目标、已赢单与接口一致；合计行全部加粗，合计与接口一致。
- **应收账款**：
  - 3 个工作表；未收、逾期金额与张数、各账龄金额都与接口一致。
  - 按客户汇总的顺序与接口一致；明细 3 行，未付余额与接口一致。
  - 审计记录格式和条数；销售代表、只读用户导出返回 403。

## 第二轮：集成测试
命令：`npx vitest run tests/report-excel/report-excel.r2-integration.test.ts`
结果：**4/4 通过（首次即通过）**。原始输出：[results/report-excel-r2-integration.txt](results/report-excel-r2-integration.txt)

覆盖：
- **用 Python 标准库独立校验真实导出文件**：
  - 应收账款和销售报表的 Excel 都由 `zipfile` 校验每个文件的 CRC，由 `xml.dom.minidom` 解析每个 XML。
  - 内容类型声明和工作簿关系都指向存在的部件，每个工作表都能找到。
- **危险文本**：客户名为 `=HYPERLINK(...)`、`<script>…</script> & "引号"`、表情加中日韩字符时，都原样作为文本保存，文件中没有公式，`<script>` 被转义。
- **跨组织隔离**：另一个组织的导出为 0 行，文件中不含本组织的客户名。
- **截断**：明细超过上限时被截断（标记已截断），概览中的未收金额和张数仍为全量（300、3）。
- **并发**：同一时刻 5 个并发导出，文件内容完全一致。
- **性能**：20,000 行工作表在 5 秒内生成，并通过 Python 校验。
- **跨域**：
  - 允许的来源能读取 `Content-Disposition`、`X-Export-Count` 响应头；不在允许列表中的来源不返回跨域头。
  - 测试环境没有配置跨域来源，用例中临时设置后恢复。最初的写法在没有配置时直接返回，等于什么也没测，已改正后才计入。

另外，报表导出、应收账款、报表、销售预测、多语言、审计、权限、导入导出、工单导出相关测试共 238/238 通过（含本功能 8 项）。

### 失败与修复
| 现象 | 原因 | 修复 |
|---|---|---|
| R2 自查：跨域用例在测试环境中直接返回 | 测试代码问题：没有配置跨域来源时提前返回，没有实际断言 | 用例内临时设置来源并在结束时恢复，同时增加“不允许的来源不返回跨域头”；4/4 通过 |
| 开发中：现有 E2E 用 `/导\s*出/` 匹配导出按钮 | 预防：如果新按钮也叫“导出 Excel”，会与原按钮同时匹配 | 新按钮命名为“下载 Excel”，并加 `data-testid="export-excel"` |
