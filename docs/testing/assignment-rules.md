## 功能
- **规则**：按顺序逐条匹配，第一条“条件全部满足”的启用规则命中后，在其负责人中**轮流分配**。
  - 条件最多 5 条：线索来源、市场活动、网页表单为“等于”；公司、职位、邮箱、描述支持等于、包含、开头是、结尾是（不区分大小写，去首尾空格）。
  - 没有条件的规则匹配全部线索，适合放在最后兜底；停用的规则不参与。
  - 每条规则 1–20 名负责人，最多 50 条规则。
- **轮流分配**：规则记录已分配次数（指针），按负责人顺序循环。
  - 停用的负责人跳过；规则内负责人全部停用时继续尝试下一条规则。
  - 指针在分配事务内原子递增；分配持共享锁、保存持排他锁，**保存期间的提交会等待保存完成后按新规则分配**，不会落空。
- **应用场景**：
  - 网页表单设为“按分配规则分配”时的公开提交（没有规则命中则不分配）；负责人通知、审计注明规则名称。
  - 线索导入选择“未填负责人邮箱的行：按分配规则”（需 `owner.assign`，仅线索）：文件中指定的负责人优先，没有命中归导入人；预检不占用轮次。
  - 线索列表批量“按规则重新分配”（需 `owner.assign`）：没有规则命中、已转化的线索逐条报失败；负责人变化时写审计并通知新负责人，不变则不写。
  - 手工新建线索不受规则影响（仍默认归创建人）。
- **界面**：线索列表“分配规则”按钮打开规则弹窗（上移/下移、启用开关、负责人多选、条件编辑、已分配次数）；网页表单编辑中“按分配规则分配”开关（打开后负责人置空并禁用）；导入弹窗中的负责人选项。
- **权限、审计**：所有人可查看规则；`assignment.manage`（管理员、经理）可保存，整体替换，保存后指针从头开始。审计对象 `assignment`，记录规则数与规则文本前后对比。
- **演示数据**：4 条规则——展会线索（郑经理、王芳）、官网询盘（王芳、陈静）、职位含“采购”（陈静）、兜底（王芳、陈静）；“官网产品咨询”表单使用分配规则。
- **不做**：客户、商机、工单的分配规则；按地区（Territory）分配；按负载（未结线索数）分配。

### 失败与修复
| 现象 | 原因 | 修复 |
|---|---|---|
| R1 首次 2 项失败（[首次输出](results/assignment-rules-r1-first-run-failed.txt)） | 测试数据错误：① 市场活动类型写成 `TRADE_SHOW`（实际为 `EXHIBITION`），新建失败导致后续保存 400；② 导入示例的来源写成“网站”（实际标签为“官网”），该行校验不通过 | 改正测试数据；重新运行 5/5 通过 |
| R2 第二次运行 1 项失败（[失败输出](results/assignment-rules-r2-first-run-failed.txt)） | **真实缺陷**：保存规则是“先删后建”，同时到达的提交先读到旧规则，取号时规则已被删除，线索变成未分配 | 分配时取共享咨询锁、保存时取排他锁（同一键），保存前的审计快照也移到锁内读取；并把并发测试加强为 30 个提交穿插 3 次保存、断言没有未分配。修复后连续 10 次通过；临时去掉共享锁时 6 次失败 5 次，确认测试能发现该缺陷 |
| 加强后的并发测试偶发失败 | 测试假设错误：并发发出的 3 次保存按取得锁的先后生效，不能假定最后一次是“新24” | 改为断言最终只剩一组且是三者之一 |
| R3 首次 E2E 1 项失败（[首次输出](results/assignment-rules-r3-first-run-failed.txt)）：已有用例“只读用户只能查看客户与联系人评分规则” | 已有测试的偶发问题，与本功能无关（该页面与组件未改动）：截图显示弹窗已经关闭，但“关闭”按钮的点击仍在等待；单独运行 3 次均通过 | 关闭步骤改为按结果判断（弹窗仍可见才点击，最终必须隐藏），断言不变；重跑 R3 全部通过 |
| 新 E2E 首次失败两次 | 测试写法问题：① 通用 `selectOption` 只适用单选，多选时下拉不会自动收起；② 判断“值”是否已变成文本框时，下拉选择框内部也是 INPUT，判断无效；antd v6 单选框显示元素类名不同 | 多选改为点选后点击名称框收起；改为按结果判断（规则卡片内出现两个文本框、显示“包含”）；2/2 通过 |
