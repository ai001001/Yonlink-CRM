# 字段验证规则 — 三轮测试记录

日期：2026-11-21　环境：同 [leads.md](leads.md)　参考：Zoho CRM Validation Rules

迁移 `20261127090000_validation_rules`：新表 `validation_rules`（名称、对象（线索/商机，复用工作流对象枚举）、适用条件 JSON、要求 JSON、提示、提示字段、启用、创建人）；约束：名称组织内唯一（不区分大小写）且非空白、提示非空白、适用条件为数组且最多 5 条、要求 1–5 条。应用迁移后，`prisma migrate diff` 与数据库对比为空迁移，没有漂移。

另外把工作流的条件判断与条件校验提取为可复用函数（`evaluate`、`checkCondition`），并新增日期类型（为空、不为空、≥、≤，按 YYYY-MM-DD 比较）；工作流行为不变（工作流测试 15/15 通过）。新增共用的条件编辑组件 `ConditionRows`。

## 功能
- **规则**：满足“适用条件”（全部成立；为空表示总是适用）的记录必须满足“要求”（全部成立），否则拒绝保存，显示自定义提示。
  - 线索字段：状态、来源、名称、公司、职位、邮箱、电话、手机、描述、负责人、市场活动。
  - 商机字段：阶段、币种、名称、描述、金额、预计成交日、负责人、市场活动。
  - 不含评分（评分在写入后才计算）。
  - 提示可指定显示在某个字段下（表单中该字段标红），未指定则作为整体提示。
- **校验时机**：线索、商机的新建与编辑，按写入后的值判断（编辑时为原值与修改合并后的结果）；包括批量操作（逐条报错）、看板拖动、API 密钥调用。多条规则同时不满足时全部列出，按提示字段归类（未指定的归入 `rule`）。
- **不校验**：网页表单（访客无法修正内部规则）、导入、线索转化生成的商机、工作流的自动改动。
- **维护**（设置 › 验证规则）：列表按对象筛选，显示适用条件、要求、提示与提示字段、启用开关；新建/编辑弹窗。所有用户可通过接口查看；新建、修改、启停、删除需 `validation.manage`（管理员、经理），对象创建后不可改，每组织最多 50 条（加锁判断），写审计。
- **演示数据**：2 条——金额达到 100 万的商机必须填写预计成交日；输单的商机必须在描述中填写原因。全部演示商机都满足这两条（编辑演示商机不会被误拦）。
- **不做**：跨对象的规则（如商机金额对比客户字段）、公式表达式、客户与联系人的规则。
