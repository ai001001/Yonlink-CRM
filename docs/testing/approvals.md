日期：2026-11-24　环境：同 [leads.md](leads.md)　参考：Zoho CRM Approval Processes（Quotes 折扣审批）

说明：复杂审批原列在路线图“暂不做”中；负责人要求按 Zoho CRM 补齐功能，本功能先实现最常用的报价单折扣/金额审批。

- `20261124090100_quote_approvals`：
  - 枚举 `approval_status`（PENDING、APPROVED、REJECTED）、`approval_action`（SUBMIT、APPROVE、REJECT、RECALL）。
  - `quotes` 新增 `approval_status`、`approval_reasons`；约束：待审批只出现在草稿上，原因必须伴随状态。
  - 新表 `quote_approval_settings`（每组织一行：启用、折扣上限 0–100、金额非负）与 `quote_approvals`（审批历史，复合外键同组织，意见非空白，`UPDATE` 被触发器拒绝）。
- 应用迁移后，`prisma migrate diff` 与数据库对比为空迁移，没有漂移。

## 功能
- **审批规则**（审批页上方，`approval.manage`：管理员、经理可改，其他人只读）：启用；折扣上限（任一明细折扣超过即需审批）；金额（总计按当天汇率折合人民币达到即需审批；没有汇率时视为需要审批）。两个条件可只用一个；启用时至少要有一个。修改写审计。
- **流程**：
  - 需要审批的草稿直接发送被拦（409，并列出原因）。
  - 提交审批：记录原因，状态“待审批”；报价单锁定，不能修改、同步明细、删除、发送；通知其他有审批权限的用户（管理员、经理）。
  - 批准或驳回（驳回必须填写意见）：需 `quote.approve`，**不能审批自己提交的**；通知提交人（已停用则不通知）。
  - 撤回：提交人或审批人。
  - 驳回后可修改再提交；批准后可发送；批准或驳回后再修改（含同步明细、改税率）清空审批结果，需重新审批。
  - 不需要审批的报价单不能提交（409）；规则不启用时原有流程完全不变。
- **并发安全**：提交、审批、撤回都是条件更新（同时审批只有一个成功）；修改、同步、删除在事务内对报价单加行锁并重新检查，发送的状态更新同时要求审批状态未变，避免“待审批但内容已改”。
- **界面**：
  - 报价单详情：状态旁显示审批标签；审批面板显示状态、原因、提交/批准/驳回/撤回按钮与审批历史（时间线）；待审批时隐藏编辑、同步、发送、删除，并提示已锁定。
  - 活动 › 审批：审批规则卡片；“待我审批”（有审批权限时，可直接批准/驳回，自己提交的显示需他人审批）与“我提交的”。
  - 通知中心：新增“待审批”“审批结果”两类通知（关联商机）。
- **回收站**：删除商机时报价单的审批状态、原因与历史一并进入快照，恢复后原样还原。
- **演示数据**：启用审批（折扣 > 5% 或折合 ≥ ¥1,000,000）；需要审批的草稿中第 1 张由提交人提交、管理员批准，第 2 张（陈静提交、折扣 8%）待审批，其余（如王芳的大额美元报价）未提交。
- **不做**：多级审批、按金额分配不同审批人、其他对象（如订单、折扣以外字段）的审批流程。

## 第一轮：功能测试
命令：`npx vitest run tests/approvals/approvals.r1-functional.test.ts`
结果：**6/6 通过（第三次运行通过，前两次失败见下表）**。原始输出：[results/approvals-r1-functional.txt](results/approvals-r1-functional.txt)

覆盖：
- 规则：默认不启用；保存；7 类非法输入（折扣 > 100、负数、3 位小数、金额负数或非数字、启用但无条件、多余字段）；不启用时可都为空；销售 403、经理可改；审计三次变化。
- 不启用时原流程不变；不需要审批时不能提交（not_required）。
- 完整流程：发送被拦（`required` + `discount:15>10`）→ 提交（通知管理员与经理 2 人、不含提交人）→ 锁定（再次提交、修改、同步、删除、发送均 409 pending）→ 销售不能审批 → 驳回缺意见 400 → 驳回（通知提交人）→ 仍不能发送 → 修改清空结果 → 再提交 → 批准 → 不能再提交 → 发送成功且保持已批准；审批历史顺序与意见；审计动作序列；修改审计注明清空原审批结果。
- 批准后同步明细清空批准、发送再被拦（`total:200000.00>=100000`）；撤回（无关销售 404，提交人成功，再撤回 not_pending）；经理不能审批自己的、管理员可以。
- 外币：没有汇率 `total:no_rate`；录入 USD 汇率 4 后 20,000 美元（80,000）可发送，30,000 美元（120,000）需审批。
- 列表：待我审批（含能否审批、提交人）；销售查看待审批 403；我提交的（含状态）；非法范围 400。

## 第二轮：集成测试
命令：`npx vitest run tests/approvals tests/quotes tests/sales-orders tests/invoices tests/notifications tests/audit tests/rbac tests/i18n tests/exchange-rates tests/recycle tests/workflows tests/deals tests/stage-history`
结果：**30 个文件 328/328 通过（首次运行发现回收站恢复缺陷，修复后通过，见下表）**。原始输出：[results/approvals-r2-integration.txt](results/approvals-r2-integration.txt)

覆盖：
- 两个审批人同时审批：一个 200、一个 409，历史只有一条决定。
- 5 个并发提交只有 1 个成功；修改与提交并发 5 轮，凡最终为待审批的，提交之后都没有修改。
- 组织隔离：B 的经理审批 A 的报价单 404；B 的规则默认不启用。
- 数据库：已发送却待审批、有原因无状态、折扣上限 120 均被约束拒绝；历史不能修改；空白意见被拒绝；删除报价单级联删除历史。
- 提交人停用后仍可审批、不发通知；通知中心返回审批通知（类型、操作人、关联商机）；审计日志按 quote、approval 筛选。
- 回收站：删除商机后恢复，已批准报价单的审批状态、原因、历史（ID、动作、意见、原因）与未提交的报价单都原样恢复。
- 演示数据：规则；一张已批准（提交 + 批准）、一张待审批；原因与系统重新计算一致；经理批准待审批单后提交人收到通知。
- 报价单、销售订单、发票、通知、审计、权限、多语言、汇率、回收站、工作流、商机、阶段历史相关测试全部通过。

### 失败与修复
| 现象 | 原因 | 修复 |
|---|---|---|
| R1 首次 5 项失败（[首次输出](results/approvals-r1-first-run-failed.txt)） | 测试准备错误：客户由管理员创建，销售看不到，因而不能在其下建商机与报价单 | 客户负责人设为该销售 |
| R1 第二次 1 项失败 | 测试准备错误：① 外币商机的明细产品须与商机同币种；② 汇率接口是 PUT 不是 POST | 外币用例改建同币种产品；改用 PUT；6/6 通过 |
| R2 首次 1 项失败（[失败输出](results/approvals-r2-first-run-failed.txt)）：回收站恢复带报价单的商机返回 500 | **真实缺陷**（本功能引入）：报价单快照中新增的可空 JSON 字段 `approvalReasons` 为空值时，恢复写入用了普通 `null`，Prisma 拒绝 | 恢复时写为数据库 NULL；同时把审批历史加入快照并恢复；新增回收站恢复用例；30 个文件 328/328 通过 |
| 新 E2E 首次 1 项失败 | 测试写法问题：antd 在两个汉字的按钮中间插入空格（“批 准”），按名称精确匹配不到 | 改为正则 `/批\s*准/`；3/3 通过 |
