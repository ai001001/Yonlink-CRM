# 整页详情（#67）— 三轮测试记录

日期：2026-11-26　环境：同 [leads.md](leads.md)　参考：Zoho CRM 记录详情页（概览、时间线、相关列表、字段内联编辑）

迁移：无（只新增接口与页面）。

## 功能
- **整页详情**：线索 `/leads/view?id=`、客户 `/accounts/view?id=`、商机 `/deals/view?id=`。
  - 入口：列表详情抽屉标题旁的“整页查看”，也可直接访问地址。原有的抽屉保留，列表操作不变。
  - 顶部摘要：状态或阶段、金额、评分、负责人、区域、标签（可直接增删）。
  - 左侧“详细信息”：标准字段与自定义字段。
  - 右侧页签：时间线，以及与抽屉相同的相关列表。线索：跟进、备注、附件；客户：联系人、商机、跟进、备注、附件、自定义模块；商机：产品明细、报价单、联系人角色、竞争对手、阶段历史、跟进、备注、附件。有审计权限时另有“修改记录”页签。启用流程蓝图时显示蓝图页签。
- **点字段直接编辑**：
  - 有编辑权限时，点字段或铅笔按钮进入编辑，保存只提交该字段（自定义字段同样逐项保存）。
  - 编辑器按类型：文本（回车保存）、多行文本、下拉（只列启用的选项并保留当前值）、负责人（需指派权限）、日期、金额。必填字段为空时不能保存。
  - 只读情况：已转化的线索；启用流程蓝图时的状态或阶段；有产品明细时的金额与币种；没有编辑权限时整页只读并提示（例如区域只读的记录）。
  - 所有校验仍在服务端执行，失败时显示服务端的提示。
- **时间线**（`GET /api/timeline`）：
  - 内容：跟进、备注与该记录自身的修改记录（新建、修改、转化、工作流的字段修改等）合并，最新在前，每页 30 条，可加载更多。
  - 范围：记录须对查看者可见（含区域只读范围），否则 404；跟进按查看者的可见范围；修改记录的值在写入审计时已脱敏，没有审计权限时不返回 IP。
  - 分页：使用“时间 + 已返回条目”游标，同一毫秒的条目不会遗漏或重复。
- **手机**：整页详情在手机上上下排列（摘要、字段、页签），不横向超宽。
- **不做**：联系人整页、整页中的转化与删除（在列表与抽屉中进行）、时间线中其他记录的变化（如客户下商机的修改）、列表点击直接打开整页。

## 第一轮：功能测试

结果：**4/4 通过**。原始输出：[results/record-page-r1-functional.txt](results/record-page-r1-functional.txt)

覆盖：
- **合并与排序**：线索的修改、备注、跟进、新建按时间倒序合并，只含该记录自身的审计。
- **分页**：40 条同一毫秒的备注加 25 条跟进与 1 条审计，逐页读取得到 66 条且不重复；首页 30 条并提示还有更多。
- **范围**：他人的线索 404；区域成员看到区域内他人商机的备注与修改记录，但看不到他人的跟进；管理员三类都能看到；没有审计权限时 IP 为空；其他组织 404；对象、ID、时间参数校验。
- **单字段修改**：只改提交的字段、可清空、每次修改写审计并出现在时间线；他人不能修改。

## 第三轮：回归测试
命令：`bash scripts/regression.sh record-page`（lint、typecheck、全部单元/集成测试、Pages 构建、生产构建、全部端到端测试）
结果：**lint、typecheck、单元/集成（158 个文件 1290/1290）、两种构建均通过；端到端每次完整运行都有 1–2 个不同用例因机器负载偶发超时，单独运行均通过。经负责人确认，记录后上线。**

完整运行记录：
1. 第一次回归：端到端 141 通过、8 失败，均卡在关闭详情抽屉。**产品问题**：“整页查看”链接遮住了抽屉的关闭按钮（见下方）。修复后这 8 个用例与本功能用例单独运行 18/18 通过。原始输出：[results/record-page-r3-first-run-failed.txt](results/record-page-r3-first-run-failed.txt)
2. 修改产品代码后重跑完整回归：lint、typecheck、单元/集成 1290/1290、两种构建通过；端到端 148 通过、1 失败（集成设置页“API 密钥已创建”弹窗未关闭，挡住后续按钮）。该页面本次未改动，单独运行通过；用例改为按结果确认弹窗关闭。原始输出：[results/record-page-r3-second-run-failed.txt](results/record-page-r3-second-run-failed.txt)
3. 只改测试后重跑全部端到端：147 通过、2 失败（客户评分用例在创建页面阶段超时、仓库用例下拉选项一直不稳定），两者单独运行通过（3/3）。原始输出：[results/record-page-r3-e2e-rerun1-failed.txt](results/record-page-r3-e2e-rerun1-failed.txt)
4. 再次重跑全部端到端：148 通过、1 失败（报表用例等待接口响应超过 30 秒）。原始输出：[results/record-page-r3-e2e-rerun.txt](results/record-page-r3-e2e-rerun.txt)

分析：第 2–4 次失败的用例每次不同，都是超时，单独运行均通过，涉及的页面不在本次改动范围内。运行环境只有 2 个 CPU，测试期间负载 3.6–4.3，线上演示服务也在同一台机器上运行，判断为负载导致的偶发超时。按“同一操作反复失败就换方法”的原则，第 4 次后不再原样重跑，经负责人确认记录后上线。后续建议在负载较低时运行端到端测试，或把测试与演示服务分开部署。

### 失败与修复
| 现象 | 原因 | 修复 |
|---|---|---|
| E2E 首次：找不到描述字段 | 测试问题：描述字段的名称是“备注” | 改正 |
| R2 首次：启用蓝图后改阶段仍成功 | 测试问题：流程蓝图新建时默认停用，测试未启用（已通过接口返回确认 `isActive: false`） | 新建时传 `isActive: true` |
| R3 首次：8 个端到端用例在关闭详情抽屉时超时 | 产品问题：抽屉右上角按钮区加入“整页查看”后过宽，链接遮住了抽屉的关闭按钮（线索抽屉最明显），用户无法点击关闭 | “整页查看”移到抽屉标题中，按钮区恢复原样；修改产品代码后重跑完整的第三轮 |
| R3 第二次：集成设置页用例弹窗未关闭 | 测试问题（偶发）：点击“我已保存”后没有确认弹窗关闭就继续操作 | 按结果确认弹窗关闭（没关上就再点一次） |
| R3 第三、四次：评分、仓库、报表用例偶发超时 | 运行环境负载高（2 个 CPU，负载 3.6–4.3），单独运行均通过 | 未改代码；如实记录，经负责人确认后上线 |
| R2 首次：时间线中没有 `workflow.run` | 测试预期不准确：工作流执行记录在工作流名下，商机上记录的是它做出的 `deal.update` | 改为检查商机上的 `deal.update` 与 `deal.create` |
