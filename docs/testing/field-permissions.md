迁移：

- 手写约束：系统角色与自定义角色二选一；系统角色不能是系统管理员；字段只能取可限制的标准字段，或 `custom.<自定义字段键>`。

## 功能
- **设置 › 字段权限**（需 user.manage，即系统管理员）：
  - 选对象（线索、客户、联系人、商机）与角色（销售经理、销售代表、只读用户，以及各自定义角色）。
  - 逐个字段设为可编辑、只读或隐藏，按角色整体保存；未保存时有提示。
  - 系统管理员不受限，不在角色中。
  - 保存写审计，记录各字段访问级别的变化与自定义字段名称；审计日志中可读显示。
- **可限制的字段**：
  - 标准字段：
    - 线索：职位、电话、手机、邮箱、描述
    - 客户：电话、网站、地址、描述
    - 联系人：职位、电话、邮箱
    - 商机：描述
  - 名称、阶段、金额、负责人、来源、行业等核心字段不能限制：它们用于看板、预测、仪表盘和内置报表的汇总。
  - 自定义字段全部可限制（含已停用的）。删除自定义字段时，其设置一并删除。
- **谁受限**：
  - 使用自定义角色的用户只按该自定义角色的设置，否则按系统角色的设置。
  - 规则在每个请求认证时随身份从数据库读取，修改后下一个请求立即生效。
  - API 密钥按其绑定用户受限。
- **隐藏**（服务端执行）：
  - **返回内容**：以下接口都不返回隐藏字段：列表、详情、新建/修改的返回、看板，以及客户下的联系人、联系人列表、商机联系人角色、工单联系人、报价单/销售订单/发票中的客户、线索转化结果、查重结果。
  - **搜索与导出**：
    - 列表搜索和全局搜索不匹配隐藏字段，不能借搜索探测隐藏的值。
    - 导出去掉隐藏的列和隐藏的自定义字段。
  - **审计与报表**：
    - 时间线与审计日志的变更记录中去掉隐藏字段。
    - 自定义报表的字段目录不含隐藏字段。用到隐藏字段（列、筛选、分组、汇总、排序）的报表不能预览、保存、运行或导出，返回 403。
  - **查重与订单**：
    - 查重不按隐藏字段匹配。
    - 由报价单生成订单时，隐藏的客户地址不带入收货地址。
  - **写入**：
    - 编辑时提交隐藏字段一律拒绝（403 `field_hidden`），值相同也拒绝，避免用写入探测。
    - 新建时只能留空。
- **只读**：
  - 可以看到。编辑时只能保持原值，改动返回 403 `field_read_only`；新建时只能留空。
  - 合并重复记录时不能通过选择来源改变受限字段，导入时受限列有值的行报错（`not_editable`）。
- **必填的自定义字段**：受限时该角色不需要填写（管理员仍须填写）。
- **界面**：
  - 列表列、详情、编辑表单、整页详情、查重合并按当前用户的规则隐藏字段或禁用输入；自定义字段同样处理。
  - 规则随 /api/auth/me 读取，前端只用于显示，服务端仍逐请求执行。
- **演示数据**：
  - 只读用户（周会计）看不到线索的手机与电话、联系人的电话。
  - 销售代表的客户地址只读。
  - 重置时先删除再重建。
- **已知限制**（记录在案）：
  - 评分明细中“已填写某字段”的规则会反映该字段是否为空，但不显示值。
  - 线索转化按系统映射把线索的电话、邮箱复制到新客户和联系人，不检查目标字段的只读设置。
  - 客户门户的开通信息显示门户登录邮箱（即联系人邮箱）。该页面需门户管理权限。
  - 工作流、Webhook 等系统动作不受字段权限限制。
- **不做**：角色层级与记录共享（#70）、布局级的字段显示（不同布局）。

### 附带修复：删除角色与分配角色并发时的死锁
第二轮的相关套件中，#68 的并发用例出现 500。单独重复运行该用例 12 次，5 次失败，数据库报 `deadlock detected`。

原因：修改用户时对管理员行加了 `FOR UPDATE` 锁，防止并发降级后没有管理员。删除角色时写审计，审计的操作人外键检查要对管理员行加 `KEY SHARE` 锁，被它挡住；而修改用户的事务在等被删除的角色行，形成环。新增的级联外键让这种情况更容易出现。

第一次修复只给角色行加锁排序，重复 15 次仍有 11 次失败。按“换方法”的规则停下重新分析，确认锁环在管理员行上。

修复：
- 管理员行改用 `FOR NO KEY UPDATE`：修改之间仍然串行，但不阻塞外键检查。
- 删除角色时先锁角色行，并在同一事务内复查使用人数。
- 分配角色时对角色加共享锁；角色已被删除则返回 400。

修复后该用例连续 15 次 0 失败。另加了一个用例：删除与 4 个并发分配，重复 5 轮，不出现 500。“最后一名管理员”的并发用例仍然通过。

  - 读取：线索的 5 个标准字段与自定义字段（名称、启用、必填），角色为 3 个系统角色加自定义角色；经理、销售不能读写。
  - 7 类非法保存：核心字段、未知自定义字段、商机金额、非法级别、管理员角色、未指定角色、同时指定两种角色；不存在的自定义角色 404。
  - 保存与替换：“可编辑”不存储，整体替换，系统角色与自定义角色分开保存；无变化不写审计，审计记录变化与自定义字段名称。
  - 数据库约束：管理员、两者都填、两者都空、核心字段、商机金额被拒绝；重复行被唯一索引拒绝。

  - 隐藏的标准字段与自定义字段不在详情和列表中返回；管理员、经理不受影响。
  - /me 返回规则（管理员为空）。
  - 按隐藏的电话搜索：销售在列表和全局搜索中都搜不到，管理员能搜到；按可见的邮箱仍能搜到。
- **写入**：
  - 新建：隐藏、只读的标准字段与自定义字段有值时拒绝，留空可以。
  - 必填的隐藏自定义字段不要求销售填写，管理员仍须填写。
  - 编辑：隐藏字段值相同也拒绝；只读字段相同可以，改动或清空拒绝；只读的数字自定义字段 0.50 与 0.5 视为相同。
  - 修改其他字段时隐藏的值保持不变；管理员不受限。
- **自定义角色与生效**：
  - 销售按系统角色设置，套用自定义角色后只按自定义角色的设置。
  - 清空或改为只读在下一个请求立即生效。
  - 删除自定义角色时其设置级联删除，系统角色的设置保留。

### 失败与修复
| 现象 | 原因 | 修复 |
|---|---|---|
| R1：新建线索时隐藏字段被误判为“提交了值” | 产品问题：新建的输入校验会把未填的字段补为空值 | 新建时只有隐藏字段真的有值才拒绝；编辑时只要提交就拒绝 |
| R2：演示查重用例找不到“邮箱”分组 | 演示设置最初让只读用户看不到线索邮箱，旧用例以只读账号在演示数据中查重（说明功能生效） | 演示设置改为隐藏线索的手机与电话，旧用例不改 |
| R2：#68 的“删除与分配并发”用例偶发 500 | 产品问题：数据库死锁（见上方“附带修复”） | 调整锁的类型与顺序，新增并发用例 |
| R2：时间线用例中经理读不到审计日志、报价单建不出来 | 测试问题：经理角色没有“查看审计日志”；报价单需要先有产品明细 | 改用能看审计日志的自定义角色（顺带覆盖自定义角色的规则）；先加产品明细 |
| E2E：切换到销售账号时 `/login` 跳回首页、恢复设置时会话已失效 | 测试问题：未退出就切换账号；退出后管理员会话作废 | 销售在独立的浏览器上下文中登录，管理员会话保留用于恢复 |
