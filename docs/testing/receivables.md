# 应收账款报表 — 三轮测试记录

日期：2026-11-14　环境：同 [leads.md](leads.md)　参考：Zoho 应收账龄报表（AR Aging）
迁移：无（只读统计已有发票与收款数据）

## 功能
- 入口：报表页右上角“应收账款”，地址 `/reports/receivables`（左侧导航仍高亮“报表”）；应收账款页可返回销售报表。
- 筛选：币种（各币种分别统计，不做汇率换算；下拉中优先列出有未收发票的币种）；负责人（管理员、经理、只读可选）。
- 汇总：未收金额与发票数、逾期金额与发票数、近 30 天收款金额与笔数。
- 账龄分布：未到期、逾期 1–30 天、31–60 天、61–90 天、90 天以上（金额与张数）。
- 按客户汇总：发票数、未收金额、各账龄金额、最早到期日，欠款多的在前。
- 未收发票明细：按到期日升序，显示余额与“逾期 N 天 / 未到期”，点击发票号打开发票详情；超过 500 张时只列出最早到期的 500 张并提示（汇总仍含全部）。
- 统计口径：未收 = 未付款、部分付款发票的“发票金额 − 已收金额”（已付清、已作废不计）；逾期天数 = 今天（UTC 日期）− 到期日；近 30 天收款按收款日期统计。
- 权限：所有登录用户可看；销售代表只统计自己负责商机的发票与收款（传他人负责人参数也不会越权）；按组织隔离。
- 中英文文案；沿用已有演示发票（人民币：部分付款逾期 90 天以上、未付款逾期 61–90 天；美元：未付款未到期）。
- 不做：外币换算为本币汇总、指定历史日期的应收快照、导出 CSV、催款提醒、平均回款天数（DSO）。

### 失败与修复
| 现象 | 原因 | 修复 |
|---|---|---|
| R1 首次 1 项失败：同名客户出现两行 | 测试辅助函数每建一张发票都新建客户，同名的实际是两个客户 | 同名客户复用同一条记录；同时修正“币种分别统计”用例中一行恒为真的断言（改为断言人民币未收 100.00） |
| R2 首次 5 项失败：报表为空 | 测试辅助函数的产品编码含中文客户名，不符合编码规则，产品创建失败，后续商机明细、报价、订单、发票全部未建成；辅助函数未检查每步状态，问题没有在第一步暴露 | 产品编码改用序号；辅助函数每一步断言创建成功 |
| R3 首次：既有“产品”E2E 超时（[首次失败输出](results/receivables-r3-regression-first-run-failed.txt)；其余 47/48 通过，Vitest 820/820） | 与销售订单第三轮的附件 E2E 相同：操作成功提示条盖住抽屉“关闭”按钮，鼠标悬停使其不消失。当时只修了附件 E2E，没有把同类写法一并改掉 | 全部 E2E（16 个文件 20 处）关闭抽屉统一改用 `closeDrawer`，该函数先把鼠标移到左上角空白处，再等提示条消失后点击关闭 |
| 验证上述修改时“标签”E2E 偶发失败（同一组 5 个文件连续运行时 2 次中出现 1 次） | 失败点在添加标签、尚未关闭抽屉处，与上一项修改无关：点击下拉选项“新建标签”时下拉仍在展开动画中，Ant Design 忽略了这次点击（截图显示下拉与选项仍在，输入完整）。项目已有会重试的 `selectOption`，但 7 个 E2E 文件中 12 处直接点击下拉选项、没有重试 | 新增 `clickOption`：点击后确认下拉收起，未生效则重试；只在下拉仍处于展开（非收起中）时重试，避免同一选项被选两次。12 处全部改用；改动涉及的 7 个文件 14/14、原失败的 5 文件组合 8/8 通过后完整重跑第三轮 |
