# 站内通知与提醒 — 三轮测试记录

日期：2026-11-14　环境：同 [leads.md](leads.md)　参考：Zoho CRM Notifications / Reminders
迁移：`20261114090000_notifications`（新表 `notifications`、枚举 `notification_type`、`activities (organization_id, id)` 唯一约束；CHECK：恰好关联一条记录，跟进提醒必须带跟进、到期时间与去重键）

## 功能
- 顶部栏通知铃铛：显示未读数（每 60 秒、窗口重新可见时、在本页标记已读或删除后刷新）；点开显示最新 8 条，点击标为已读并跳转到记录；“全部标为已读”“查看全部通知”；页面跳转后弹层自动收起。
- 通知中心（左侧导航“通知中心”）：全部 / 未读筛选、分页、标为已读、删除、全部标为已读、清除已读；点击通知跳转到关联记录。
  - 已经在目标列表页时直接打开记录详情（不重新加载页面）；跟进列表页支持 `?id=` 打开跟进详情。
- 分配通知：线索、客户、商机、跟进的负责人被**他人**改为某位用户时，在同一业务事务内通知新负责人（新建、修改、批量分配、查重合并选用其他负责人）。
  - 自己分配给自己、负责人未变化时不通知；导入与线索转化不发通知（避免批量导入产生大量通知；转化沿用原负责人）。
- 跟进提醒：未完成跟进在到期前 30 分钟内、或已到期 24 小时内，为负责人生成一条提醒。
  - 在读取未读数或通知列表时按需生成，不需要后台任务；去重键含到期时间，并发读取也只生成一条；改期后到了新时间会再次提醒。
  - 跟进完成、改期、改负责人时撤销尚未阅读的旧提醒；已读的提醒保留。
- 安全：通知只属于接收人本人，所有读取、标记、删除都按服务端会话的组织与用户限定，别人的通知一律视为不存在（标记返回 0 条、删除 404）。
  - 通知随关联记录删除（数据库外键级联）；从回收站恢复记录不会恢复通知；超过 90 天的通知在读取时清理。
  - 通知属于个人收件箱，已读、删除、清除不写审计；触发通知的业务写操作本身已审计。
- 中英文文案；演示数据：经理分配给两位销售、管理员分配给经理，每人 3 条（线索、进行中商机未读，客户已读），共 9 条；跟进提醒按真实到期时间自动生成，不预置。
- 不做：邮件 / 短信 / 手机推送、实时推送（WebSocket）、@提及、自定义提醒时间、通知偏好设置。

### 失败与修复
| 现象 | 原因 | 修复 |
|---|---|---|
| 迁移首次应用失败（P3009） | 生成迁移 SQL 时把 Prisma 的日志行写进了文件开头，第一句即语法错误，没有任何语句生效 | 删除该行，把开发库与测试库中的失败记录标记为已回滚后重新应用；之后用标准输出单独生成 |
| R1 首次：改期用例 1 项失败 | 测试代码问题：期望值与提交值分别计算当前时间，相差 22 毫秒 | 先保存新时间再提交与比较 |
| 构建时 TypeScript 报错 | R2 测试中查询参数数组类型推断不符合 `Record<string, string>` | 显式标注类型（测试逻辑不变） |
| 通知 E2E 首次 2 项失败 | ① 测试未退出就切换演示账号，登录页自动跳走；② 通知文字使用无地址的可点击文字，没有链接语义，键盘与读屏无法识别 | ① 先退出再登录；② 铃铛与通知中心改用带真实地址的链接（点击时标为已读并在本页打开） |
| 通知 E2E 第二次 1 项失败 | 点“查看全部通知”跳转后铃铛弹层仍然打开，页面上出现两个“全部标为已读” | 页面路径变化时自动收起弹层，并在 E2E 中断言弹层已收起 |

说明：E2E 的前两次失败发生在第三轮之前的单独调试运行，终端输出未另存文件，原因与修复记录于上表。
