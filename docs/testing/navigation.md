# 导航结构调整（按 Zoho CRM 模块分组）— 三轮测试记录

日期：2026-11-17　环境：同 [leads.md](leads.md)　参考：Zoho CRM 模块分组（Sales / Marketing / Activities / Inventory / Support / Analytics / Setup）
迁移：无

## 背景
原来的左侧导航有 21 项平铺，按功能开发的先后顺序追加，没有分组：销售、库存、服务、系统管理混在一起，通知中心也占了一个位置。

## 调整后的结构
| 分组 | 菜单 | 可见范围 |
|---|---|---|
| （无标题） | 工作台 | 所有人 |
| 销售 | 线索、联系人、客户、商机、销售预测 | 所有人 |
| 营销 | 市场活动 | 所有人 |
| 活动 | 跟进 | 所有人 |
| 库存 | 产品、报价单、销售订单、发票 | 所有人 |
| 服务 | 服务工单、知识库 | 所有人 |
| 分析 | 报表（应收账款从报表页进入） | 所有人 |
| 设置 | 用户管理、汇率、查重合并、回收站、审计日志 | 用户管理需 `user.manage`、回收站需 `record.delete`、审计日志需 `audit.read`；汇率、查重合并所有人可见（页面内的写操作仍按原权限控制） |

- 销售组按 Zoho 的顺序排列：线索 → 联系人 → 客户 → 商机 → 销售预测。
- “通知中心”移出导航，从顶部铃铛的“查看全部通知”进入；“个人设置”仍在右上角用户菜单。
- 分组里没有可见菜单时，整组隐藏。不在导航中的页面（通知中心、个人设置）不高亮任何菜单。
- 只调整菜单的分组和顺序，各页面的地址和权限不变，原有的链接和书签仍然有效。
- 新增网站图标 `src/app/icon.svg`。原来没有图标，浏览器每打开一个页面，都会请求不存在的 `/favicon.ico`，控制台报 404；线上的 Pages 和后端都已确认存在这个问题。
- 不做：顶部模块切换栏、用户自定义菜单顺序、菜单折叠记忆。

## 第一轮：功能测试
导航调整没有新的服务端逻辑，第一轮是界面层面的功能检查：
- 类型检查与 lint 通过；生产构建通过，构建产物中包含 `/icon.svg`。
- 新增 E2E `e2e/navigation.spec.ts`，在开发中逐个角色运行，验证分组标题、菜单顺序，以及每个菜单都能打开。

首次运行结果：4 个角色的分组、顺序、权限、页面打开、高亮全部正确，但**每个角色都有 1 条控制台错误**：资源返回 404。逐项排查后确认是缺少网站图标（见上文），线上同样存在。补上图标后，4/4 通过。

## 第二轮：集成测试
命令：`npx playwright test e2e/navigation.spec.ts e2e/ticket-comments.spec.ts`（开发环境，真实后端与测试库）
覆盖：
- **四种角色**（系统管理员、销售经理、销售代表、只读用户）分别登录：
  - 分组标题为“销售、营销、活动、库存、服务、分析、设置”。
  - 菜单项及其顺序与该角色的权限完全一致；管理员 20 项，经理 18 项，销售和只读各 17 项。
  - 导航中没有“通知中心”。
- **逐个点击每个菜单**：
  - 地址正确，对应菜单高亮；
  - 页面主体已渲染，不是错误页；
  - 全程没有未捕获的页面错误、控制台错误或 404 请求。
- **铃铛入口**：通过“查看全部通知”进入通知中心，此时不高亮任何菜单。
- **原有的工单评论 E2E**：改为通过铃铛进入通知中心，与用户的实际操作一致，3/3 通过。

结果：**7/7 通过**（导航 4 + 工单评论 3）。
