# 角色权限（RBAC）与演示账号一键登录 — 三轮测试记录

迁移：`20261110232938_user_roles`（`user_role` 枚举、`users.role`、`users.is_demo`；已有用户设为系统管理员，避免升级后无人可管理）

## 权限矩阵（服务端强制，角色每个请求从数据库读取）
| 权限 | 系统管理员 ADMIN | 销售经理 MANAGER | 销售代表 SALES | 只读用户 READONLY |
|---|---|---|---|---|
| 查看线索/客户/商机/跟进 | 全部 | 全部 | 仅自己负责的 | 全部 |
| 新建 | ✓ | ✓ | ✓ | ✗ |
| 编辑 | 全部 | 全部 | 仅自己负责的 | ✗ |
| 删除 | ✓ | ✓ | ✗ | ✗ |
| 线索转化 | ✓ | ✓ | 仅自己的线索 | ✗ |
| 指派负责人给他人 | ✓ | ✓ | ✗ | ✗ |
| 审计日志 | ✓ | ✗ | ✗ | ✗ |
| 用户管理 | ✓ | ✗ | ✗ | ✗ |

- 可见范围同时作用于列表、详情、关联校验（跟进/商机/转化只能关联可见记录）、工作台统计、商机金额合计、全局搜索；与筛选条件以 AND 组合，无法用 `ownerId` 参数绕过。
- 联系人属于客户资料：能编辑客户即可管理其联系人。
- 不可见记录一律 404（不泄露存在性）；可见但无权操作返回 403。
- 用户管理：不能修改自己的角色或停用自己；组织至少保留一名启用中的管理员（事务内 `FOR UPDATE` 锁定管理员行防并发）；停用与重置密码立即注销该用户全部会话；全部操作写审计（邮箱打码、不记密码）。

## 演示账号一键登录
- `GET /api/auth/demo-accounts`、`POST /api/auth/demo-login`：仅 `DEMO_LOGIN_ENABLED=1` 时可用，默认关闭（未开启时两个接口均 404）。
- 只允许 `is_demo=true` 且启用中的账号；不涉及、不暴露任何密码（演示账号密码随机生成且不输出）；登录写审计 `auth.demo_login`；演示账号权限与其角色完全一致。
- 种子：`npm run db:seed-demo` 创建独立组织“演示企业（演示数据）”、5 个演示账号（林管理/郑经理/王芳/陈静/周会计）与标注【演示】的业务数据。

### 失败与修复
| 现象 | 原因 | 修复 |
|---|---|---|
| 回归中 6 个原有 E2E 失败：`getByRole('button', { name: /登\s*录/ }) resolved to 6 elements` | 登录页新增的演示账号“登录 王芳”等按钮也匹配原登录辅助函数的宽松选择器；客户用例通过只是因为演示列表尚未加载完（时序巧合） | 登录按钮选择器改为整词匹配 `/^登\s*录$/`，重新执行回归全部通过 |
| 第 3 次回归：“系统管理员管理用户”超时，下拉选项遮挡“保存”按钮（同一用例前两次均通过） | 在 antd 下拉展开动画期间点击选项被忽略，下拉未关闭（测试点击过快导致的偶发问题，非应用缺陷） | 新增 `selectOption()` 辅助函数：选择后确认已选中且下拉关闭，否则自动重试；单独连续执行 3 次均通过，第 4 次完整回归通过 |
| 本地目视检查：窄窗口下右上角用户名被拆成两行 | 用户菜单未禁止换行 | 用户菜单加 `white-space: nowrap`（此后重新执行完整回归） |
| 开发中：原审计 R2 用例把 `entityType=user` 当作非法参数 | 本次新增了“用户”审计对象，该值变为合法 | 用例改用真正非法的 `session` |

## 剩余风险
- 客户详情中的“商机数”统计包含他人负责的商机数量（商机列表本身已按可见范围过滤）。
- 固定四种角色，暂不支持自定义角色、团队/上下级可见范围、字段级权限。
- `DEMO_LOGIN_ENABLED` 若在生产环境误开启，任何人都可登录演示账号（仅限演示组织数据）；部署清单需检查此项。
- 尚未启用 PostgreSQL RLS 作为纵深防御（ADR-005）。
