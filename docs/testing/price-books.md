# 价格表 — 三轮测试记录

日期：2026-11-17　环境：同 [leads.md](leads.md)　参考：Zoho CRM 库存模块 Price Books
迁移：`20261117190000_price_books`
- 新表：`price_books`、`price_book_entries`（产品价格）、`price_book_tiers`（数量阶梯）。
- 新枚举：`price_book_pricing_model`（固定价 FLAT、阶梯价 DIFFERENTIAL）。
- 新列：
  - `accounts.price_book_id`：客户默认价格表，组织内复合外键。
  - `deal_line_items.price_book_name`：价格来源快照。
- 外键：
  - 产品价格、阶梯随价格表删除；产品价格随产品删除。
  - 客户引用为 NO ACTION，删除价格表时由服务端在同一事务内先清除。
- 手工约束：
  - 价格表名称在组织内唯一，不区分大小写，且不能为空白；币种为 3 位代码。
  - 价格不能为负。
  - 阶梯起始数量为正，截止数量不小于起始数量，折扣在 0–100 之间。

## 功能
- **权限**：
  - 所有用户都可以查看价格表，因为添加商机明细时要用。
  - 新建、修改、删除、维护产品价格、指定客户需要 `product.manage`，即管理员和经理。
  - 客户接口不接受 `priceBookId`，销售代表不能给自己的客户指定更低的价格表。
  - 销售代表添加明细时仍可以手工改价或选择其他价格表，与原来可以手工改单价一致；价格表控制的是默认价格。
- **导航**：“库存”组按 Zoho 的顺序：产品、**价格表**、报价单、销售订单、采购单、发票、供应商。
- **价格表**：
  - 字段：名称、币种、定价方式、说明、启用状态。
  - 阶梯价：按数量区间设置折扣。区间不能重叠，只有最后一档可以不封顶；输入不要求按顺序，服务端会排序并校验。
  - 已有产品价格的价格表不能改币种。
  - 改为固定价时清除阶梯；改为阶梯价时必须有阶梯。
- **产品价格**：
  - 只能添加与价格表同币种、已启用的产品；同一产品重复设置即为修改。
  - 并发设置同一产品时使用 `INSERT … ON CONFLICT`，只会保留一条。
  - 详情中显示目录价和相对目录价的百分比。
- **适用客户**：
  - 每个客户只能有一个默认价格表，指定新的会替换原有的，审计中记录被替换的价格表。
  - 停用的价格表不能指定给客户。
  - 价格表详情只列出当前用户可见的客户。
  - 客户详情显示“价格表”，并可点击进入。
- **商机明细取价**：
  - 选择价格表（默认为客户的默认价格表，也可以手工指定或选“不用价格表”）、产品、数量后，服务端返回价格（预览接口 `GET /api/deals/:id/price`），自动填入单价和折扣，并显示价格来源。
  - 用户可以修改单价和折扣，只提交用户改过的字段，未改动的由服务端按同一规则取价。
  - 来自价格表的明细保存价格表名称快照，明细表中以标签显示；手工改过单价的明细不记为价格表价。
  - 以下情况取产品目录价：客户默认价格表不存在、已停用、币种不同，或价格表中没有该产品。
  - 手工指定价格表时，不存在、已停用、币种不同、没有该产品都返回 400。
  - 报价单、销售订单、发票从商机明细复制价格，因此沿用价格表价。删除价格表或修改价格不影响已有明细。
- **回收站**：恢复客户时，如果其默认价格表已删除则置空，并在恢复结果中提示“默认价格表（已删除）”。
- **审计**：
  - 记录价格表的新建、修改、删除，以及设置价格、移除价格、指定客户、取消指定。说明只记“已修改”；阶梯以文本记录，如 `10-49.99:5%`。
  - 添加商机明细的审计中包含价格表名称。
  - 审计日志页可以按“价格表”筛选。
- **演示数据**：
  - 北美经销商价格表（美元，固定价，目录价的 88%，指定给王芳的两个客户）。
  - 国内批量阶梯价（人民币，10 件起 5%，50 件起 10%，指定给经理的两个客户）。
  - 已停用的旧版欧洲价格表。
- **界面交互修正**：添加明细时，选择产品后单价仍会自动带出（产品目录原有行为，产品 E2E 依赖它），现在带出的是价格表价。
- **不做**：价格表有效期、按联系人或供应商指定、价格表导入导出、按价格表批量重算已有明细。

## 第一轮：功能测试
命令：`npx vitest run tests/price-books/price-books.r1-functional.test.ts`
结果：**6/6 通过（首次即通过）**。原始输出：[results/price-books-r1-functional.txt](results/price-books-r1-functional.txt)

覆盖：
- **维护**：
  - 新建；同名（含首尾空格、大小写不同）返回 409；6 类非法参数返回 400。
  - 阶梯规则：固定价带阶梯、阶梯价无阶梯、截止小于起始、非最后一档不封顶、区间重叠（含未排序输入）。
  - 新建审计（说明打码，阶梯文本）；修改名称、停用的审计；改名重复返回 409。
  - 改为阶梯价必须带阶梯，并记录阶梯前后变化；只改说明时沿用阶梯；改回固定价清除阶梯。
  - 无产品价格时可以改币种，有产品价格后返回 409。
  - 按启用状态、币种、关键词筛选；列表中的产品数和客户数正确。
- **产品价格**：
  - 设置与修改；价格相同时不重复写审计；详情显示目录价。
  - 币种不同、已停用、产品不存在返回 400；3 类非法价格返回 400。
  - 移除价格；重复移除返回 404。
- **适用客户**：
  - 指定后客户详情显示价格表；重复指定不产生审计；指定另一张即替换，审计记录被替换的价格表。
  - 取消指定（未指定给该价格表时返回 404）。
  - 停用的价格表不能指定；客户不存在返回 400。
  - 删除价格表会清除 2 个客户上的指定、删除产品价格，审计记录产品数和客户数。
- **取价**：
  - 客户默认固定价；不在表中的产品取目录价；手工单价不算价格表价；手工折扣仍用价格表单价；不用价格表时取目录价。
  - 阶梯边界：9.99 件 0%，10 件 5%，49.99 件 5%，50 件 10%，1000 件 10%；各行金额精确到分。
  - 指定价格表的 4 种错误。
  - 默认价格表停用后取目录价；美元商机不使用人民币价格表。
- **预览与报价单**：预览结果与实际添加一致，不写数据；数量为 0 返回 400；报价单复制价格表价和折扣；删除价格表后已有明细不变。
- **演示数据**：价格表名称、启用状态、阶梯、适用客户数正确；产品价格等于目录价乘以比例；可以重复重置。

## 第二轮：集成测试
命令：`npx vitest run tests/price-books/price-books.r2-integration.test.ts`
结果：**6/6 通过（第二次运行通过，首次失败见下表）**。原始输出：[results/price-books-r2-integration.txt](results/price-books-r2-integration.txt)

覆盖：
- 销售代表、只读用户可以查看列表和详情，7 类写操作都返回 403，数据不变；经理可以维护，审计数量正确。
- 客户新建、修改带 `priceBookId` 返回 400。
- 价格表详情只列出销售代表自己可见的客户。
- 销售代表为自己的商机添加产品时，按客户价格表取价。
- 预览要求商机可见（销售代表看别人的商机返回 404，只读用户可以预览）；只读用户不能添加明细。
- 跨组织隔离：
  - 查看、修改、设置价格、指定客户都返回 404；价格表名称只在组织内唯一。
  - 不能引用其他组织的产品、客户；其他组织的商机不能使用本组织的价格表。
  - 在数据库层面，复合外键也会拒绝跨组织引用。
- 回收站：价格表仍在时恢复客户保留默认价格表；价格表已删除时置空并提示。
- 删除产品时，其价格表价格随之删除；有商机明细的产品仍不能删除。
- 5 个并发请求设置同一产品价格，全部成功且只保留一条；审计日志接口可以按价格表和操作筛选。

另外，产品、商机、报价单、回收站、权限、多语言、审计、客户相关测试共 298/298 通过（含本功能 12 项）。

### 失败与修复
| 现象 | 原因 | 修复 |
|---|---|---|
| R2 首次 1 项失败（[首次输出](results/price-books-r2-integration-first-run-failed.txt)） | 测试代码错误：审计条数算错了。初始化写 2 条（新建、设置价格），经理再写 3 条，应为 5 条，测试写成了 6 条 | 改正预期并注明来源；重新运行 6/6 通过 |
| 新 E2E：明细没有显示价格来源标签，数据库中 `price_book_name` 为空 | **缺陷**：界面用 `isFieldTouched` 判断用户是否改过单价，但当前表单库中 `setFieldsValue` 也会把字段标记为已改动，自动填入的价格因此被当作手工价格提交 | 改为在表单 `onValuesChange` 中记录用户改动（只由用户输入触发），换产品、换价格表、添加后重置；产品 E2E 和价格表 E2E 均通过 |
| 新 E2E：点击侧栏“商机”被遮挡 | 测试流程错误：通过 `/accounts?id=…` 打开的客户详情抽屉仍然开着，遮罩挡住了侧栏 | 改为直接打开商机页 |
| 新 E2E：“编辑”按钮匹配到 2 个 | 测试定位过宽：产品价格行也有编辑按钮 | 编辑、删除限定在抽屉右上角的操作区 |
