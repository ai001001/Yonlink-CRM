# 供应商与采购单 — 三轮测试记录

日期：2026-11-17　环境：同 [leads.md](leads.md)　参考：Zoho CRM 库存模块 Vendors、Purchase Orders
迁移：`20261117150000_vendors_purchase_orders`
- 新表：`vendors`、`purchase_orders`、`purchase_order_line_items`、`document_counters`（通用单据编号计数器）。
- 新枚举：`purchase_order_status`。
- 外键：供应商为 RESTRICT；销售订单、创建人为组织内复合外键。
- 手工约束：
  - 供应商名称在组织内不区分大小写唯一。
  - 金额、税率、汇率、币种、主题合法；状态与对应时间一致。
  - 明细数量为正，已收数量不超过采购数量。
  - 编号计数器的序号为正。

## 功能
- **权限**：
  - 新增“查看采购”（`purchase.read`）：管理员、经理、只读用户。
  - 新增“管理采购”（`purchase.manage`）：管理员、经理。
  - 销售代表看不到采购菜单，也不能调用采购接口（403），因为采购成本属于敏感信息。
- **导航**：“库存”组参照 Zoho 的顺序：产品、报价单、销售订单、**采购单**、发票、**供应商**。
- **供应商**：
  - 字段：名称、联系人、电话、邮箱、网站、地址、默认币种、付款条件、备注、启用状态。
  - 名称在组织内唯一，不区分大小写。
  - 已停用的供应商不能用于新采购单。
  - 有采购单的供应商不能删除，会提示改为停用。
  - 详情列出最近 20 张采购单。
  - 审计：电话、邮箱打码，地址、备注只记“已修改”。
- **采购单**：
  - 编号 PO-年份-序号，由计数器原子分配，删除后不复用。
  - 明细：可以从产品目录选择（保存产品信息快照），也可以手工填写 SKU、品名、单位；填写数量和采购单价，自动计算金额、税额、总额（四舍五入到分）。
  - 币种默认取供应商的默认币种。
  - **由销售订单生成（以销定采）**：在销售订单详情中点“生成采购单”。系统复制订单明细（采购单价为 0，需要填写），收货地址默认取销售订单的收货地址。已取消的销售订单不能生成。
  - **状态流转**：草稿 → 已下单 → 部分到货 → 已到货；草稿、尚未收货的已下单可以取消，并可填写原因；已到货、已取消为终态。
  - **下单**：要求每行采购单价大于 0（否则提示第几行未填）；下单后锁定明细，并保存当天汇率快照和折合人民币金额，缺汇率时为空并提示。
  - **修改**：草稿可以改全部内容，包括整体替换明细；已下单、部分到货只能改主题、预计到货日、收货地址、备注。修改有乐观并发控制。
  - **收货**：按行登记本次收货数量，默认填剩余未收数量，可以分多次收货；累计数量不能超过采购数量；全部收齐后变为已到货并记录到货时间。收货时锁定采购单，防止并发超收。
  - 只能删除草稿。
  - 打印页 `/print/purchase-order?id=…`，可打印或另存为 PDF 发给供应商。
- **审计**：
  - 供应商：新建、修改、删除。
  - 采购单：新建、修改、状态变更（含汇率快照）、收货（记录各行 SKU 和数量）、删除。
  - 审计日志页可以按“供应商”“采购单”筛选；补充了“汇率快照”“折合人民币”的字段名称（发票也一起受益）。
- **演示数据**：
  - 4 个虚构供应商，其中 1 个已停用、1 个使用欧元。
  - 4 张采购单：已到货、部分到货、已下单（欧元，关联第一张销售订单）、草稿。
  - 编号计数器同步。
- **不做**：采购退货、供应商对账与付款、库存数量管理、采购审批、价格表。

## 第一轮：功能测试
命令：`npx vitest run tests/purchase-orders/purchase-orders.r1-functional.test.ts`
结果：**7/7 通过（第二次运行通过，首次失败见下表）**。原始输出：[results/purchase-orders-r1-functional.txt](results/purchase-orders-r1-functional.txt)

覆盖：
- **供应商**：
  - 新建；同名（含首尾空格、大小写不同）返回 409；4 类非法参数返回 400。
  - 修改的审计打码；停用后不能用于新采购单，恢复启用后可以。
  - 有采购单时删除返回 409，没有时可以删除；详情列出采购单；按启用状态筛选。
- **采购单草稿**：
  - 目录产品与手工明细；金额 999.99、25；税额 133.25；总额 1158.24；币种默认取供应商的。
  - 编号连续，删除草稿后不复用。
  - 5 类非法明细和缺少明细返回 400；审计记录正确。
- **由销售订单生成**：复制明细和收货地址，总额为 0；下单时提示第 1 行单价为 0；填写单价后可以下单；可按销售订单筛选；已取消的订单不能生成。
- **下单与汇率快照**：人民币为 1；美元为 7.1，折合 7100；欧元缺汇率时为空。下单后改明细、税率返回 409；改主题、预计到货日可以；不能重复下单；状态值非法返回 400；审计中包含汇率快照。
- **收货**：
  - 未下单不能收货。
  - 部分收货后状态为部分到货；超收、重复行、不存在的行返回 400。
  - 部分到货的采购单不能取消。
  - 收齐后为已到货，并记录到货时间；终态不能修改；已下单的不能删除；收货审计逐行记录。
- **取消与列表**：草稿取消可带原因；已下单取消；不能下单时附带原因；部分到货不能取消；按状态、供应商、单号、供应商名搜索筛选。
- **演示数据**：供应商和采购单状态正确；金额与明细一致；汇率快照正确；已收数量不超过采购数量；关联了销售订单；计数器同步。

## 第二轮：集成测试
命令：`npx vitest run tests/purchase-orders/purchase-orders.r2-integration.test.ts`
结果：**7/7 通过（首次即通过）**。原始输出：[results/purchase-orders-r2-integration.txt](results/purchase-orders-r2-integration.txt)

覆盖：
- 销售代表对供应商、采购单的查看、新建、修改、下单都返回 403。
- 只读用户可以查看，5 类写操作都返回 403；经理可以下单、收货，审计记录操作人。
- 跨组织隔离：查看、下单、收货、删除采购单和供应商都返回 404；供应商名称只在组织内唯一；不能引用其他组织的供应商、销售订单、产品；编号按组织独立。
- 客户端提交编号、状态、汇率、总额、组织、已收数量都返回 400；修改接口不能改状态；未登录返回 401。
- 并发：
  - 8 个并发新建，编号不重复。
  - 剩余 10 件时，两人同时各收 7 件，只有一次成功，最终已收 7 件，不会超收。
  - 下单和取消同时进行，结果一致。
  - 同时修改同一张采购单，失败的一方返回 409。
  - 删除供应商和新建采购单同时进行 3 轮，都不会留下指向已删除供应商的采购单。
- 跨域预检（6 个接口）。

另外，权限、多语言、审计、销售订单相关测试共 115/115 通过。

## 第三轮：回归测试
命令：`scripts/regression.sh purchase-orders`（后台运行）
结果：**通过**（第三次运行）：lint、类型检查、97 个文件 997 项单元/集成测试、Pages 构建、生产构建、84 项 E2E 全部通过；前两次各有 1 项 E2E 失败，见下表。原始输出：[results/purchase-orders-r3-regression.txt](results/purchase-orders-r3-regression.txt)

### 失败与修复
| 现象 | 原因 | 修复 |
|---|---|---|
| 生成演示数据时报错：明细行不接受 `organizationId` | **缺陷**：新建采购单时用嵌套创建同时写入明细行，但明细通过组合外键关联采购单，Prisma 的嵌套创建不接受 `organizationId`。服务端新建采购单的代码也是同样写法，类型检查没有发现，运行时一定会失败 | 服务端和演示数据都改为先创建采购单，再批量写入明细（与修改采购单时一致） |
| 演示数据中“关联第一张销售订单”取不到 | 采购单的种子代码放在了销售订单创建之前 | 移到销售订单和发票之后 |
| R1 首次 3 项失败（[首次输出](results/purchase-orders-r1-functional-first-run-failed.txt)） | ① 测试代码错误：电话打码后的星号数量算错了（13 位应有 8 个星号）；② **缺陷**：由销售订单生成采购单时，收货地址没有默认取销售订单的地址，因为校验规则把“未填写”转成了 null，服务端无法区分“没填”和“填了空值”；③ 测试预期不一致：部分到货的采购单不能取消，服务端返回“已有收货”比“状态不允许”更准确，与同一文件中另一个用例的预期一致 | ① 改正测试；② 收货地址字段在规则后加 `.optional()`，与销售订单的写法一致；③ 统一测试预期为“已有收货”；重新运行 7/7 通过 |
| 新 E2E 首次 1 项失败：打开的不是刚生成的采购单 | 测试代码错误：销售订单详情中的采购单按创建时间倒序排列，测试却取了最后一个，拿到的是演示数据原有的那张 | 生成前先记下已有单号，生成后取新增的那一张；2/2 通过 |
| R3 首次 E2E 1 项失败：`sales-orders.spec.ts` 的状态断言匹配到 2 个元素（[首次输出](results/purchase-orders-r3-regression-first-run-failed.txt)） | 测试代码定位过宽：原测试用 `.ant-descriptions` 定位订单信息，销售订单详情新增的“采购单”区块也是同类组件，严格模式下匹配到两个元素。其余 83 项及 lint、类型检查、997 项单元/集成测试、两种构建均通过 | 订单信息区加 `data-testid="order-summary"`，测试改用该 ID 定位；重新构建后单独运行销售订单与采购单 E2E 4/4 通过，再完整重跑第三轮 |
| R3 第二次 E2E 1 项失败：侧栏折叠测试中点击图标栏弹出的“服务工单”超时（[第二次输出](results/purchase-orders-r3-regression-second-run-failed.txt)） | 测试时序不稳定，与本功能无关：悬停弹出子菜单后，点击等待动画稳定期间弹出层已开始关闭，点击落在下层表格上；该用例在侧栏功能回归和本次首轮回归中均通过。其余 83 项及其他检查全部通过 | 改为按结果重试（与 `closeDrawer` 一致）：未跳转到工单页就重新悬停并点击；单独运行通过后完整重跑第三轮 |
