# 工单 SLA 超时升级 — 三轮测试记录

日期：2026-11-16　环境：同 [leads.md](leads.md)　依赖：[服务工单](tickets.md)　参考：Zoho CRM Escalation Rules
迁移：`20261116190000_ticket_sla`
- 新表 `ticket_sla_policies`（每个组织一行；升级接收人为组织内复合外键）。
- `tickets` 新增 `due_auto`、`escalated_at`。
- 通知类型新增 `TICKET_ESCALATED`。
- CHECK：时限 1–8760 小时。
- 部分索引：未升级且有期限的工单，供升级检查使用。

## 功能
- **SLA 设置**（服务工单页右上角，需新权限 `sla.manage`，管理员、经理）：
  - 启用或停用 SLA。
  - 按优先级设置处理时限（小时），默认紧急 4、高 24、中 72、低 168。
  - 升级接收人：选填，必须是本组织的在职用户。
  - 所有登录用户都可以读取规则；修改会写审计（审计对象“SLA 规则”，只记录变化的字段）。
- **自动处理期限**：
  - 启用后，新建工单时期限留空，就按优先级自动计算，详情中标注“（按 SLA 自动）”。
  - 自动期限会随优先级修改，按创建时间重新计算。
  - 手动填写或修改的期限不会被覆盖；手动改过之后，这张工单不再自动计算。
  - 填写为空（不设期限）同样保留，不会被自动补上。
- **超时升级**：未解决（新建、处理中、等待客户）的工单超过处理期限时：
  - 标记“已升级”，并记录升级时间。
  - 通知负责人和升级接收人；两者是同一人时只通知一次；没有接收人时只通知负责人。
  - 写一条系统审计（操作人为空），记录错过的期限和通知人数。
  - 每张工单只升级一次。处理期限改到未来后，升级标记清除；之后再超时，可以再次升级。
  - 已解决、已关闭的工单不升级；停用 SLA 后也不再升级。
- **触发方式**：系统没有定时任务，升级检查在以下时机进行：
  - 任何用户读取通知或未读数（铃铛定时刷新）、工单列表、工单详情、显示“我的待处理工单”的工作台时。
  - 条件更新保证多人同时触发也不会重复升级或重复通知。
  - **局限**：如果整个组织都没人在线，就要等下一个人打开页面才会升级。要做到准时，需要在服务器上加定时任务。（已由 [SLA 定时任务](sla-scheduler.md) 解决：服务器每 5 分钟检查一次。）
- **界面**：
  - 工单列表的状态旁显示“已升级”标签；新增“只看已升级”筛选（只含未解决的工单）。
  - 详情显示升级时间；工作台“我的待处理工单”显示“已升级”标签。
  - 通知中心显示“工单 … 已超过处理期限，已升级”。
  - 审计日志可以按“超时升级”和“SLA 规则 · 修改”筛选。
- **演示数据**：开启 SLA（默认时限），升级接收人为郑经理；已逾期的演示工单在首次查看时升级。
- **不做**：
  - 定时任务、按工作日和工作时间计算时限、多级升级。
  - 升级后自动改派或提高优先级、首次响应时限。
  - 导出 CSV 中增加升级列。

## 第一轮：功能测试
命令：`npx vitest run tests/ticket-sla/ticket-sla.r1-functional.test.ts`
结果：**6/6 通过（首次即通过）**。原始输出：[results/ticket-sla-r1-functional.txt](results/ticket-sla-r1-functional.txt)

覆盖：
- 规则：未配置时返回默认值；保存；5 类非法参数和不存在的接收人返回 400；审计记录变化的字段。
- 自动期限：未启用时不自动；启用后紧急工单为 +4 小时；手动期限保留；明确填空保留；改优先级按创建时间重算；手动改期限后不再自动。
- 升级：超时工单只升级一次；已解决和未到期的不升级；负责人和接收人各收到一条通知；系统审计；未读数接口也会触发检查。
- 负责人即接收人时只通知一次；没有接收人时只通知负责人。
- 期限移到未来后清除升级（并记入审计），再次超时可以再升级；解决后不出现在“只看已升级”里；停用后不升级；非法筛选参数返回 400。
- 工作台卡片带升级时间；演示规则正确，演示数据中有可升级的工单。

## 第二轮：集成测试
命令：`npx vitest run tests/ticket-sla/ticket-sla.r2-integration.test.ts`
结果：**5/5 通过（首次即通过）**。原始输出：[results/ticket-sla-r2-integration.txt](results/ticket-sla-r2-integration.txt)

覆盖：
- 权限：销售、只读可以查看规则，修改返回 403（缺 `sla.manage`）；经理可以修改。
- 接收人不能是其他组织或已停用的用户。
- 规则和升级按组织隔离：其他组织不升级，也不自动计算期限。
- 客户端不能提交 `dueAuto`、`escalatedAt`（返回 400）；未登录返回 401。
- 并发：4 个用户刷新未读数、4 次列表读取、1 次直接检查同时进行，5 张超时工单各只升级一次；负责人和接收人各收到 5 条通知，审计 5 条；销售能筛出自己的已升级工单。
- 跨域预检。

另外，原有的工单、评论、导出、工作台卡片、通知测试共 63/63 通过（SLA 默认不启用，原有行为不变）。
