## 功能
- **设置 › 角色与权限**（需 user.manage，即系统管理员）：
  - 系统角色（系统管理员、销售经理、销售代表、只读用户）的权限按类别只读展示。
  - 自定义角色：选择基础角色（销售经理、销售代表、只读用户）后按其权限预填，再按类别勾选权限，填写名称与说明。名称组织内唯一，每组织最多 30 个。
  - 修改名称、说明、权限；基础角色建立后不可改。无人使用时可删除，使用中返回 409。
  - 新建、修改、删除写审计，修改记录增减的权限。
- **不能授予的权限**：“管理用户与角色”“管理 API 密钥与 Webhook”只属于系统管理员（否则持有者可提升自己为管理员）。界面中不能勾选，接口拒绝，数据库约束兜底。
- **分配**（用户管理）：
  - 角色下拉分为系统角色与自定义角色两组；选择自定义角色时，用户的角色自动设为其基础角色。
  - 指定的自定义角色与角色不一致时报错；只改角色时，不一致的自定义角色自动清除。
  - 系统管理员不能套用自定义角色（数据库约束兜底），不能修改自己的角色。
  - 用户审计记录自定义角色的变化。
- **生效**：
  - 有效权限 = 自定义角色的权限（只保留可授予的），没有时为系统角色的权限；系统管理员始终是全部权限。
  - 每个请求认证时从数据库读取，修改与撤销在下一个请求立即生效（不依赖缓存）；API 密钥按其用户的有效权限。
  - /api/auth/me 返回自定义角色与有效权限；顶部角色标签显示自定义角色名；菜单与按钮按有效权限显示。
- **仍按基础角色判断的场景**：报价单审批层级、流程蓝图中允许的角色、低库存提醒的接收人、“至少一名启用的系统管理员”。
- **演示数据**：“【演示】可导出的销售代表”（销售代表另加导出数据），不分配给演示账号，演示账号权限不变；重置时先清除账号上的自定义角色。
- **不做**：字段级权限（#69）、角色层级与记录共享（#70）。

命令：`npx vitest run tests/custom-roles/custom-roles.r1-functional.test.ts`
结果：**3/3 通过**（首次运行因测试引用的用户接口路径写错未能加载，见下方）。原始输出：[results/custom-roles-r1-functional.txt](results/custom-roles-r1-functional.txt)

覆盖：
- **维护**：系统角色与可授予目录（含导出、不含用户与集成管理）；经理、销售不能读取或维护；6 类非法新建（空名、基础角色为管理员、未知权限、用户管理、集成管理、重复权限）与同名；修改权限并审计增减；基础角色不可改；上限 30 个。
- **分配与生效**：基础角色不一致、改为管理员并套用、修改自己、不存在的角色均被拒绝；销售原本不能导出，套用可导出角色后 /me 含导出且导出成功；撤销后立即 403；只读角色去掉采购查看；只改角色时清除不一致的自定义角色并获得新角色的系统权限；新建用户时指定；授予“查看全部记录”的销售看到他人的客户；用户审计记录自定义角色。
- **删除**：使用中 409，清除后可删，再删 404。
