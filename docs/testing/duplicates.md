# 重复记录检测与合并 — 三轮测试记录

日期：2026-11-14　环境：同 [leads.md](leads.md)　参考：Zoho CRM Deduplication
迁移：无（复用已有表与回收站）

## 功能
- 左侧导航新增“查重合并”：切换线索 / 客户，列出疑似重复的记录组，组内显示匹配依据、负责人、相关数据数量与创建时间（最早的在前，默认作为主记录）。
- 检测规则（满足任一即归为同组，可传递）：
  - 线索：邮箱相同（不区分大小写）；电话或手机相同（只比较数字、取后 11 位，兼容 +86 等前缀，电话与手机可交叉匹配）；姓名 + 公司相同（忽略大小写与空白）。
  - 客户：名称相同（忽略大小写、空白与中英文标点）；电话相同；网站域名相同（忽略协议、www、端口与路径）。
  - 遵循可见范围（销售代表只在自己负责的记录中查找）；每次最多检查 20000 条。
- 合并（管理员、经理，需删除权限且能编辑主记录）：选择主记录，逐字段选择保留值（主记录为空时默认取第一条有值的记录）；改负责人需指派权限。
  - 线索：备注、跟进、附件、标签转到主记录。
  - 客户：联系人（主客户已有主要联系人时转入的不再是主要联系人）、商机、备注、跟进、附件、标签、转化来源线索转到主记录。
  - 被合并的记录移入回收站（相关数据已转移，恢复只找回记录本身）；已转化的线索不能合并；合并后标签超过 20 个时拒绝；一次最多 10 条。
  - 全部在一个事务内完成，任何检查失败都不改动数据；审计 `lead/account.merge`（合并了哪些记录、字段变化、转移数量），被合并记录的删除审计标记 `mergedInto`。
- 中英文文案；审计日志筛选新增“合并”，审计详情显示被合并的记录名称。
- 演示数据：2 条重复线索（邮箱大小写不同且电话格式不同；姓名与公司相同）、1 条重复客户（名称只差空格与标点、网站带路径），在原始数据之后写入，不影响其他样本。
- 不做：模糊相似度匹配（错别字等）、联系人查重、自动合并。

## 第一轮：功能测试
命令：`npx vitest run tests/duplicates/duplicates.r1-functional.test.ts --reporter=verbose`
结果：**8/8 通过**（修正测试数据后重新执行）。原始输出：[results/duplicates-r1-functional.txt](results/duplicates-r1-functional.txt)；首次失败输出：[results/duplicates-r1-functional-first-run-failed.txt](results/duplicates-r1-functional-first-run-failed.txt)
覆盖：匹配键规范化（电话、域名、名称）；分组可传递并列出全部依据；线索分组（邮箱、电话与手机交叉、姓名+公司）；客户分组（名称、网站、电话）；合并线索（备注、跟进、附件、标签转移，字段选择，回收站与审计）；合并客户（主要联系人规则、商机、转化来源线索、负责人字段）；从回收站恢复被合并记录只找回记录本身；演示重复记录能被找到。

## 第二轮：集成测试
命令：`npx vitest run tests/duplicates/duplicates.r2-integration.test.ts --reporter=verbose`
结果：**15/15 通过（首次即通过；消除一处 lint 警告后重新执行，结果相同）**。原始输出：[results/duplicates-r2-integration.txt](results/duplicates-r2-integration.txt)
覆盖：查重遵循可见范围；合并需删除权限（销售、只读 403，经理可以）；跨组织或类型不符的记录 404 且整体不变；已转化线索 409 且不变；标签上限 400 且不变；同一记录并发合并到两个主记录只成功一次、备注只去一处；8 类非法合并参数（含客户端提交 organizationId、超过 10 条）；非法查重参数与未登录。

## 第三轮：回归测试
命令：`scripts/regression.sh duplicates`（后台运行，逐阶段汇报）
结果：**PASS（第三次运行通过，前两次失败见下表）**——lint 15s、typecheck 7s、Vitest **740/740**（171s）、静态导出 56s、生产构建 49s、E2E **40/40**（366s）。原始输出：[results/duplicates-r3-regression.txt](results/duplicates-r3-regression.txt)

### 失败与修复
| 现象 | 原因 | 修复 |
|---|---|---|
| R1：合并客户用例返回 400 | 测试数据问题：新建客户接口不接受直接附带联系人，主客户未创建成功 | 先建客户，再通过联系人接口添加主要联系人 |
| 演示数据重建日志客户数未包含重复客户 | 日志文字遗漏 | 改为“31 客户（含 1 条重复）” |
| R3 首次：既有演示数据测试 5 项失败（[首次失败输出](results/duplicates-r3-regression-first-run-failed.txt)） | 新增的演示重复记录违反了既有演示数据约定：数量断言未包含重复记录；重复客户没有联系人（约定每个客户至少 2 位联系人、恰 1 位主要联系人）；重复线索的大写邮箱不符合区分大小写的保留域名检查 | 重复客户补录同样的前两位联系人（带【演示】前缀与保留域名邮箱，第一位为主要联系人）；数量断言显式加上重复记录；域名检查改为不区分大小写；停止该次回归并完整重跑 |
| R3 第二次：RBAC E2E 按名称找到两行（[第二次失败输出](results/duplicates-r3-regression-second-run-failed.txt)） | 演示重复线索 A 复制了第 1 条线索，而它正是 E2E 使用的“王芳的线索”样本 | 改为复制非样本线索（第 11 条），并在生成函数中检查源记录不得是 E2E 样本；单独运行演示数据、查重测试（40/40）与 RBAC、查重 E2E（4/4）通过后完整重跑 |
