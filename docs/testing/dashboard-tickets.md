# 工作台“我的待处理工单”卡片 — 三轮测试记录

日期：2026-11-16　环境：同 [leads.md](leads.md)　依赖：[服务工单](tickets.md)、[工作台自定义](dashboard-layout.md)
迁移：无（只新增工作台卡片键 `myTickets`）

## 功能
- 新卡片“我的待处理工单”：列出负责人是我、且未解决（新建、处理中、等待客户）的工单。
  - 排序：先按优先级（紧急在前），再按处理期限（早的在前，没有期限的排最后）。最多列 10 条。
  - 顶部显示“未解决 N 项，已逾期 M 项”。
  - 每条显示优先级、主题（点击打开工单详情）、逾期标记、工单号、状态、客户、处理期限。
  - “查看全部”跳到服务工单页。
- 卡片只列“我负责的”：经理和管理员虽然能查看全部工单，这张卡片里也只有自己负责的。工单改派后，会从原负责人的卡片移到新负责人的卡片。
- 布局：
  - 默认布局里排在“我的待办”之后；没有保存过布局的用户直接看到。
  - 已经保存过自定义布局的用户，不会被自动加入新卡片（尊重已有选择），可以在“自定义工作台”里勾选。
  - 隐藏这张卡片时，服务端不查询工单。
- 演示数据：演示工单的负责人改为在王芳、郑经理、陈静之间轮换，每张工单关联的客户属于同一负责人，三位都有未解决工单。原来 10 张工单全部归王芳。
- 不做：工单数量统计图、按团队查看、卡片内直接改状态。

结果：**4/4 通过（首次即通过）**。原始输出：[results/dashboard-tickets-r1-functional.txt](results/dashboard-tickets-r1-functional.txt)

覆盖：
- 默认布局含该卡片，且位于“我的待办”之后；没有工单时卡片为空。
- 只含我负责的未解决工单：已解决、已关闭和同事的工单都不出现；同事的工单出现在同事的卡片里。
- 排序：紧急 → 高（已逾期 → 后天 → 无期限）→ 低。逾期计数、客户与工单号字段正确。
- 工单解决后移出卡片，重新打开后回到卡片；最多 10 条，总数照常计算；卡片隐藏时返回 null。
- 演示数据：三位负责人都有未解决工单，客户都归负责人本人。
