# 跟进日历视图 — 三轮测试记录

日期：2026-11-12　环境：同 [leads.md](leads.md)　参考：Zoho CRM Calendar（Activities 按日/周/月查看与拖动改期）
迁移：无（使用已有的 activities.due_at）

## 功能
- 跟进页右上角新增“列表 / 日历”切换；日历支持月视图（周一起始的 6 周网格）与周视图，“今天”、上一页/下一页。
- 每天显示当天到期的跟进：时间 + 主题，左侧色条区分类型（电话/会议/客户拜访/任务），已完成划线、逾期浅红底；月视图每格最多 3 条，其余显示“还有 N 项”。
- 点击日期显示当天跟进列表，可“在这一天新建”（截止时间默认当天 09:00）；点击跟进打开详情，详情中可“标记完成 / 重新打开”和编辑。
- 拖动跟进到其他日期即改期，保留原时间点；没有编辑权限的跟进不能拖动（只读用户、销售代表对他人的跟进）。
- 筛选：全部/未完成/已完成、类型、负责人（经理/管理员/只读可选）。没有截止时间的跟进不在日历中显示（页面注明）。
- 接口：`GET /api/activities/calendar?from=&to=&type=&completed=&ownerId=`，按截止时间 [from, to) 返回，最长 43 天（6 周 + 1 天夏令时余量），最多 1000 条，超出时返回 `truncated` 并在页面提示。改期使用已有的 `PATCH /api/activities/:id`（同样的权限、校验与审计）。
- 日期按浏览器本地时区显示与分组。
- 演示数据：跟进截止时间分布在北京时间 09:00–17:30（之前统一为 UTC 10:00，即北京时间 18:00）。

覆盖：半开区间边界（含开始、不含结束，带时区偏移）、排除无截止时间、升序；类型/完成状态/负责人筛选；超过 1000 条截断标记；改期保留时间点并写审计；周一起始、月视图 42 天（含 2 月从周一开始的情况）、周视图 7 天；演示数据当月有跟进且含逾期。

### 失败与修复
| 现象 | 原因 | 修复 |
|---|---|---|
| 开发阶段 E2E：拖动超时 | 测试脚本：点击日期格中心选中当天时点到了跟进条目，打开了详情抽屉，遮罩挡住拖动 | 改为点击日期格左上角的日期区域 |
| 开发阶段 E2E：找不到“截止时间”“拜访”“今天” | 测试脚本：字段实际为“截止/计划时间”，选项为“客户拜访”；antd 两字按钮显示为“今 天”；“类型”同时匹配到隐藏的新建表单 | 修正文字与正则，并把类型筛选限定在日历区域 |
| 本地预览：所有演示跟进都在 10:00（北京时间实为 18:00） | 演示数据截止时间统一为 UTC 10:00 | 分布在北京时间 09:00–17:30 |
