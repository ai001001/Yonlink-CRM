# 英文界面（中英文切换）— 三轮测试记录

日期：2026-11-13　环境：同 [leads.md](leads.md)
迁移：无

## 功能
- 语言：简体中文（默认，中文优先）与英文。顶部栏与登录页右上角新增“中文 / English”切换；选择保存在浏览器（`yonlink-crm.locale`），切换后刷新页面使菜单、选项等模块级文案一并更新。
- 文案：新增 `src/i18n/en-US.ts`，类型为 `Record<MessageKey, string>`——缺少任何中文已有的 key 都会编译失败；新增语言只需再加一个同结构文件。
- Ant Design 组件语言包（en_US / zh_CN）与 dayjs 语言随当前语言切换；`<html lang>` 与页面标题随语言设置。
- 界面中硬编码的全角标点（冒号、顿号、分号、括号）与产品默认单位“件”改为文案 key（英文为 `: `、`, `、`; `、` (…)`、`pcs`）。
- CSV：导出与导入模板接受 `lang` 参数，表头、枚举文字、时间列后缀、模板示例行按语言输出；导入识别任一语言的列名与字段名、任一语言的枚举标签与代码（英文不区分大小写）；缺失列提示按请求语言显示。默认行为（中文）不变。
- 预渲染：服务端与静态导出始终为默认语言；登录页改为挂载后渲染，避免预渲染中文与浏览器英文不一致导致水合错误；业务页面本来就在登录校验完成后才渲染。
- 不做：服务端 API 错误码的开发者说明（界面按错误码显示翻译后的文字）、演示数据内容（虚构中文业务数据）、用户级语言偏好同步到服务器（目前按浏览器保存）。

### 失败与修复
| 现象 | 原因 | 修复 |
|---|---|---|
| 开发阶段 E2E：切换英文后页面标题仍为中文 | 根布局通过 Next 元数据设置标题，框架在客户端设置之后再次写入元数据标题 | 元数据不再设置标题（只保留应用名），标题由客户端按当前语言设置（业务页面均需登录，无需预渲染标题） |
| 写入英文文案文件时被写入检查拦截 | 已知的过期检查：认为会话在已删除的隔离副本中（`git worktree list` 确认只有主目录） | 与之前相同，改用 shell 写入主目录 |
