# 市场活动 — 三轮测试记录

日期：2026-11-15　环境：同 [leads.md](leads.md)　参考：Zoho CRM Campaigns
迁移：`20261115120000_campaigns`（新表 `campaigns`，枚举 `campaign_type`、`campaign_status`；`leads`、`deals` 新增 `campaign_id`（组织内复合外键，不级联）；CHECK：预算与花费非负、结束不早于开始、币种代码；组织内活动名称唯一）

## 功能
- 左侧导航新增“市场活动”（位于“线索”之后）：名称、类型（展会、广告、邮件营销、线上研讨会、社交媒体、其他）、状态（计划中、进行中、已完成、已取消）、起止日期、币种、预算、实际花费、负责人、说明。
- 列表：搜索（名称、说明）、按类型与状态筛选；显示线索数 / 已转化、商机数 / 赢单数、赢单金额（折合人民币）、投入产出比。
- 详情：线索数、转化率、在手金额、赢单金额、花费（均折合人民币）、投入产出比 =（赢单金额 − 实际花费）÷ 实际花费；缺少汇率的币种列出且不计入；最近关联的 20 条线索与 20 个商机（可跳转）。
- 线索、商机表单新增“来源市场活动”（不列已取消的活动，但保留当前值），详情显示并可跳转活动；线索、商机列表可按活动筛选，导出遵循该筛选。
- 线索转化时，新建的商机沿用线索的来源活动。
- 权限：所有人可查看；新建、修改、删除需新权限 `campaign.manage`（管理员、经理）；把线索、商机关联到活动按原记录编辑权限；关联的活动必须属于本组织。
- 统计遵循可见范围（销售代表只统计、只列出自己负责的线索与商机）；删除限制按全部记录计算：有关联线索或商机的活动不能删除（提示改为“已取消”）。
- 回收站恢复线索、商机时，若来源活动已被删除则清空该关联并提示“部分未恢复：来源市场活动”。
- 审计：活动新建、修改、删除（审计对象“市场活动”）；线索、商机的来源活动变化随其修改审计。
- 演示数据：4 个活动（汽配展已完成、广告与海外社媒进行中、研讨会计划中）；展会、广告、社交媒体来源的线索关联相应活动，展会线索转化的商机同样关联。
- 不做：活动成员与邮件群发、审批、父子活动、多点归因。

覆盖：新建（默认值、统计初值）、同名 409、日期颠倒 400、修改与审计；列表搜索与按类型、状态筛选；选项排除已取消（include 当前值时保留）；有关联不能删除、无关联可删除并审计；线索与商机关联、按活动筛选、转化继承；统计（线索、转化率、商机、在手、赢单、美元花费折算、欧元缺汇率不计、投入产出比 42.9%）；关联他组织活动 400、修改与清除关联的审计；回收站恢复时清空已删除活动；演示活动与关联一致。

### 失败与修复
| 现象 | 原因 | 修复 |
|---|---|---|
| 活动模块与商机模块可能循环引用（开发中自查） | 活动模块引用商机模块的金额、日期规则，商机模块又需要校验活动 | 把“校验活动属于本组织”拆到独立的 `campaign-links.ts` |
| E2E 首次 1 项失败：元素重复 | 页面上统计卡片与关联线索表格使用了相同的测试标识 `campaign-leads` | 关联表格改为 `campaign-linked-leads` / `campaign-linked-deals` |
| R3 首次：既有“商机完整业务流程”E2E 1 项失败（[首次失败输出](results/campaigns-r3-regression-first-run-failed.txt)；其余 58/59 通过，Vitest 888/888） | 截图显示“关联客户”未选上：与工作台 E2E 相同，下拉展开动画期间的点击被忽略（该处为输入后直接点击，无重试）。本次未改动客户选择框 | 新增 E2E 辅助函数 `pickRecord`（按结果重试，与已在 CI 验证的写法一致），商机、跟进、工作台三处记录选择统一改用；三个文件单独运行通过后完整重跑第三轮 |
