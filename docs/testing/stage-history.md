## 功能
- **阶段历史页签**（商机详情）：最新在前；阶段（阶段变化的行蓝色、赢单绿、输单红，当前行标“当前”）、金额、可能性、预期收入、预计成交日、停留时长、修改人（系统写入显示“系统”）、修改时间。
  - 停留时长 = 到下一条的时间；当前行为进行中阶段时计到现在；赢单、输单不计。
  - 可能性按阶段固定，与销售预测一致：资格确认 10%、需求分析 20%、方案报价 40%、商务谈判 70%、赢单 100%、输单 0%；预期收入 = 金额 × 可能性。
  - 可见范围与商机一致（销售代表看不到别人的商机，返回 404）。
- **回收站**：删除商机时历史放入快照，恢复后原样还原（替换触发器在恢复时写入的新建行）；旧快照没有历史时保留恢复时写入的一行。
- **阶段停留时长报表**（报表页卡片，`/api/reports/stage-duration`）：
  - 连续相同阶段的历史合并为一段“停留”。
  - 每个进行中阶段：时间段内开始且已结束的停留的平均天数与次数；目前处于该阶段的商机数与已停留平均天数（不受时间段影响）。
  - 成交周期：首条历史到进入赢单/输单的平均天数（进入时间在时间段内）。
  - 遵循可见范围，可按负责人筛选，与报表页共用时间段与负责人；所有币种一起统计。
- **演示数据**：每个演示商机按编号确定推进路径——进行中商机从资格确认推进到当前阶段；赢单商机走完四个阶段后在预计成交日赢单；输单商机推进 1–3 个阶段后输单；修改人为商机负责人。
- **不做**：阶段停留时长不进入报表导出（CSV/Excel）；不支持自定义阶段可能性；回收站以外的删除（如组织删除）不保留历史。

### 失败与修复
| 现象 | 原因 | 修复 |
|---|---|---|
| R1 首次 1 项失败（[首次输出](results/stage-history-r1-first-run-failed.txt)） | 测试假设错误：非法 ID 预期 400，项目约定为 404（`routeId` 对非 UUID 返回 404，与其他接口一致） | 改为预期 404；6/6 通过 |
| R2 首次 1 项失败（[失败输出](results/stage-history-r2-first-run-failed.txt)）：并发修改后出现相邻两行阶段相同 | **真实缺陷**：触发器用 `now()`（事务开始时间）记录变化时间；并发时先开始、后提交的事务得到更早的时间，历史顺序与实际不符，停留时长也会算错 | 新增迁移，改用 `clock_timestamp()`（触发器在取得行锁后执行）；修复后连续 8 次通过；在测试库临时换回 `now()` 时 6 次失败 5 次，确认测试能发现该缺陷 |
| 新 E2E 首次 1 项失败 | 测试假设错误：商机列表的名称不是链接 | 改为通过接口取一个演示赢单商机，用 `?id=` 打开详情；2/2 通过 |
