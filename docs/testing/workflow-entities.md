## 功能
- **客户的工作流**：
  - 触发：新建时、编辑时、新建或编辑时、字段变化时（行业、负责人、区域）、相对日期（创建日）、无跟进（按客户的跟进记录）。
  - 条件字段：行业、名称、电话、网站、地址、描述、评分、负责人、区域。
  - 动作：更新字段（行业）、指派负责人、创建任务（关联客户）、通知、加标签、调用 Webhook（负载为 ID、名称、行业、负责人、区域、评分，不含电话等个人信息）。
- **服务工单的工作流**：
  - 触发：新建时、编辑时、新建或编辑时、字段变化时（状态、优先级、负责人）、相对日期（处理期限或创建日）；工单没有跟进记录，不能用“无跟进”。
  - 条件字段：状态、优先级、类型、渠道、主题、描述、负责人、客户。
  - 动作：更新字段（状态只能改为新建、处理中、等待客户——已解决与已关闭需要处理结果；优先级）、指派负责人、创建任务（跟进没有工单字段，关联工单所属客户）、通知（关联工单）、调用 Webhook；不能加标签（工单没有标签）。
  - 工单改回未完成状态时同时清除解决时间（满足原有约束）。通知与审计中工单以“编号 主题”作为名称。
- **触发来源**：客户的新建与编辑；工单的新建与编辑，以及客户在门户中新建的工单（没有操作人）。导入客户不触发（与线索导入一致）。
- 其余规则不变：在触发写入的同一事务内执行，工作流做出的改动不会再次触发，接口返回工作流修改后的记录。
- **界面**：工作流规则页的对象增加“客户”“服务工单”；字段名称随对象变化（如工单的“状态”）；条件中的区域与客户用下拉选择；工单不显示“无跟进”触发与“加标签”动作。
- **其他模块**：宏、流程蓝图、销售节奏、验证规则仍只用于线索与商机（接口校验与数据库约束）。
- **演示数据**：新增“【演示】工单升为紧急：通知经理”“【演示】新客户：安排首次拜访”两条规则（共 8 条演示规则）。
- **不做**：联系人、报价单等其他对象的工作流；工作流修改工单优先级后重算 SLA 期限（期限保持不变）；门户客户回复导致的重新打开不触发编辑类规则。

### 失败与修复
| 现象 | 原因 | 修复 |
|---|---|---|
| R1 首次：工单用例 400 | 测试问题：修改工单时提交了接口不接受的 `updatedAt`（并发检查在服务端进行） | 去掉该字段 |
| R1 自查：客户用例中 Webhook 的断言实际被跳过 | 测试问题：建 Webhook 时提交了不支持的字段导致创建失败，而断言写成了“有 Webhook 时才检查” | 改为必须创建成功，断言无条件执行（随后通过） |
| R1：工单任务负责人的预期值错误 | 测试问题：通过接口新建的工单负责人默认为新建人，测试预期写成了空 | 改为新建人 |
| R3 首次：原有低库存提醒端到端用例切换账号时超时 | 测试问题（#60a 的用例）：仍登录时打开登录页，登录页跳回首页与点击竞争 | 切换前先退出，见第三轮说明 |
| R2 首次：验证规则的约束用例没有触发约束 | 测试问题：直接写入验证规则时缺少必填字段，先被 Prisma 拒绝；另有一段对空表执行更新的无效断言 | 四类记录各建一条真实的线索记录，再改为客户或工单，逐一断言对应的检查约束 |

### 测试调整说明（行为变化）
- 原有工作流测试用“工单”作为非法对象的例子，工单现已支持，改用仍不支持的“联系人”，断言不变。
- 原有工作流 E2E 统计演示规则数从 6 条改为 8 条（新增客户与工单各 1 条演示规则）。
