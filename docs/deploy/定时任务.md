# 服务器定时任务

适用：公网演示环境（`~/yonlink-deploy`）；其他环境同理。所有定时任务都是 systemd 用户定时器，不需要 sudo。

| 定时器 | 频率 | 作用 | 说明 |
|---|---|---|---|
| `yonlink-backup.timer` | 每天北京时间 03:30 | 数据库与附件备份 | 见 [备份与恢复](备份与恢复.md) |
| `yonlink-sla.timer` | 每 5 分钟 | 工单 SLA 超时升级检查 | 本文 |
| `yonlink-webhook.timer` | 每分钟 | Webhook 投递与失败重试 | 本文 |
| `yonlink-workflow.timer` | 每 15 分钟 | 定时工作流（相对日期、无跟进）与销售节奏（到期步骤、退出） | 本文 |

## 工单 SLA 超时升级检查
- 服务 `yonlink-sla.service`：在 `current` 发布目录运行 `scripts/sla-sweep.ts`，读取 `shared/app.env` 中的数据库连接。
  - 检查全部已启用 SLA 的组织：未解决、且已超过处理期限的工单标记为“已升级”，通知负责人与升级接收人，并写系统审计。
  - 每个组织单独处理，一个组织出错不影响其他组织；只要有组织出错，退出码为 1（`systemctl --user status` 显示失败），日志里列出出错的组织。
  - 可以重复运行：每张工单只升级一次。用户打开页面时也会顺带检查本组织，两者同时进行也不会重复升级或重复通知。
- 定时器 `yonlink-sla.timer`：每 5 分钟（`OnCalendar=*:0/5`，精度 30 秒）。上一次没结束时不会重复启动；关机期间错过的不补做，下次运行会一并处理。单次运行超过 2 分钟视为卡住并结束。
- 因此，超时工单最晚约 5 分钟内升级，不再依赖有人在线。
- 模板：`deploy/systemd/yonlink-sla.service`、`deploy/systemd/yonlink-sla.timer`。
- 依赖：发布目录中必须已有 `scripts/sla-sweep.ts`，所以要先部署包含该脚本的版本，再安装定时器。

安装 / 更新：
```bash
cp deploy/systemd/yonlink-sla.service deploy/systemd/yonlink-sla.timer ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now yonlink-sla.timer
```

常用命令：
```bash
systemctl --user list-timers yonlink-sla.timer       # 下次执行时间
systemctl --user start yonlink-sla.service           # 立即检查一次
journalctl --user -u yonlink-sla.service -n 20       # 最近几次结果
systemctl --user disable --now yonlink-sla.timer     # 停用定时检查（页面按需检查仍然有效）
```

日志示例：`SLA 检查完成 / SLA sweep done: 组织 1 个，升级工单 2 张，出错 0 个；用时 356ms`

## Webhook 投递
- 服务 `yonlink-webhook.service`：在 `current` 发布目录运行 `scripts/webhook-sweep.ts`，每次最多发送 200 条到期投递（含按 1、5、30、120、360 分钟退避的重试）。
  - 领取投递使用 `FOR UPDATE SKIP LOCKED` 并把下次时间推后 5 分钟作为租约，多个进程或与应用内的后台发送同时运行也不会重复领取；进程中断时，被领取的投递 5 分钟后会再次被领取。
  - 第 6 次仍失败标记为“失败”，可在“设置 › 集成”中手动重试。
- 定时器 `yonlink-webhook.timer`：每分钟（`OnCalendar=*:*:00`，精度 10 秒）；上一次没结束时不会重复启动。
- 应用在产生投递后约 2 秒也会在后台尝试发送，因此正常情况下不必等待定时器；定时器负责重试与补发。
- 模板：`deploy/systemd/yonlink-webhook.service`、`deploy/systemd/yonlink-webhook.timer`；先部署包含 `scripts/webhook-sweep.ts` 的版本，再安装定时器。

安装 / 更新：
```bash
cp deploy/systemd/yonlink-webhook.service deploy/systemd/yonlink-webhook.timer ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now yonlink-webhook.timer
```

常用命令：
```bash
systemctl --user start yonlink-webhook.service       # 立即发送一次
journalctl --user -u yonlink-webhook.service -n 20   # 最近几次结果
```

日志示例：`Webhook 投递完成 / webhook sweep done: 领取 1，成功 1，待重试 0，失败 0；用时 312ms`

## 定时工作流
- 服务 `yonlink-workflow.service`：在 `current` 发布目录运行 `scripts/workflow-sweep.ts`，检查全部组织启用的“相对日期”“无跟进”工作流规则并执行到期的动作；然后处理销售节奏：让进入退出状态或已转化的记录退出，为到期的步骤创建跟进（错过的步骤补建，每个参与只处理一次，可安全重复运行）。
  - 每条记录在独立事务内先登记执行键（规则 + 记录 + 日期值或最近跟进时间），并发运行时只有一个成功，重复运行安全。
  - 相对日期最多补做 7 天内的触发日；无跟进在下次运行时一并检查。每条规则每次最多处理 500 条记录，余下的下次继续。
  - 有规则出错时退出码为 1，日志列出出错的规则，其他规则照常处理。
- 定时器 `yonlink-workflow.timer`：每 15 分钟（`OnCalendar=*:0/15`，精度 30 秒）；上一次没结束时不会重复启动。
- 模板：`deploy/systemd/yonlink-workflow.service`、`deploy/systemd/yonlink-workflow.timer`；先部署包含 `scripts/workflow-sweep.ts` 的版本，再安装定时器。

安装 / 更新：
```bash
cp deploy/systemd/yonlink-workflow.service deploy/systemd/yonlink-workflow.timer ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now yonlink-workflow.timer
```

日志示例：`定时工作流完成 / scheduled workflows done: 规则 2 条，检查 3 条记录，执行 2 次，出错 0 条；用时 410ms`，随后一行 `销售节奏完成 / cadences done: 节奏 2 个，退出 0 个参与，处理 5 个参与，创建跟进 5 条，出错 0 个`。销售节奏复用同一个定时器，不需要新增定时器。
