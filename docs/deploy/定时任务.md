# 服务器定时任务

适用：公网演示环境（`~/yonlink-deploy`）；其他环境同理。所有定时任务都是 systemd 用户定时器，不需要 sudo。

| 定时器 | 频率 | 作用 | 说明 |
|---|---|---|---|
| `yonlink-backup.timer` | 每天北京时间 03:30 | 数据库与附件备份 | 见 [备份与恢复](备份与恢复.md) |
| `yonlink-sla.timer` | 每 5 分钟 | 工单 SLA 超时升级检查 | 本文 |

## 工单 SLA 超时升级检查
- 服务 `yonlink-sla.service`：在 `current` 发布目录运行 `scripts/sla-sweep.ts`，读取 `shared/app.env` 中的数据库连接。
  - 检查全部已启用 SLA 的组织：未解决、且已超过处理期限的工单标记为“已升级”，通知负责人与升级接收人，并写系统审计。
  - 每个组织单独处理，一个组织出错不影响其他组织；只要有组织出错，退出码为 1（`systemctl --user status` 显示失败），日志里列出出错的组织。
  - 可以重复运行：每张工单只升级一次。用户打开页面时也会顺带检查本组织，两者同时进行也不会重复升级或重复通知。
- 定时器 `yonlink-sla.timer`：每 5 分钟（`OnCalendar=*:0/5`，精度 30 秒）。上一次没结束时不会重复启动；关机期间错过的不补做，下次运行会一并处理。单次运行超过 2 分钟视为卡住并结束。
- 因此，超时工单最晚约 5 分钟内升级，不再依赖有人在线。
- 模板：`deploy/systemd/yonlink-sla.service`、`deploy/systemd/yonlink-sla.timer`。
- 依赖：发布目录中必须已有 `scripts/sla-sweep.ts`，所以要先部署包含该脚本的版本，再安装定时器。

安装 / 更新：
```bash
cp deploy/systemd/yonlink-sla.service deploy/systemd/yonlink-sla.timer ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now yonlink-sla.timer
```

常用命令：
```bash
systemctl --user list-timers yonlink-sla.timer       # 下次执行时间
systemctl --user start yonlink-sla.service           # 立即检查一次
journalctl --user -u yonlink-sla.service -n 20       # 最近几次结果
systemctl --user disable --now yonlink-sla.timer     # 停用定时检查（页面按需检查仍然有效）
```

日志示例：`SLA 检查完成 / SLA sweep done: 组织 1 个，升级工单 2 张，出错 0 个；用时 356ms`
