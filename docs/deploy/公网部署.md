## 架构
```text
浏览器 ──HTTPS──> GitHub Pages（静态前端）
   │
   └──HTTPS（Bearer 令牌，CORS 仅允许 ai001001.github.io）──> Caddy :443（Let's Encrypt 证书，自动续期）
                                                              └──> Next.js 后端 127.0.0.1:3001
                                                                     └──> PostgreSQL 127.0.0.1:54330（数据库 yonlink_mvp_demo）
```
- 域名使用 sslip.io（`132-226-98-75.sslip.io` 自动解析到服务器 IP），免费、无需注册。
- 后端与数据库只监听 127.0.0.1；对外只有 Caddy 的 80（仅证书与跳转 HTTPS）和 443。
- 演示环境使用独立数据库 `yonlink_mvp_demo`，只含“演示企业（演示数据）”和 5 个演示账号；与开发库 `yonlink_mvp_dev`、测试库 `yonlink_mvp_test` 隔离。
- 开启演示账号一键登录（`DEMO_LOGIN_ENABLED=1`，仅此环境）。

## 日常运维
```bash
# 发布已提交的代码（导出 → 安装 → 迁移演示库 → 构建 → 切换 → 重启后端）
scripts/deploy.sh

# 状态与日志
systemctl --user status yonlink-crm yonlink-postgres yonlink-caddy
journalctl --user -u yonlink-crm -f

# 重启
systemctl --user restart yonlink-crm

# 修改 Caddyfile 后
cp deploy/Caddyfile ~/yonlink-deploy/shared/Caddyfile && systemctl --user reload yonlink-caddy

# 重新写入演示数据（幂等；组织已存在时只补齐账号）
cd ~/yonlink-deploy/current && set -a && . ../shared/runtime.env && . ../shared/app.env && set +a && npx tsx prisma/seed-demo.ts
```
- 升级 node（nvm）后：更新 `shared/runtime.env` 中的路径，再重启服务。
- 替换 Caddy 二进制后：需重新执行 `sudo setcap cap_net_bind_service=+ep ~/yonlink-deploy/bin/caddy`。

## 负责人已执行的一次性操作

## 已知风险与后续
- **备份**：尚未配置数据库定时备份与离线副本（ADR-008）；演示数据可随时用种子重建，但开发库数据无备份。
- **单机**：数据库与应用同机，无高可用。
- **演示登录**：此环境任何人都可一键登录演示账号（仅演示组织数据），这是有意为之；正式生产环境必须关闭 `DEMO_LOGIN_ENABLED`。
- **数据库角色**：应用以 PostgreSQL 属主账号连接，尚未切换为非属主运行角色（ADR-005）。
- **登录限流**：基于进程内存，服务重启后清零。
